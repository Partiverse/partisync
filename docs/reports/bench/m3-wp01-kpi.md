# M3-WP01 KPI 底稿：分片元数据基准（10⁷ 导入 / LIST p99 / 盘上预算）

- 日期：2026-09-20 · 主机：Apple Silicon（darwin 25.6.0 arm64，本地 NVMe）
- 基准：`crates/partisync-hub/benches/wp01.rs`（宏基准，M2 KPI 同款口径：
  参数驱动 + Instant 计时 + 本报告人工登记；复现命令见各节）
- 数据形态：10⁴ 目录 × 1000 子项（每子项 name ≈ 25B + content_id 32B 的
  常规行）；ID 为 seq 的纯函数（ULID 形状 + splitmix），list/point 可离线重放
- 对照：SPEC M3-WP01 验收「盘上预算基准」「基准报告（T06）」；
  M3 关门 KPI（M3-WP00）终裁归 WP06 规模验证——本报告为**底稿**

## KPI ①：盘上预算 ≤300 B/条目（含 LSM 写放大 ×3 口径）——✅ 达标

命令：`cargo bench -p partisync-hub --bench wp01 -- import N && cargo bench -p partisync-hub --bench wp01 -- budget`

| 规模 | 逻辑 B/条目 | 盘上 B/条目 | 盘上/逻辑 |
|---|---|---|---|
| 10⁶ | 175.9 | **296.9** | 1.69× |
| 10⁷ | 175.9 | **182.3** | 1.04× |

- 逻辑口径 = entry 键+值 + children 键+值（SPEC §1 双平面合计预算带 150–270B，
  实测 175.9B ✓）；盘上含 LSM 未压实段。
- 10⁶ 的 1.69× 是导入刚结束、压实未追平的瞬态；10⁷ 收敛到 1.04×。
  两规模均 ≤300B 硬线，写放大远在 ×3 内。
- 10⁹ 外推：逻辑 175.9B × 10⁹ ≈ 176GB（+ 墓碑/压实余量）——单节点 NVMe
  可承载，WP06 实测复核。

## KPI ②：10⁷ 顺序导入吞吐

命令：`cargo bench -p partisync-hub --bench wp01 -- import 10000000`（release）

两轮对照（分裂搬移算法修复，全程留痕）：

| 轮次 | move_keys 实现 | 总耗时 | 平均吞吐 | 分裂停顿 |
|---|---|---|---|---|
| 基线 | 每批从 `start` 重开迭代器 | 621.4s | 16.1k/s | 两次停顿 ~100s/~195s（4.1M、7.9M 处） |
| **终版** | 游标自批尾续扫（O(M)） | **146.9s** | **68.2k/s** | 三次停顿各 8–15s（搬移批压实 I/O，非扫描） |

- 稳态写入速率（分裂间隙的即时速率）：均值 ~109k/s，峰值 184k/s；
  总均值被分裂停顿与 LSM 压实摊薄至 68k/s。
- **根因与修复**（M0 报告「优化全程留痕」先例）：`move_keys` 每批 4096 行
  均从区间起点重开 range 迭代器，跳过已搬走键的扫描量为 O(M²/B)——
  4M 行分裂搬 2M 行即 ~500 批 × 平均 1M 行重扫。修复为游标
  `Bound::Excluded(上批末键)` 续扫，总扫描 O(M)；崩溃语义不变（批原子、
  恢复重放幂等——已搬走的键不在源中，重放自然跳过），T05 failpoint
  四场景回归通过。
- 10⁹ 外推（WP06 终裁）：稳态 109k/s → 10⁹ ≈ 2.6h 单写者（分裂停顿
  占比随规模下降：停顿数 ∝ √增长，写入量线性）；10 节点 × WP02 复制
  开销后对照关门线 24h 余量充足。

## KPI ③：LIST p99 与点查（10⁷ 本地实测）

命令：`cargo bench -p partisync-hub --bench wp01 -- list 3000` / `point 3000`
（页大小 256——SPEC §4 单目录 p99 由分页保证的口径）

| 规模 | LIST p50 | LIST p95 | LIST p99 | LIST max | 点查 p50 | 点查 p99 |
|---|---|---|---|---|---|---|
| 10⁶ | 1.7ms | 3.8ms | 32.3ms | 190ms | 8μs | 59μs |
| 10⁷ | 5.2ms | 23.5ms | **36.1ms** | 68ms | 185μs | 726μs |

- **10⁷ LIST p99 = 36.1ms < 100ms**（M3 关门线，10⁹ 终裁 WP06）。
  p50→p99 的斜率来自读时修复核验（每页 256 项 × 256 分片哈希点查）+
  冷缓存首访；10⁶→10⁷ 的 p50 退化 1.7→5.2ms 与 LSM 层深增长一致。
- 点查 p99 = 726μs（blake3 路由 + 单 keyspace 直读）；10⁶ 时 59μs 的
  差异主要是块缓存命中率——服务化前置缓存归 WP02+。
- 病态目录形态（单目录 10⁵+ 子项的跨页深遍历）未在本基准覆盖——
  keyset 分页完备性由 T04 属性测试保证，性能形态归 WP06。

## 附属测量：Hub 生命周期（观察项，非 KPI）

命令：`cargo bench -p partisync-hub --bench wp01 -- lifecycle 3`

- open 耗时：10⁶ 库 10.5s / 10⁷ 库 12.8s（p50≈p99，稳定）。
- 主导项 = 256 keyspace 逐个打开 + 首次 manifest/段文件扫描，与数据量
  弱相关——对应 SPEC 风险条目「每分片独立 keyspace ×256 的资源开销 /
  keyspace 收敛（分片键加前缀共享实例）」。**WP02 复制层进场前建议
  专项评估**：收敛后 keyspace 数从 256+分区数 → 个位数，open 预期降一个
  量级；行为契约不变（SPEC 已预留该裁定）。
- 测试套件时长（T05 观察）同源于此：单测试一次 Hub open+drop ≈10s。

# ADR-0033: 许可终局与商业分层——Apache-2.0 转正、hub 治理平面商业扩展区、三阶段商业路线

状态: 已接受 · 日期: 2026-10-10 · 决策人: @lead（AI 代理起草，@lead 2026-10-10 会话内核签确认）
关联: ADR-0000（决策 5 复议）· docs/specs/M7-WP03.md（企业议题登记）· docs/reviews/M8-roadmap-proposal.md §3-4 · docs/reviews/M8-evolution-research-2026-10.md · docs/reviews/M11-roadmap-proposal.md §1.5（D19）· docs/specs/M10-WP06.md（发布节奏，本件挂 M11-WP01-T04 执行）

## 背景

ADR-0000 决策 5 将全仓许可证定为 Apache-2.0 并**显式标记「临时」**：复议条件为「治理结构（基金会/公司/社区）确定」；其后果条款要求「许可证复议前，所有对外发布的产物须附带『临时许可』说明」。三项实况使复议条件实质已满足、继续推迟的成本开始大于收益：

1. **治理结构实质已定**：单人（@lead）+ AI 代理作业模式，无外部贡献者、无基金会/公司实体。等一个不会自己到来的「治理结构确定」只是把决定推给未来；而「临时许可」发布说明义务在 v0.1.0-beta 与 v0.2.0-rc 发布清单（M10-WP06 release-cadence）中始终未落实，构成持续在账的债。
2. **商业价值面已收敛但从未定案**：M7-WP03 将企业特性（SSO/AD-LDAP、审计日志、空间配额、多租户隔离）以「只登记不设计」纪律封存，触发条件 =「企业客户诉求」；M8-roadmap §3-4 纸面判断「企业化竞争全在 Hub 侧治理平面」；M6-WP01 明确当前产物是「非商业 SaaS 的投资人/招聘演示件」。散落的判断没有一份决定性文档收拢。
3. **rc 发布窗口在即**（M11-WP01）：v0.2.0-rc.1 发布产物的许可口径需要一个终局答案，不能带着「临时」标签出 rc。

## 决策

**全仓（12 产品 crate + xtask）许可证转正为 Apache-2.0 终局决策，废止「临时」标记；商业扩展区预先划定为 hub 治理平面（触发后新增代码进独立仓、独立授权，基座永不回收）；商业模式按三阶段推进，引擎本体永不直接收费。**

条款：

1. **许可转正**：ADR-0000 决策 5 的「临时」标记与本件签署之日废止。已发布版本依 Apache-2.0 授权性质永久开源（不可撤回）；未来版本仅对第 2 条「商业扩展区」的**新增**代码保留另择授权的自由（版权全数在 @lead，无贡献者归属障碍）。deny.toml 许可证白名单与「无聊依赖」原则不变。
2. **商业扩展区边界（现在划界，触发后切割）**：hub 治理平面四件套——SSO/AD-LDAP、审计日志、空间配额、多租户隔离（即 M7-WP03 §3 登记清单）——为指定商业落点。触发前维持「只登记不设计」纪律不变；触发后该部分**新代码**在独立私有仓开发、以商业授权发布，本仓基座（含 hub 开源面：openraft 复制、联邦路由、分层与 EC）保持 Apache-2.0。多租户过滤语义 spike（docs/reviews/M8-WP03-tenant-spike.md）作为技术储备留在本仓。
3. **对外贡献策略（第一个外部贡献者出现前生效）**：接受 DCO（`Signed-off-by`）；外部贡献范围限于开源基座，不进入商业扩展区（该区不开放外部贡献，从源头消灭贡献归属争议）。不设 CLA。
4. **三阶段商业路线**（与资金现状匹配）：
   - **阶段一（现在，零产品投入）**：GitHub Sponsors + 公益/生态资助申请（local-first + E2EE + Rust + 自托管信任工程画像与 NLnet 类资助高度吻合）；Ente 式开放信任资产顺带积累。**待办登记：[docs/reviews/commercial-actions-backlog.md](../reviews/commercial-actions-backlog.md)**。
   - **阶段二（hub 可部署后）**：托管 hub 试点订阅 = 自然 SaaS。硬前置 = 以真实数字关闭 ADR-0015 的 iroh relay 定价开放项、算清单位经济后再定价；自托管永远免费（同时是信任营销）。
   - **阶段三（M7-WP03 触发条件发生）**：企业自托管授权（治理平面四件套打包）。
5. **Partiverse 边界**：「合并后即最终产品」（D19）的收费问题归 partiverse 仓文档裁决，不在本仓视野；建议口径 = 消费端应用免费 + hub 托管同步订阅。PartiSync 本体保持纯基础设施、永不直接收费——引擎的采纳面就是 Partiverse 的获客渠道，两层互相供血。
6. **义务终结**：ADR-0000 后果条款「对外发布产物附带『临时许可』说明」自本件接受之日起废止，发布清单不增设该条目。

## 备选方案

- **AGPL-3.0 + 商业双许可**：否决——双许可需要 CLA 与基金会式治理，单人 + AI 作业模式无社区杠杆亦无谈判筹码；AGPL 显著收窄引擎被嵌入（含闭源产品）的采纳面，与引擎优先定位相逆。
- **FSL/BSL 全仓延迟开源**：否决——声誉成本高，beta 期不存在被云厂商「白嫖」的实际威胁；M8-evolution 已归档 Spacedrive 的真教训是资金断档而非许可证选错。
- **GPL/AGPL 全仓**：维持 ADR-0000 第 24 行否决结论（与「开源核心 + 商业扩展」路径冲突），本件不翻案。
- **维持「临时」标签继续推迟**：否决——复议条件实质已满足，推迟只持续产生未清偿的发布说明义务，且让 rc/GA 的对外口径悬空。
- **现在启动托管 SaaS**：否决——单人项目背 SaaS on-call 负担 + relay 成本未知（ADR-0015 开放项未关），阶段二硬前置未清。

## 后果

正面：

- ADR-0000 「临时许可」发布说明义务终结，M11-WP01 rc 窗口对外许可口径收口。
- 引擎采纳面最大化（rclone 判例：permissive 引擎靠嵌入取胜），为 Partiverse 与阶段二/三商业面供血。
- 商业扩展区边界先行划出并配 DCO 限界，规避事后切割贡献归属的经典翻车点。

负面（明示放弃的东西）：

- 接受任何人今日即可 fork 全部已发布代码：护城河改由迭代速度、信任工件（minisig 签名 + SBOM + 可复现构建，ADR-0027/0030）与 Partiverse 先发集成承担。
- 「未来整仓改 FSL/AGPL」选项被本件显式关闭（已发布版本不可撤回，社区对转正许可形成依赖预期）；仅商业扩展区新增代码保留另择授权自由。
- 商业扩展区与基座同仓开发的便利被放弃：触发后需开独立仓，存在一段双仓同步成本。

门禁影响：本件为治理文档，零代码 diff；deny.toml 白名单、workspace 依赖、rust-toolchain 均不动，无新增 audit/deny 告警面。

## 重新评估条件

- 第一个外部贡献者出现且 DCO + 基座限界约定被拒 → 贡献策略复议；
- hub 托管试点启动时 relay 单位经济测算为负 → 阶段二推迟或定价模型复议；
- 出现对基座的实际云化白嫖且造成可量化损害 → 商业扩展区边界扩大复议（新 ADR 取代本件，已发布版本仍不可撤回）；
- @lead 决定设立公司/基金会 → 治理与商标归属复议。

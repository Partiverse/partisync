## 1. 诚实披露（铁律 9「会话即弃」+ 铁律 6「双通道审查」原则）

按 SPEC §裁定 1 原计划：「双人盲标 + 仲裁记录」，relevance 4 档（0/1/2/3）。
**实际执行偏离原计划**，必须诚实披露：

### 1.1 标注者

- **单人标注**（本会话内的 AI 起草）
- 无独立第二标注者
- 无独立仲裁者（执行方案 §1.2 RACI 中 A=人终审，但本会话仅完成 AI 起草阶段）

### 1.2 规模偏离

| 项 | SPEC 计划 | 实际交付 | 偏差 |
|---|---|---|---|
| 语料规模 | N=200 | N=50 | -75% |
| 查询数量 | 40 | 25 | -37.5% |
| Ground truth 数量 | 估算 100+ | 32 | 显著减少 |

### 1.3 偏差原因

- **200/40 是 SPEC 起草时的理想值**；实际执行发现 50 个**手工精挑**的语料 + 25 个
  **手工设计的查询**比 200/150 个合成语料更能在 CI 中复现、更能区分 BM25 vs hybrid
- 真实 INBOX 库的 mime 全 null、OCR 全空（仅 1 张真实图片），按原计划「跨 mime_kind
  分层采样」不可行；改用手工合成 + 真实结构化 frontmatter 的方案
- 双人盲标需要两轮独立标注 + 仲裁流程（本会话单 AI agent 无法完成）

## 2. 标注口径（relevance 4 档）

| 档 | 含义 | 操作定义 |
|---|---|---|
| 3 | 高度相关 | 该文档直接回答 query 的核心意图 |
| 2 | 相关 | 主题相同 + 部分回答 |
| 1 | 弱相关 | 主题领域相近但不直接回答 |
| 0 | 不相关 | 主题领域不同 |

**绝不**将 BM25/hybrid 检索结果反向当 ground truth——这是「自评自」反模式。

虽然单人标注，但以下措施提高诚实度：

  但同领域加密货币是远期集成（与 PartiSync 无直接关系）；档=1 而非 0 = 诚实承认主题相关但非直接回答

1. 初稿
2. 隔离 1 小时后复读 + 修正

| 文本字段 | filename / 部分 tag | filename / tags / body 全文 |

**WP06 评估是合成库的离线基线**，不是 INBOX 真实场景的代理。
真实场景的召回质量需要：
- 真实 OCR 文本入索引（依赖 Sidecar 管线 + 模型）
- 真实向量入索引（依赖 BGE-M3 模型下载）
- 真实查询来自 Agent 用户

→ 留 M5+ 作为「生产档」评测。

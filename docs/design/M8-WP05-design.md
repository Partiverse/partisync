## 1. 定位与原则

PartiSync 桌面壳是**本地优先引擎的档案工具**：用户的核心对象是「有
内容身份的文件」。设计语言 = **指纹即视觉**——

1. **内容身份是一等公民**：blake3 摘要前 8 位以等宽徽章呈现，且条目
   的指纹色相由摘要派生（HSL，同内容在任何视图颜色相同）——颜色是
   产品语义，不是装饰；
2. **档案工具气质**：纸灰底、克制的铜绿主色、宋体标题——安静、可信、
   长时间使用不疲劳；
3. **动效唯一**：仅检索结果指纹条生长一处入场动画（回答「结果来了」），
   其余交互即时反馈；`prefers-reduced-motion` 全局尊重；
4. **文案即指路**：错误说明怎么修、空态给出动作邀请、同一动作全流程
   同名（「检索」按钮 → 「个命中」计数）。

## 2. Tokens

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#F4F5F3` | 页面基底（冷灰纸，非暖奶油） |
| `--ink` | `#171B19` | 主文字 |
| `--ink-2` / `--ink-3` | `#4A524E` / `#7C847F` | 次级/辅助文字 |
| `--line` | `#D8DCD7` | 分割线 |
| `--green` | `#33604F` | 主色（当前态/主按钮/得分条） |
| `--green-soft` | `#E4EDE8` | 选中底/highlight |
| `--amber` | `#9A6B15` | 唯一警示色（冲突/错误级） |
| 指纹色 | `hsl(H, 38%, 40%)` | H = 摘要首字节 × 137.508° mod 360（黄金角散布） |
| 标题字体 | `Songti SC, serif` | wordmark/详情标题/大数字 |
| 正文字体 | `PingFang SC, sans` | 全部正文与控件 |
| 等宽字体 | `SF Mono, monospace` | **仅**真实摘要/时间戳数据 |

字号阶梯：44（同步大数字）/ 21（wordmark）/ 17（检索输入/详情标题）/
14.5（条目名）/ 14 正文 / 13.5 表格 / 12.5 辅助 / 11（指纹徽章）。

## 3. 三大界面结构

### 检索（旗舰）
```
┌────────────────────────────────────┐
│  [ 搜文件名、内容、转写文本……  ][检索] │  ← hero 框（全宽 720px，墨色描边）
│  ○关键词 ●语义 ○含转写文本          │  ← 分段单选（非卡片）
│  14 个命中 · 语义模式 · 耗时 41 ms   │
│  ▌[9f3a2c1d] 名称                  │  ← 每行：指纹条+徽章+摘要高亮
│  ▌路径  片段……        ▂▂▂ 0.92     │     + score 细条（数据可视化）
└────────────────────────────────────┘
```

## 4. 实现对照（T1–T4 落地要求）

- styles.css 重写为 tokens 变量体系（现状样式整体替换）；
- 指纹色派生函数进 app-core.js（`fingerprintHue(hex8)`），三处视图
  共用；真实摘要数据处才用等宽；
- 新 tab/面板 DOM 结构对照本文档 wireframe；交互即时反馈不加过渡动画；
- 空态文案：「本机还没有索引文件——运行 `partisync index <路径>` 开始」
  （给动作，不给情绪）。

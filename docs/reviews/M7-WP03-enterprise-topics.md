## 1. 承接背景

SPEC M7-WP01 §4 非目标把「扩展分发/签名/registry」列为推迟项，理由
「供应链面，需独立威胁模型」。WP01 已交付**扩展运行时**（ext-host +
注权 manifest + MCP 工具面接线），运行时的存在使**扩展从何处来**成为
下一个真实攻击面——本 T03 登记该威胁模型草案与企业特性候选清单，
供 M8+ 立项决策。

## 2. 扩展分发/签名/registry 威胁模型草案

### 2.1 当前状态（基线事实）

- 扩展发现约定：`~/.partisync/extensions/<name>.wasm` + `<name>.json`
  （M7-WP01 §2.2，gateway 启动期一次扫描）；
- 装载期校验：manifest 三阶段（IO→parse→validate）+ capability 白名单 +
  撞名拒绝 + fail-closed（M7-WP01 T02/T04）；
- **无签名校验、无来源认证、无 registry、无更新通道**——扩展是本地
  「用户自己放文件」的信任假设。

### 2.2 资产 / 攻击者 / 攻击面

| 资产 | 说明 |
|---|---|
| 宿主完整性 | ext-host 进程、MCP 工具面、gateway |
| 资产图谱数据 | 经 `index.read` capability 暴露的检索结果 |
| 设备身份密钥面 | 扩展沙箱**无**此 capability（P13 默认拒权）——设计上不可达 |
| 用户信任 | 扩展来源不可辨 → 恶意扩展伪装成官方 |

| 攻击者 | 能力 |
|---|---|
| A1 本地低权用户 | 往 `~/.partisync/extensions/` 放文件（**当前唯一信任根：文件系统写权限**） |
| A2 供应链攻击 | 篡改「用户手动下载的扩展」（无签名 → 无法验伪） |
| A3 网络 MITM | 经 SMB/FUSE 桥接分发扩展时（若实施 WP 落地） |

### 2.3 威胁与缓解草案

| # | 威胁 | 现状缓解 | 缺口 | 缓解方向（不设计） |
|---|---|---|---|---|
| T-S1 | 恶意扩展投放（A1） | capability 白名单最小集 + fail-closed + 撞名拒绝 | 无来源辨识——用户无法区分官方/第三方 | 签名（Ed25519，锚定分发者公钥）+ 装载期强制验签 |
| T-S2 | 供应链篡改（A2） | 无 | 下载源不可验证 | 分发者签名 + 可选 registry 元数据（版本/信誉） |
| T-S3 | 桥接路径注入（A3） | 无 | FUSE/SMB 桥接实施后新增分发面 | 桥接只读面（已定）+ 分发走签名而非裸文件 |
| T-S4 | 扩展越权调用宿主能力 | ✅ **P13/P14 已覆盖**：capability 白名单 + 缺 manifest 拒载 + 注权 fail-closed + 30 测试 | 无 | 已闭合（引用 WP01 结论，不重复） |
| T-S5 | 扩展崩溃/挂死拖垮宿主 | 部分：gateway `spawn_blocking` + 10s timeout（R8 处置 b+c） | 无限循环 guest 仍持锁（epoch/fuel 正解未做） | epoch interruption（WP01 SPEC R8 登记的后续项） |

**结论**：运行时侧安全（T-S4）已闭合；**来源侧安全（T-S1/T-S2/T-S3）
完全空白**，且随扩展生态规模化风险递增。

## 0. 口径与诚实边界

- **文件/负载**: 64 MiB /dev/urandom 伪随机；读电池 = 冷读 4 MiB ×5
  （每次读前 drop——0.2s 静置）/ 热读 4 MiB ×5 / 顺序全读 64 MiB /
  随机 4 KiB n=200（open→seek→read→close 全链路，offset 均匀分布）。
  **M8 原脚本临时不入仓未留档，区段选取/seek 分布/每读一 drop 为本轮
  重构假设**（M8 报告 §1 仅指标表；差异如实标注，量级结论不受影响）。
- **两轮口径**: ①**tmpfs 后备**（对齐 M8「无真实磁盘 IO」口径，可比）；
  ②**容器 overlayfs 后备**（宿主 NVMe，drop 后真读盘——M8 无此变体，
  为本轮新增的含设备参考值）。两轮同命令序列。
- **by-hash 侧**: `--cas` 挂载 + 手工构造 CAS（objects/<h2>/<digest>
  裸文件，`ChunkStore::get` 只读对象路径不查库）；digest = blake3
  （宿主同源实现计算）。

## 1. 结果

### 1.1 tmpfs 后备（= M8 口径，可比轮）

| 指标 | 本轮（Linux/Kubuntu） | M8 基线（Apple Silicon 容器） | 判读 |
|---|---|---|---|
| 冷读 4 MiB ×5 | **2.14–6.26 ms**（中位 3.20） | 3.2–3.3 ms | 同量级 ✓ |
| 热读 4 MiB ×5 | 1.26–2.03 ms | 2.5–3.7 ms | 同量级略优 ✓ |
| 顺序全读 64 MiB | **2932 MiB/s**（21.8 ms） | 1567 MiB/s（40.8 ms） | 1.87×（平台差，非回归）✓ |
| 随机 4 KiB p50/p95 | **17 µs / 23 µs** | 328 µs / 361 µs | 优 ✓（16C 裸机 vs 容器） |

**透传读路径结论：无算法性劣化**——冷/热/顺序/随机四指标对 M8 全部
同量级或更优（跨机口径注意沿交接文档 §3：数字不直接横比，量级判读
成立）。

### 1.2 容器 overlayfs 后备（NVMe 参考值，0.3 新增变体）

透传：冷读 10.99–14.26 ms / 热读 6.73–12.56 ms / 顺序 396 MiB/s /
随机 p50 389 µs p95 1009 µs——drop 后真读盘的含设备参考（M8 无此口径，
仅存档）。

### 1.3 by-hash（CAS 直连，两轮一致）

| 指标 | tmpfs 轮 | overlayfs 轮 |
|---|---|---|
| 冷读 4 MiB | 63.8–86.7 ms | 137.7–175.5 ms |
| 热读 4 MiB | ~32 ms | 68.5–73.0 ms |
| 顺序 64 MiB | 770 MiB/s | 292 MiB/s |
| 随机 4 KiB p50 | 31.8 ms | 61.8 ms |

**B1 断言 `cas ≤ max(3×dir, 50ms)` 按字面 FAIL**（cold/rand/seq 三项
超限，tmpfs 与 overlayfs 两轮一致）。**根因 = by-hash 打开语义**：
`cas_reads` 于 open 时**整载全对象**（fs.rs「open 时取一次，read 直
读」——M8-WP07-T04 设计），每次 open 支付 O(全文件) 成本（64 MiB 热
载 ~32 ms），与后续读出多少无关。**这是设计语义的必然结果，非本轮
读路径回归**（透传侧四指标全绿佐证引擎读路径无恙）。

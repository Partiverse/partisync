## 7. 与 M10 的差异说明

1. **节骨架与状态**：沿 M10 八节版式收敛为七节 + 结论，并**新设本节**
   （M10 判例无独立差异节）；状态从 M10 入仓即「已拍板（§7-0 记录）」
   降为**「提案待拍板」**——本提案合入仅 = 文档落档，非方向批准；
2. **主题结构**：M10 = 用户拍板的单一主线（GUI 功能加速，原推荐三主
   线 α2+β2+γ2 重排后置）；M11 推荐**回归「尾款收官 + 双线并行」结构**
   ——桌面尾款与发布执行无交叠并行，主线叙事从「补课」转「收敛」；
3. **尾款承接口径**：M10-WP00 承接 M9 尾款三笔（人工件/回填/发布执行）；
   M11-WP00 承接 M10 尾款两笔（WP02 收官 + WP01 关账回填），且**首次
   出现「上游拍板默认生效但无落点」的显式裁决项**（§1.4 G10）；
4. **D5 处置升级**：M10-WP03 §6-D5「登记不处置、另立任务候选」→
   M11-WP02 入线（R1）——定性从「候选」升「主线硬伤件」；
5. **记忆编辑/删除 UI**：条件触发（M10-WP00 §3-T03 承接位）→ 主线承
   接位兑现（M11-WP03）；
6. **发布工程**：M10 只出拍板文档与清单（执行全部留窗口）→ M11 执行
   窗口（用户确认前置红线不变，非目标边界同 M10-WP06 §4）；
7. **候选池缩编**：M10 曾设「联邦扩军/压测」条件位 WP（WP06，未占线）
   → M11 不再设条件位编号，一律入 §6 条件行（候选 5 亦不占固定编号）；
8. **向量检索**：M10 出评估件并拍板「条件不成熟暂不实施」→ M11 维持
   实施位条件触发，但新增「T3 先决清偿可主动化」动作位（随 M11-WP05
   评估窗口）——清偿即满足评估触发（评估仍可结论不实施），实施位仍
   须 T1–T3 齐备 + T4 对齐（§6 全定义）；并经候选 3 的查询实证与 T2
   联动；
9. **0.3 partiverse D19 定位对齐（本修订主旨）**：输入源新增 partiverse
   仓 §9 裁决（D19/D27/S1–S5）——①主线从「GUI 功能面二期收官」更替
   为「partisd 守护进程实体化 + 底座并发语义」（桌面冻结令直接后果，
   S1 首推承接「替换 M10 GUI 容量」）；②M11-WP03（记忆编辑/删除 UI）
   撤出，M10-WP00 §3-T03 承接承诺修订为拍板项（§4-4b）；③D5 定性从
   「桌面硬伤件」重构为「底座单写多读并发语义债」；④桌面壳处置三步

   锚登记（§6）；⑥rc 桌面二进制随发口径新增小拍板（§4-2b）。**边界

## 8. 结论

M10 交付后，能力版图五件成立（本地写同步 / 可验证记忆含生命周期 /
远程 MCP mock AS 边界 / 扩展验签 / beta 发布）；0.3 时点桌面尾款亦已
清账（WP02 双 PR 合入 + GUI 三帧归档，`gh pr list` = 0）。partiverse
D19 定位裁决入纲后，残缺口重述为：**底座常驻形态缺位（partisd 骨架
未实体化 + D5 并发语义）+ 发布一窗（rc 待确认执行）+ 拍板三账（G10
未兑现 / 桌面冻结令确认 / 承接承诺修订）**。M11 0.3 推荐组合即沿这三
条收敛：候选 1（partisd+D5）立底座常驻形态、候选 2 兑现发布、候选 3
还拍板账，候选 4/6 随行、候选 5 条件位；桌面壳按 D19 三步走（冻结→
参考实现→V2 后废弃），partisync 以「CLI + 库 + MCP」永久形态为
Partiverse 供弹。本提案若获批，M11-WP00 沿 M10-WP00 判例正式化 WP 图
并逐 WP 走 SPEC 批准流程；本提案合入仅 = 文档落档，方向批准以用户
拍板为准。

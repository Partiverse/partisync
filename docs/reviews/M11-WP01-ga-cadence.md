## 2. rc 反馈窗口轴（三个空白落锤）

发布报告 §5-2 明示「窗口时长、issue 门槛均未在任何文档定义」——本节
给推荐值，用户拍板或修订：

| 项 | 推荐 | 理由 / 依据 |
|---|---|---|
| 窗口时长 | **rc.1 发布日起 ≥ 14 自然日** | 与 stored 原文域实施排期（SPEC 批准 → 实施 → 复跑）自然并行，不另增等待；短于 14 天公开 Release 的外部反馈量预期不足以支撑「验收」语义 |
| 门槛（叠加条件，非二选一） | ① **零未处置 P1**（崩溃/数据损坏/验签失败级）；② **已登记 issue 全部有处置结论**（修复 / 降格登记 / 条件触发，三选一留痕）；③ 窗口内 **≥ 1 次内部全链验收**（CLI/partisd/MCP 面对单，沿桌面端验收规则 2026-10-09 修订：验证走 CLI/守护进程/MCP） | ①② 保证「反馈闭环」可审计不假绿；③ 承接 M11 冻结令后的验证面（GUI 不再实操） |
| rc.2 迭代规则 | 窗口内出现需改代码的反馈 → 修复 PR 合入后 **删 tag 重打 rc.2**（B4 alpha 9 跑 + rc.1 BSD strip 判例延续）；纯 docs/登记类反馈不重打 | rc.1 窗口已两次演练删 tag 重打（#220）；避免 rc.N 碎片化 |
| 反馈渠道 | GitHub Issues（标签 `rc-feedback`）+ Release 反馈区 | 首个公开 Release，渠道与公开仓库对齐即可，不自建 |

## 3. GA 发布序列轴

### 3.1 推荐案

| 项 | 推荐 | 理由 / 依据 |
|---|---|---|
| tag | `v0.2.0`（去 `-rc.N` 段；tag 前 B1–B8 复跑全绿） | M10-WP06-T02 §1.1 原案「rc.1 → rc.2 → … → GA `v0.2.0`」；semver 正式版语义 |
| Cargo workspace version | **维持 0.2.0 不动（零 Cargo 面 diff）** | rc 口径已整数 bump（M10-WP06-T02 §1.1：rc 迭代零 Cargo diff，GA 同样零 diff）；GA 前若 API 有 breaking（预期无——桌面冻结令 + rc 锁面），则另拍版本轴 |
| 产物名 | release.yml 模板去 `-rc.N` 段（`…-0.2.0-linux-x86_64.tar.gz` 等） | M10-WP06-T02 §1.2 附加面 #2 原案「GA 时去 pre-release 段」 |
| CHANGELOG | 新增 `[0.2.0]` 节（rc.1 → GA 的增量如实登记；rc 已知限制清单逐项复核：清偿/延续标注） | 沿「AI 起草人终审」判例（M8-WP02 §2.4） |
| 发布报告 | GA 版落 docs/reviews/M11-WP01-release-report-ga.md（run id、产物 sha256、与 rc.1 的偏差） | 沿 rc.1 报告判例 |
| 已知限制随附 | NB-WP05-1（真实外接 AS 端到端未验）等窗口期末状态如实复核随附，不假绿 | M10-WP06-T02 §3.1 已知限制清单判例延续 |

### 3.2 GA 序列（J1–J4 满足 + 本档三轴确认后执行）

1. M11-WP04 SPEC 批准（G0）→ 实施（T03+）→ 三门禁绿 + 检索验收；
2. 候选 4 T1 观察项进度登记（M11-WP05-T04 证据件，如实标注语料来源
   与强度，沿 T2 自建语料降格登记判例）；
3. release.yml 产物名去 rc 段 + CHANGELOG `[0.2.0]` 节（PR）；
4. B1–B8 复跑全绿（B1 按 v2 口径）→ 用户终审 → tag `v0.2.0` →
   draft Release → 用户终审 publish → GA 发布报告落档。

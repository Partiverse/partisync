## 1. 动机

G8「MCP 仅本地 stdio」在 M9-WP05 完成半清偿：评估文档（差距面 + 威胁
模型 T-R1..T-R7）+ hub 端 mock 骨架（`crates/partisync-hub/src/mcp_remote.rs`

交付。剩余面 = M10-roadmap-proposal §6 **NB3**：真实 OAuth 2.1 授权
（评估文档 A-3 全量缺席——受众绑定/scope 校验/token passthrough 禁止）、
TLS 终结、工具透传（远程调 asset_*/memory_* 真实执行）。工具语义层已与
传输解耦（`ServerHandler for McpServerState`，mcp.rs:548，11 工具
mcp.rs:609-619），评估文档最重要的正面发现（§5-2）是 2026-07-28 的
stateless 化使无状态 handler 直调模型可原样平移——正式化的技术地基已验
证，本 WP 落锤实施。

不做本 WP：远程客户端永远无法以标准 OAuth 2.1 流程接入任何真实工具面，
MCP 远程化停在「评估完备、骨架 mock」的半成品态；MCP 2.0 定稿（2026-07-28）
起 6–12 个月对齐窗口持续关闭（M10-roadmap-proposal §3-2），窗口后评估成
本与竞品差距同步升高；β2 主线「复用 M9-WP05 全部评估资产（边际成本最低
的新主线）」（roadmap §5）悬空。范围口径（用户指令）：**评估与 ADR 落锤
照做，可本地测试的部分（mock AS/集成测试）实施，真外部依赖如实登记债务，
不伪造端到端**。

## 2. 契约

### 2.0 宿主与机制总则（裁定 + 不锁死声明）

- **宿主裁定 = gateway 侧**：真实面落 `partisync-gateway` 新模块——
  McpServerState/11 工具/`run_mcp_server`（mcp.rs:1704）所在；hub 无
  graph 数据面，工具透传需新建 hub→gateway 通道 = 范围级蔓延，否决。
  依据：评估文档 §2.3 handler 与传输解耦可平移 + gateway Windows target
  已有 rmcp `server-side-http` feature 先例（Cargo.toml:49）。hub
  mcp_remote 骨架**原样保留**（M9 交付物 + mock 边界探针是防误用契约），
  与真实面并存（不同 bin、不同端口，无路径冲突），双面关系在评估件登记。
  若 T02 评估以证据反向推翻本裁定 → SPEC v0.2 修订（沿 M9-WP03 v0.2
  实施期发现转正判例）。
- **机制不锁死**：传输件（rmcp `transport-streamable-http-server` 的
  StreamableHttpService vs 既有 axum 骨架扩展）、token 校验件（rmcp
  auth 线位 vs 独立 JWT 验签 crate）由 ADR-0031 落锤；SPEC 契约按**行
  为**验收（探针钉行为，不钉实现）。起草期已实证的输入（rmcp 3.4.0
  registry 源码，2026-10-07）：`auth` 模块为**客户端侧** OAuth
  （auth.rs:511 AuthClient/PKCE/CredentialStore）——RS 侧 token 校验
  零 SDK 现成件，是 ADR 必答题；`transport-streamable-http-server`
  提供 StreamableHttpService + Origin/host 校验与 stateless 协议头开
  关（tower.rs:206-271），G-3/G-4 有 SDK 面可依（逐项覆盖度仍须 O1
  实施期复核）。
- **新依赖全部走 ADR-0031**（铁律 8）：workspace 现无 rustls 线位/
  jsonwebtoken/oauth2 顶层 pin（Cargo.toml:28-85 实证）；Cargo.lock 现
  无 oauth2/jsonwebtoken——feature 启用即新增传递依赖，deny 核对随实施
  PR 门禁实证。

### 2.2 传输面（T03）

- **端点形状沿 M9 骨架口径**：单一 MCP endpoint `POST /mcp` + PRM
  `GET /.well-known/oauth-protected-resource`（RFC 9728 形状四字段：
  resource / authorization_servers ≥1 / scopes_supported /
  bearer_methods_supported——值从 mock 换 ADR-0031 配置）；
- **Origin/host 校验**（G-4，T-R3 防线）：存在且非白名单 → 拒绝，先于
  授权面；
- **协议头校验**（G-3）：`MCP-Protocol-Version`/`Mcp-Method`/`Mcp-Name`
  头-体一致性——覆盖件按 O1 复核结论定形（rmcp 自带或手写补层）；
- **TLS 终结**（ADR-0031 机制）+ **非回环绑定必须 TLS 的启动守卫**：
  非 127.0.0.1 bind 且未配置 TLS → 拒绝启动（显式错误，不静默降级明文）；
- **远程入口**：新 bin（名随实施，建议 `partisync-mcp-http`），gateway
  stdio 面/桌面 sidecar 契约零改动；默认 bind 127.0.0.1；
- **fail-closed 默认态（墙先于门）**：T03 合入时除 PRM（公开发现面，
  spec 语义）外一切请求 401 挑战——传输面先行但无任何数据通路，授权
  （T04）不开门则工具面不可达。

### 2.3 授权面（T04，真实 OAuth 2.1 RS）

- **token 校验 fail-closed**：签名验签失败 / issuer 不匹配 / **aud ≠
  本 resource**（RFC 8707 受众绑定，T-R1 防线）/ exp 过期 → **401** +
  `WWW-Authenticate: Bearer resource_metadata="<PRM 路径>"`（评估文档
  A-2 挑战形状）；scope 不足 → **403** + `error="insufficient_scope"`
  （A-3）；**MUST NOT** 接受/转投签发给其他 resource 的 token——token
  passthrough 显式禁止（spec security_best_practices，评估文档 T-R1）；
- **PRM 真实化**：resource/authorization_servers/scopes_supported 为配
  置入参，scopes_supported 缺省 = ADR-0031 落锤的 scope 模型（O3）；
- 校验件机制随 ADR-0031；hub 骨架「mock Bearer 存在即放行」边界在
  gateway 真实面**不成立**（hub 面契约不受影响，M9-WP05 §7-R2 预告的
  「接真实 OAuth 时该探针必红」限定在 hub 面自身，hub 不动即不触发）；
- **新不变量 P23（远程 MCP 授权 fail-closed）**，登记随 T04 走
  partisync-property-registry，**登记先于测试代码**（M9-WP02-T02 /
  M10-WP04-T04 判例）：
  (a) 无/非法/受众错配/过期 token 必 401 且 WWW-Authenticate 指向 PRM；
  (b) scope 不足必 403 + insufficient_scope；
  (c) 无绕过通道——校验矩阵注入（含他 resource 签发 token）钉死「未
  过校验不达任何工具执行」。

### 2.4 工具透传（T05）

- **tools/list 一致性**：远程面与 stdio 面同 11 工具（schema 逐字段一
  致，M10-WP04-T02 探针判例延伸）；
- **tools/call 真实执行**：McpServerState 直调（评估文档 §2.3 平移判
  据），错误口径与 stdio 面一致；scope→工具映射按 ADR-0031（O3 拍板）
  执行；
- **跨请求状态绑定已验证身份**（T-R5）：任何 handle/键控以
  `<subject>:<handle>` 组织，MUST NOT 以 handle 持有替代鉴权；
- **mock AS 本地集成测试**（dev-only，不入产品依赖图）：本仓内线程内
  AS（axum 既有依赖）+ ADR-0031 校验件 dev 依赖签发标准 JWT——全链
  e2e：PRM 发现 → 无 token 401 挑战 → 取 token → initialize →
  tools/list → tools/call 真实执行（含 memory_write 幂等语义抽查）；
- gateway stdio 面/桌面 sidecar 零改动。

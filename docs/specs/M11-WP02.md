## 1. 动机

D5（M10-WP03 §6 登记，2026-10-09 已复现实证归档）：`partisync-mcp`
sidecar 启动即建 tantivy `IndexWriter`（mcp.rs:1721 → engine.rs:66 →
bm25.rs:282 无条件开写者），而 partisync-index **不存在只读打开路径**
（全仓唯一打开入口 `open_or_create`）——导致任何第二消费者（桌面壳
search/index_stats、CLI search，语义上纯只读）撞 `.tantivy-writer.lock`
得 `LockBusy` fatal。复现实证（M11-WP02-d5-repro-evidence.txt）：sidecar
(pid 183669) 以 `10wW` 独占持锁，CLI search 同库查询被拒（错误全文归
档）。更广地：CLI reindex/watch 与任何常驻进程并存即「写者 vs 写者」
必冲突。不做本 WP：底座无常驻形态（partisd 恒为 8 行骨架），S1（
partiverse 需求清单首推「替换 partisync M10 GUI 容量」）无法承接，
Partiverse V2/V3 的 crate/进程集成缺接缝，D5 类互斥随每个新消费者复发。

tantivy 0.26.2 并发语义（对本仓 pinned 版本源码查证，registry
tantivy-0.26.2/src/，行号见 ADR-0032 §决策2）：`IndexWriter` 经
非阻塞 `.tantivy-writer.lock` 全局独占（index.rs:539-563，测试
`test_lockfile_stops_duplicates` 钉死）；`IndexReader` 跨进程并发读安
全（directory_lock.rs:52-59 META_LOCK 防段 GC：「It makes it possible
for another process to safely consume our index in-writing」）；
`Index::open_in_dir` 本身不取写锁（index.rs:498-504）。**单写多读是
tantivy 原生能力，本仓缺的只是只读打开路径与写者归属纪律。**

## 2. 契约

### 2.0 总则与裁定

- **并发模型裁定（D5 三选对证落锤）**：多读者只读打开 + 按需写者。
  读消费者（sidecar/desktop/CLI search）一律走新增只读路径，不触碰
  写锁；写者归真写面（CLI reindex/watch 及后续 daemon 作业面）按需
  短暂持有，互斥由 tantivy 原生锁保证。**否决**「共享 writer 单点」
  （tantivy writer 单进程，跨进程共享即 IPC 作业代理 = 超本 WP 面）
  与「纯懒开」（不解除只读消费者互斥根因）。
- partisd = 底座常驻进程（S1 形态），组装 graph/cas/index 并暴露
  服务面；形态与传输选型见 ADR-0032（决策 1/2）。本 WP 不锁死远程
  演进（远程/认证沿 M10-WP05 既有机制另线）。
- 验收方式与评审深度：R1（gateway/index 横切面 + 新公共 API），全审；
  公共 API 新增面（§2.1/§2.3）随 PR 登记清单。

### 2.1 partisync-index 只读打开路径（新公共 API）

- `IndexEngine::open_read_only(db 语境同 open_or_create)` 与
  `Bm25Index::open_read_only`：打开既存索引仅装配 `IndexReader`
  （ReloadPolicy::OnCommitWithDelay 同现状），**不得创建/获取
  `.tantivy-writer.lock`**；写方法（upsert/upsert_batch/commit/clear）
  在只读实例上不可用（违反即探针红）。
- 语义保证（新不变量 **P24**，登记随 T02 走 partisync-property-registry，
  登记先于测试代码）：(a) 只读打开前后 index 目录无写锁文件创建；
  (b) 只读实例与活跃 `IndexWriter` 并存时 search/approx_count 正常且
  经 reload 观察到提交；(c) N 个只读实例并发无互斥。
- 索引目录不存在时：`open_read_only` 返回结构化错误（区别于
  open_or_create 的建目录语义）。
- VectorStore 无跨进程锁（vector.rs:107-111），engine 级只读打开对
  其为同构包装，不单独设契约。

### 2.2 消费者迁移与锁冲突错误结构化

- sidecar（`build_server_state`）：eager 改**懒 + 只读**（asset_search
  纯读；首次调用触发；打开失败降级行为维持现状口径）。
- 桌面壳（state.rs OnceCell）与 CLI `search`：改只读打开。
- CLI `reindex`/`watch`：维持写者（真写面）。
- 锁冲突错误结构化：写者获取失败时错误信息含指引（「另一写者持有
  索引锁：<pid/file>；只读查询不受影响；批量重建请停写面或等待」），
  不改变错误分类语义；D3（search 打开失败落 `Internal` vs 文档声明
  `Index`）随本面清偿。

### 2.3 partisd 守护进程（MVP）

- 组装：`--db <path> --cas <dir> --index-root <dir>` 打开
  graph/CAS/索引（索引**只读**，2.1），复用 gateway `build_server_state`
  组装（partisd 依赖 partisync-gateway，壳→能力层合法方向）。
- 服务面：rmcp StreamableHttp 绑定 `127.0.0.1:<port>`（默认端口
  SPEC 定 127.0.0.1:7650），暴露与 partisync-mcp 同一套 MCP 工具面；
  **零新依赖**。红线：默认绑定不得为非环回地址；远程/认证沿
  M10-WP05 机制另线（非目标）。
- 生命周期：前台运行；`--pid-file <path>`（写 pid + 独占锁防双实
  例）；SIGTERM/SIGINT 优雅退出（服务面停机 → 资源落盘 → 退出码 0）。
- 骨架兼容：crates/partisd 现有占位 main 被替换（8 行 println 移除）。

### 2.4 并发 e2e 探针（验收载体）

partisd（常驻只读索引）+ CLI search（只读）+ partisync-mcp（懒只读）
三方并存无 LockBusy；CLI reindex（写者）运行期间三方只读查询持续可用
且 reindex commit 后可见（OnCommitWithDelay）；双 reindex 并发 = 后到
者结构化锁错误。探针位置：crates/partisd/tests/（进程级 e2e，沿
M8-WP01-T02 容器/真挂载判例可本机直跑——Linux 台架 /dev/fuse 无涉，
纯进程）。

### 2.5 验收方式与评审深度

代码探针（tests/）+ 本地三件套 + CI 全绿；R1 全审（§2.0）；新增
pub 面（§2.1/§2.3）在 §5 清单注解登记。

版本: 0.1 · 状态: **草稿（合入 = 批准**，沿 M8/M9-WP00 判例）· 关联:
ADR-0024（桌面壳） · 上游: M10-WP00 §1-WP01 行 / M10-roadmap-proposal
§7-0（用户拍板 + 「GUI 搜索形同虚设」缺陷指认，2026-10-05）
负责人: @partiverse · 批准人: @lead · 批准日期: 待合入

## 1. 动机

用户拍板 M10 主线为「前端 GUI 功能加速」，并点名缺陷「GUI 搜索形同
虚设」——检索命中只透出 content_id 哈希切片（M10-WP00 §1）。首件
修复（真实文件名透出）已由 PR #156 落地：`SearchHit.filename` +
bm25/hybrid 双路径 `enrich_hits` graph 反查 + 命中卡优先文件名
（e2e `t01_search_hit_carries_graph_filename` + 探针
`hit_card_prefers_graph_filename` 全绿，main=19162bb）。但「形同虚设」
只清了一层：命中卡摘要仍是**头部 200 字截断**（`bm25.rs:376-394` 直接
取 ocr/transcript 字段前缀，与查询词毫无关系——命中词在文档后半段时
摘要完全看不到命中依据）；命中卡是**静态 article，不可点击**（
`app-core-v3.js:215-228`），检索结果与既有详情面板（asset_detail，
M8-WP05-T02）之间没有联动；**没有任何过滤面**（三态 radio + 含记忆
之外无筛选维度）；**空态不区分「索引还没建」与「真无命中」**（
`app-core-v3.js:226-228` 统一渲染「换个更短的关键词」——索引目录为
空骨架时这句话是误导，正确动作是跑 `partisync reindex`）。

不做本 WP：检索 tab 停留在「能出哈希和无关摘要」的半成品状态，用户
指认的缺陷只修了三分之一；检索作为产品旗舰面（M8-WP05 语义检索 +
M9-WP03 记忆通道均已堆叠在此 tab）持续不可用，直接抵消 M10「GUI 功能
加速」主线。

## 2. 契约

### 2.1 已完成件登记（T01；PR #156，main=19162bb）——本 SPEC 不重做

- `SearchHit` 增 `filename: Option<String>`（`ipc.rs:44-51`）；
  bm25/hybrid 双路径经 `enrich_hits`（`ipc.rs:119-139`）以 graph
  `entries_by_content` 反查首个 entry name 回填，孤儿索引行置 None。
- 前端命中卡 name 行优先 `h.filename`，缺失回落哈希切片
  （`app-core-v3.js:220`）。
- 测试：e2e `t01_search_hit_carries_graph_filename`（含孤儿行 None
  断言）+ 静态探针 `hit_card_prefers_graph_filename`。
- 遗留：GUI 实操截图未单独归档（任务卡登记「随巡检窗口」）——随本 WP
  T02–T05 的 GUI 验收一并截图覆盖（filename 卡入镜即可）。

### 2.2 T02：命中词高亮 + 有效摘要（引擎定位 + 前端 mark）

- **引擎（partisync-index）**：bm25 `highlight` 生成从「字段头部 200
  字截断」升级为**命中词定位摘要**——用 tantivy `SnippetGenerator`
  （workspace 既有依赖 tantivy 0.26，`Cargo.toml:52`；0.26.2 registry
  源码 `src/snippet/mod.rs` 已核实存在该 API，零新增依赖）在 ocr/
  transcript 字段上生成含查询词的片段窗口；命中词以 ASCII sentinel
  `[[` / `]]` 包裹（实现期可换等价 sentinel，契约不变量见下）。
- **回落语义**：SnippetGenerator 失败 / 命中无词面（如纯向量命中）/
  字段为空 → 维持现状行为（头部截断或 None），**不 panic、不新增错误
  面**。`highlight: Option<String>` 载荷形状不变（前端零分支兼容）。
- **hybrid 继承**：hybrid 高亮本就复用 bm25 源（`rrf_fuse`，
  `hybrid.rs:85-101` highlights map）——引擎层升级自动惠及双通道，
  hybrid 侧零改动。
- **前端（desktop）**：snippet 渲染改为「先 `esc()` 全串，再做
  sentinel→`<mark>`/`</mark>` 替换」。**不变量：模板中不得出现未转义
  的 `${h.highlight}` 插值**；sentinel 之外的字符不得引入任何 HTML。
  `<mark>` 样式入 `styles-v3.css`（高亮色，暗色终端风协调）。

### 2.3 T03：结果-详情联动

- 命中卡整卡可点击（含 `cursor:pointer` 与可访问语义）；点击经**既有**
  `asset_detail({prefix: content_id})` IPC（`ipc.rs:199-211`，零新增
  command）在**检索视图内**呈现详情（大小 / 副本数 / 指纹色 / 副本
  路径，复用 `showDetail` 渲染契约，`app-core-v3.js:129-157`）；面板
  形态（浮层 / 内联区）实现期定，**硬约束：点击不得清空结果列表**，
  返回/关闭后检索结果原样可继续点击。
- 详情标题用 `h.filename`（缺失回落 content_id 切片，沿 §2.1 语义）。

### 2.4 T04：过滤面（结果集扩展名 chips，客户端）

- 每次结果渲染后从命中集 `filename` 派生扩展名集合（大小写归一；无
  扩展名/孤儿行归「(无)」），渲染 chips 行；点击 chip 切换选中态，
  **客户端过滤已渲染命中**（不重发查询、不触后端）；meta 行同步
  「显示 n / 共 m」；全不选 = 不过滤。
- **诚实边界**：只做 filename 可派生的维度。tags 过滤**不做**——生产
  索引 tags 恒空（`reindex.rs:146` `tags: Vec::new()`，M9-WP03-T06
  一期留空）；mime 过滤不做——mime 未入索引 schema。对空维度做过滤
  面 = 「形同虚设」二次犯（§4 非目标登记后续承接）。

### 2.5 T05：空态引导（索引规模可见 + 分支文案）

- 新 IPC `index_stats` → `IndexStats { docs: u64 }`：`state.index()`
  懒加载后取 `Bm25Index::approx_count()`（`bm25.rs:442`，既有 pub
  方法，当前零调用方）；打开失败 → `DesktopError::Index`（与 search
  同语义）；`lib.rs:97` generate_handler 注册。
- 检索 tab 三分支：
  1. **初始态**（未输入查询）：显示当前全文索引规模（如「全文索引
     N docs」；一次拉取缓存，不轮询）；
  2. **索引空**（docs == 0 且零命中）：引导文案明示「全文索引还没有
     建立——运行 `partisync reindex` 建立内容索引」（CLI 命令直出；
     不做 GUI 内执行按钮，§4）；
  3. **有索引无命中**：维持既有「换个更短的关键词 / 切语义模式」文案
     （`app-core-v3.js:226-228`）。
- approx_count 是 reader 快照近似值——UI 只做 0 / >0 粗分支与规模
  徽标，不承诺精确计数（§6-R5）。

### 2.6 验收方式（沿 M8-WP05/M9-WP03 判例，硬性）

- MockRuntime 单测 + e2e（直接调 `ipc::*`，`commands.rs:35-53` 判例）
  + Rust 静态契约探针（`ui_hardening.rs` include_str 断言判例）；
- **真实 GUI 实操截图**（AGENTS.md 桌面端硬性规则）：T02–T05 每任务
  随 PR 归档 `docs/screenshots/M10-WP01-T0n-*.png`（命中高亮入镜 /
  详情联动点开 / chips 过滤前后 / 索引空引导态），environment 不可得
  时 PR 保持 OPEN 打 label「待 GUI 验证」，不得合入；
- property registry 无 UI/检索条目（P1–P20 均为引擎/同步域）——
  **不新设 P 编号，以测试自身为契约**（沿 M9-WP03 §3 判例）。

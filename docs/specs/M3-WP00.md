## 动机

M2 交付了单机同步核 + 多端融合 + E2EE（10⁵ 差异同步 14.1s）。M3 把元数据平面
从单机 SQLite 抬升到分片集群：**partisync-hub v0.1**——按调研方案 §4.3 六条规律
（分片分布式 LSM、平面 ID 与目录树解耦、基数分层、小文件打包、游标分页 + Merkle
反熵）实现 Tectonic/S3 级元数据底座，10⁹ 条目量级。

## 工作包图（依赖序；对应执行方案 §6.4）

- WP01 分片元数据：fjall 存储层、entry 平面 ID 哈希分片、目录树 range 分区 +
  动态分裂（Tectonic + ADLS HNS 合成，调研方案 §5.6）、分片路由
- WP02 复制与一致：openraft 每分片一组、领导者转移/选举演练、单条目线性一致
  语义文档（钉子级，双人全审）
- WP03 hub 对账服务：设备↔hub Merkle 对账（复用 M2 WP03 分级树，P7 无假阴性
  不变量跨端保持）、空间注册表、角色 owner/editor/viewer、**kdf_salt 生产全量
  接线（M2 遗留债务 D2 清偿）**
- WP04 数据面：pack RS(10,4) 纠删（修复限流 ~10%，类 f4）、分层 NVMe→HDD→S3
  冷、增量 GC（分代 + 宽限期，无全局锁，持续写入可完成）
- WP05 全局检索：tantivy 分片索引、usearch 分片向量、联邦查询扇出聚合
- WP06 规模验证：合成 10⁹ 条目导入、节点杀灭演练（-1/-2）、GC 混沌、KPI 实测
  报告（规模验证报告 = 里程碑交付物）

## M3 关门 KPI（执行方案 §6.4 / 调研方案 §7 验收口径）

- 10 节点集群 10⁹ 条目导入 < 24h；
- 两设备经 hub 对账 10⁷ 条目差异 < 5min；
- Raft 节点故障切换 < 10s 且无损；
- GC 在持续写入下完成一轮无锁死；
- 检索 LIST p99 < 100ms（10⁹ 条目）；
- 元数据 ≤ 300 B/条目（盘上 ×3 写放大内）。

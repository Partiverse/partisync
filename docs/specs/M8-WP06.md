## 1. 动机

扩展工具调用的终止保障现状是 **timeout 假终止**：`gateway/src/mcp.rs`
以 `tokio::time::timeout(EXT_CALL_TIMEOUT, spawn_blocking(call))` 兜底
——超时后调用方放弃，但 **wasm 执行仍在后台线程继续空转**（阻塞
`&mut Store` 锁直至 guest 自然结束/死循环永存），线程与实例锁被无限
期占用。M7-WP01 §6-R8 如实登记此缺口；恶意/有缺陷扩展可借此耗尽线程
池（DoS 面）。

不做则扩展生态开放（M9 registry）前终止保障始终是软肋：timeout 数值
调小治标不治本——guest 无法被强制停下。

## 2. 契约（草稿级，批准即冻结；API 均经本地 wasmtime 47.0.0 源码查证）

### 2.1 epoch 终止（主机制，替换「假终止」）

- `Config::epoch_interruption(true)` + `Config::consume_fuel(true)`
  在进程级 Engine 单例（ext-host lib.rs `engine()`）构造期开启；
- 每次工具调用前 `Store::set_epoch_deadline(N)`：N = 当前 epoch +
  `ticks`（ticks 由墙上预算换算：epoch tick 线程固定 100ms 周期
  `Engine::increment_epoch()`，默认预算 = 既有 `EXT_CALL_TIMEOUT`
  换算 ticks，上限对齐现值不放宽）；
- 后台 tick 线程随 Engine 单例惰性启动（daemon 化，进程退出不阻塞）；
- deadline 到 → wasm 执行以 trap 中断（`CallError::Trap`，错误文本含
  epoch deadline 字样）→ ext-host 映射为结构化 `CallError::Deadline`
  → gateway 返回工具级错误 JSON；**外层 tokio timeout 保留**为二层
  防御（tick 线程异常时的兜底），错误文本区分两路径。

### 2.2 fuel 配额（确定性补充）

- `Store::set_fuel(FUEL_BUDGET)`：每次调用前重置为固定常量预算
  （编译期常量，**不进 manifest schema**——避免 P14 注权面变更）；
- fuel 耗尽 → trap → 映射 `CallError::Fuel`；
- 与 epoch 叠加：先到者终止（epoch 管「跑太久」，fuel 管「单调用
  计算量」，语义互补不互斥）。

### 2.3 不变量（不触碰）

- P13/P14 注权面零改动（fuel/epoch 是 Store 级运行时配置，非能力
  授予）；
- 既有 47/47 探针（M7-WP01-T03）与 P15 语义不回归；
- 并发模型不变：每实例 `Mutex<Store>`（epoch deadline 在锁内 set，
  无新竞态面）。

## 3. 验收标准（可执行）

- [ ] **死循环探针**：`loop {}` guest component → 调用在预算内以
      epoch trap 终止，且 `spawn_blocking` 线程随后释放（可复用池）——
      与现状（timeout 放弃后线程永占）行为对照入报告；
- [ ] **fuel 探针**：重计算 guest → fuel trap；正常工具（demo-tool
      级）不受影响（预算余量断言）；
- [ ] **错误语义**：epoch/fuel/外层 timeout 三路径错误 JSON 可区分；
- [ ] **回归**：ext-host 既有探针全绿（47/47 不回归）+ gateway mcp
      面测试绿；
- [ ] 三件套零新增豁免 + CI 全绿 + 覆盖率只升不降；
- [ ] 报告入 `docs/reviews/M8-WP06-termination.md`（含 M7-WP01 §6-R8
      核销声明）。

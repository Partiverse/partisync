# SPEC: M9-WP03 —— 桌面深耕一期（UI 硬化 + 记忆浏览面板 + 旗舰检索记忆通道）

版本: 0.3 · 状态: 批准 · 关联: ADR-0024（桌面壳）/ ADR-0029（记忆层） · 上游: M9-roadmap-proposal §3 / M8-report §5 / M8-WP05-ui-report §D2-D4
负责人: @partiverse · 批准人: @lead · 批准日期: 2026-10-04（v0.1 批准 = PR #134 合入）

## 1. 动机

桌面壳（M6-WP03 起骨架、M8-WP05 六 tab 功能面）目前是「功能可用」
状态，但有三笔登记债未清：**D2/F2**——`app-core-v3.js` 24 处
innerHTML 插值未统一转义（CSP `script-src 'self'` 挡住 inline 脚本
执行，但文件名/标签等可注入字段仍可造成 markup 破格与 UI 状态污染）；
**D3**——详情面板（asset_detail）空库路径无测试覆盖；**D4/N4**——
检索 tab 转写开关是纯语义标注（`include_transcript` 后端常开），开关
状态与实际行为脱节，用户被误导。三笔债同源于「前端提速指令」期的
最小可用实现，现在进入深耕期清偿（M8-report §8-3 建议项）。

同时，M9-WP02 交付的可验证记忆层（MCP 三工具 memory_write/search/
verify）在桌面端没有任何入口——记忆是这个产品 α 主线的核心资产，
没有浏览面 = 用户不可见。WP02 桌面透传链路已验证零改动可达
（`mcp_call("memory_*")`），差一个面板。旗舰语义检索（M8-WP05-T01
search_hybrid 已实装）也只覆盖资产通道，记忆通道未并入统一检索
体验。不做本 WP：UI 注入风险持续存在、记忆层对用户不可见、旗舰
检索是半成品——直接阻塞 WP06 v0.1.0-beta 的产品化口径。

## 2. 契约

### 2.1 UI 硬化（D2/D3/D4 清偿）

- **escapeHtml 统一**：`app-core-v3.js` 全部 innerHTML 插值站点收敛
  为 `esc()` helper（文件名/路径/tag/错误消息/扩展名等一切动态串）；
  静态模板串不强制。**测试契约**：探针经 MockRuntime 注入含
  `<script>`/`<img onerror>`/引号/反斜杠的资产名，断言渲染后 DOM
  中该串以文本节点形式存在（`textContent` 语义），且无新增元素/
  事件属性。
- **详情面板空库测试**：`asset_detail` 在空库（无 content/无 entry/
  无 sidecar）返回形状稳定的空态结构（现有字段可空、不 panic、
  不缺 key），单测覆盖。
- **N4 转写开关诚实化**：开关接通真实语义——IPC `search`/`search_hybrid`
  增 `include_transcript: Option<bool>`（默认 None = 维持后端常开
  现状），UI 开关显式传值；无后端行为变更（索引引擎透传已支持）。
  （若 §6-R1 处置为「否决开关化」则降级为置灰+文案标注。）

### 2.2 记忆浏览面板（新「记忆」tab）

- 经 `mcp_call` 透传三工具，**桌面 Rust 侧零新增 IPC command**：
  - 列表/检索：`memory_search`（query/tag/limit/offset），结果行 =
    content + tags + created_ns + origin_device + score；
  - 验证状态区：`memory_verify`（无 id）→ 根 hex（截断展示）+
    memory_count + ok 徽章（绿/红）；行级「验证」按钮 →
    `memory_verify(memory_id)` → 包含证明展开（leaf_hash/audit_path
    长度/root，ok 徽章）；
  - 写入入口：content 文本域 + tag 输入 + metadata JSON 输入 →
    `memory_write`，`deduplicated=true` 时提示幂等命中；
  - 同步态可见性：记忆行随 bisync 收敛（WP03 探针已证），面板只读
    展示 origin_device 不做编辑。
- **遥测口径**：所有 mcp_call 失败走既有 error-region（工具级错误
  文本透传显示）。

### 2.3 旗舰检索记忆通道

- 检索 tab 保持单一输入框；`searchMode` 三态（关键词/语义）之外新增
  「含记忆」勾选（默认勾选）：勾选时并行调用 `mcp_call("memory_search",
  {query})`，结果与资产命中分区展示（资产区现状不变，记忆区行 =
  content 截断 + tags + score），分区标题标明通道名。
- **排序契约**：资产区与记忆区各自内部排序不变（混合不分再排序），
  避免跨通道 score 不可比问题（§6-R2）。

### 2.5 默认数据目录对齐（v0.2 增补，T05；实施期发现转正）

桌面壳默认数据目录从 `~/Library/Application Support/partisync-desktop/`
（独立空目录——用户实测「没有任何功能」的直接根因：CLI/生态真数据不在此）
改为 `dirs::data_local_dir()/.partisync/`——与既有关键面一致：gateway
MCP `graph.db` 默认、CLI `search --index-root` 默认、MCP sidecar 生态
目录。`--data-dir` 覆盖语义不变；旧目录不迁移不删除（无害遗留，用户可
手动 `--data-dir` 指回）。

### 2.6 检索索引重建命令（v0.3 增补，T06；实施期发现转正）

**背景**：`IndexWriter::upsert_content`/`rebuild_index` 零生产调用方——
产品搜索从未工作过（index 目录恒空骨架；demo 查询系 Bm25Index 直调
example 绕开）。本节补上组合层写入方。

- **命令**：`partisync reindex [--db <path>] [--cas <dir>] [--index-root
  <path>]`（CLI 子命令；缺省沿 search_cmd 口径：db/cas = 工作目录，
  index = data_local/.partisync/index——与桌面默认数据目录一致）。
- **索引语义（拍板 = 方案 2）**：mime `text/*` / 结构化文本 mime
  （json/xml/yaml/toml）；mime 缺失时扩展名白名单嗅探（md/txt/rs/py/
  js/ts/json/yaml/toml/csv/html/xml/sh 等）。命中即读原文进
  `ocr_text` 通道（命中 highlight = 原文片段），单文档 256 KiB
  char 边界截断；非 UTF-8 / 非文本跳过（计数不静默）。
- **数据源优先级（实施期修正）**：indexer 对小文件（< 分块阈值）不写
  CAS——content_id 仅是哈希身份，字节只在源盘。故源文件
  （entry.path，同机索引常见形态）优先读，CAS 单块回退（显式 put 面）；
  大文件（chunk_root 非空）chunk hash 列表未持久化、CAS 不可重组——
  **新债登记：CAS 内容重组缺口**（命中计入 read_errors，挂后续任务）。
- **幂等**：Bm25Index upsert 先删同 content_id 旧文档——重跑安全。
- **tags**：一期留空（entry_tag 关联文本后续 sidecar 管线接管）。

### 2.4 验收方式（沿 M8-WP05 判例，硬性）

- MockRuntime 单测（JS 面经 `wasm`/DOM 断言或纯函数抽出测）+
  **真实 GUI 实操截图验收**（AGENTS.md 桌面端硬性规则）：新记忆 tab
  全空态/有数据态/验证失败态（SQL 篡改后）三态截图归档
  `docs/screenshots/M9-WP03-*.png`；
- escapeHtml 探针 + 空库测试 + 开关接线测试全绿。

## 6. 风险与开放问题

| # | 风险/开放问题 | 处置建议 |
|---|---|---|
| R1 | N4 开关化 vs 标注化：IPC 加参数是最小行为变更，但「开关语义」从此由桌面承诺——后端常开被显式关掉后，检索召回可能下降 | **已拍板开关化**（批准 PR #134 生效）；接受 |

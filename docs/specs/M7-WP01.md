## 1. 动机

Partisync 的工具面（MCP 5+ 工具、桌面壳 `mcp_call`）每次新增能力都要走
「新 MCP tool 进 partisync-gateway + 全门禁」重路径：SPEC、ADR、双通道
审查、crate 地图合规，核心 crate 持续膨胀（SPEC M6-WP04 §1）。ADR-0025
已锁定 C1 路线：wasmtime + WIT Component Model 直接嵌入，宿主形态
「wasm component 即 MCP tool」——扩展实现既有 MCP 工具语义（JSON 入参
→ JSON 出参），经宿主加载后被 `partisync-mcp` 工具面与桌面壳 `mcp_call`
IPC 无差别调用。评估证据（六项基准全 PASS：冷启动 p50 1.6 ms / RTT
p50 0.19 ms / RSS +4.4 MB / 默认拒权可达 / clippy 1.94 零警告 /
deny+audit 全绿）见 [M6-WP04 评估报告](../reports/M6-WP04-wasm-ext-eval.md)。

不解决的代价：扩展能力缺位，第三方/用户自定义工具永远进不了产品；
核心 crate 每个新工具需求都膨胀一轮，沙箱边界与核心稳定域持续混淆。
同时 SPEC M6-WP04 R6 开放问题（沙箱「默认全拒」与 MCP tool 语义需要
部分宿主能力的冲突）悬而未决——本 WP 以 Wassette 式注权 manifest
收口（ADR-0025 决策节 C3 处置登记）。

## 2. 契约

### 2.1 宿主形态与依赖

- 新独立 crate `crates/partisync-ext-host/`（能力层）：**仅依赖 core**；
  索引/图只读不直连 index/graph crate，经 `trait IndexRead`（宿主定义）
  由 partisync-gateway 组装期注入实现——保持 crate 地图「只允许向下
  依赖」，ext-host 与 gateway 无环。若实施中发现 trait 注入不足以
  表达某 capability，回退 `ext-host → graph` 直依赖（合法向下），
  须在实施 PR 说明并同步 ADR-0024 修订登记（不开新 ADR）
- wasmtime 入根 `[workspace.dependencies]`，按 ADR-0025 决策节 diff
  落地：`>=47.0.4, <48`、`default-features = false`、`cache` feature
  **必选**（冷启动预算前提，未命中路径 p95 超预算是已知行为，首载
  预热消化）；wit-bindgen 0.62 / wasmparser 0.259 同线位
- Engine 全局单例（`OnceCell`，沿 M6-WP03 `state.rs` 判例），进程级
  cache 预热一次

### 2.2 沙箱与注权（R6 收口，本 WP 核心增量）

- **P13 全量化**（登记行见 [properties.md](../tests/properties.md) P13，
  现仅覆盖实例化期默认拒 + 错误不泄露）：扩展为 per-call 拒绝语义——
  未注权 component 在每次调用 FS/网络/时钟 host function 时必败，
  错误归因细粒度化，且错误文本不泄露宿主路径/env
- **注权机制：Wassette 式 manifest**。component 旁置同名
  `<name>.json` manifest，声明所需 capability；宿主加载期白名单校验：
  - 校验失败 → **加载即拒**，拒绝先于任何 host function 暴露
  - 校验通过 → 按 manifest 注入对应 host function，**未声明的
    capability 一律不注入**（注入面 = 声明面 ∩ 宿主白名单）
- 注权面最小集（第一版白名单，批准即冻结）：

  | capability | 语义 | host function 面 |
  |---|---|---|
  | `index.read` | 索引只读查询 | 复用既有 MCP 工具语义（经 `IndexRead` trait） |
  | `clock.read` | 当前时间戳 | `now_millis()` |
  | FS / 网络 / 环境 | **不在白名单** | 无注入点，per-call 不可达 |

- **扩展发现约定**：`<data_root>/extensions/*.wasm`（manifest 同名
  `.json` 同目录）；目录扫描于 sidecar/spawn 期一次，不做热重载

### 2.3 调用面

- 扩展工具与内建工具同语义可达：`partisync-mcp` 工具面列举（工具名
  前缀 `ext_`）+ 桌面壳 `mcp_call` 调用（SPEC M6-WP03 §2.3 IPC 面
  **不扩口**）
- 扩展工具结果标注扩展来源（`source: "extension"`），不隐式获得
  内建工具信任级别
- manifest 缺失的 component 加载即拒；同名冲突（扩展工具名与内建
  工具撞名）加载期拒绝，内建优先

### 2.4 性能与资源

- 六项基准口径同 SPEC M6-WP04 §2.3（冷启动 / RTT / RSS / 默认拒 /
  clippy / deny+audit），复测数字入 M7 里程碑报告
- 单扩展加载内存增量上限：spike 实测 RSS +4.4 MB 的同数量级
  （验收 ±50% 容差，超差须解释）

## 4. 非目标

| 项 | 推迟至 | 理由 |
|----|--------|------|
| **扩展自定义数据模型随空间同步** | 独立研究 WP（不设里程碑） | graph schema 演进大坑（Spacedrive 未交卷的领域），SPEC M6-WP04 §4 原样继承，严禁混入实施 WP |
| UI/前端扩展点（桌面壳插件面板） | M7+ 后续 WP（滚动增补） | 先工具面后界面（M6-WP04 §4 继承） |
| 扩展分发/签名/registry | 企业特性议题（WP 立项待拍板，M7-WP00 §2） | 供应链面，需独立威胁模型（M6-WP04 §4 继承） |
| WASI 0.3 全依赖面（HTTP/sockets 等 hosted 能力） | 注权机制成熟后 | 第一版 capability 白名单最小集（M6-WP04 §4 继承） |
| 扩展热重载 / 独立卸载 | 未排期 | 发现约定为 spawn 期一次扫描（§2.2）；热重载引入状态一致性面，无真实需求不立项 |

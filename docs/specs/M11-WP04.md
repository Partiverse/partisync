## 1. 动机

检索摘要（highlight）的取值源是「fan-out 后的索引文本」：写入侧
`bm25.rs:395/:398/:429/:432` 对 ocr/transcript 域落盘的就是
`cjk_fan_out` 扇出串（CJK run 切 unigram+bigram 空格分隔，bm25.rs:219-246），
M10-WP01-T02 补 STORED 后 `search`（bm25.rs:514-519）取到的 stored 值
即该扇出串——中文内容的高亮呈「笔 记 笔记 …」形碎片流，命中词定位
对中文近似失效（债登记 docs/specs/M10-WP01.md §4「中文 fragment
反 fan-out（原文可读摘要）」）。代价评估（M11-WP04-T01，PR #216）
已实测判定绿：新增 stored-only 原文字段的存储域增量 +31%、reindex
全链 <1%，入线建议成立。不做本 WP：GA 不应携带已登记的中文摘要碎片
流债（M11-WP01-T07 GA 判据 J2 硬判据）；Partiverse V3 SearchBackend
与 CLI search 的中文检索体验持续劣化，且随语料增长修复成本只增不减。

## 2. 契约

### 2.0 总则与裁定

- **摘要源迁移，检索语义零变更**：本 WP 只改「摘要从哪取、命中词在哪
  定位」，不动检索面——fan-out 索引域、QueryParser 字段集、BM25 评分、
  召回与排序全部不变。验收判据之一即「同语料同查询，search 命中集与
  改造前一致」。
- **评审深度 R1**：对外行为面变化（search highlight 载荷语义）+ 存量
  索引兼容路径，全审。无新公共 API（`Bm25Index`/`IndexEngine` 签名
  不变）、无 graph schema 迁移（tantivy schema 是索引目录内嵌物）、
  无 unsafe、零新依赖。

### 2.1 schema：stored-only 原文域（T03）

- 新增两字段 `FIELD_OCR_TEXT_ORIG = "ocr_text_orig"` /
  `FIELD_TX_ORIG = "transcript_text_orig"`（字段名沿
  M11-WP04-stored-field-cost-eval.md §4）：stored-only 形态
  （不分词、零 postings、零 fieldnorm），**不进 QueryParser、不参与
  评分**。tantivy 0.26.2 的 stored-only TextOptions 具体形态以 pinned
  registry 源码查证为准（禁凭记忆；见 §6-R1）。
- 写入契约（`upsert` bm25.rs:380-406 / `upsert_batch` :412-440）：对
  `ocr_text`/`transcript_text` 同源双写——扇出串进既有索引域（检索不
  变），原文进 orig 域。`IndexedDoc` 形状不变（orig 取自同一
  `Option<String>` 源，None 则两域皆不写）。同调用点一次成文，不引入
  「两域失同步」窗口。
- 存量兼容（沿 M10-WP01-T02 判例 bm25.rs:71-76 注记）：旧索引按目录
  内嵌旧 schema 打开，打开/检索不受影响；`get_first(orig)` 取不到
  （schema 无此字段或值为空）→ 摘要走回落链（§2.2），重建
  （`partisync reindex`）后获得 orig 域。**降级兼容（新索引被旧二进制
  打开）不承诺**（§4 非目标）。

### 2.2 摘要：反 fan-out 定位（T03）

- `search`（bm25.rs:474-534）摘要回落链改为四级：
  ①**原文定位摘要**——orig 域存在且非空时，在**原文串**上定位查询词
  面（词项面 = `sanitize_query` + `cjk_fan_out` 后的 token 集：
  CJK unigram/bigram 与 Latin 词按字面子串匹配、Latin 大小写不敏感），
  命中区段经重叠折叠后以 sentinel `[[`/`]]` 包裹（bm25.rs:139-140
  既有常量与前端契约不变），窗口 ≤ `SNIPPET_MAX_CHARS`（200）字符量级，
  按字符边界截断；
  ②旧扇出串定位摘要（现行 `field_snippet` 路径，bm25.rs:162-182 原样
  保留）——仅 orig 缺失（存量索引）时触达；
  ③头部截断 `head_truncate`（bm25.rs:187-193，原样保留）；
  ④None。链序契约：**同一文档同一查询，①与②不混搭**（ocr 侧走①则
  tx 侧按同序独立判定，逐字段回落）。
- 下游透传面零形状变更：highlight 载荷仍为「纯文本 + sentinel 包裹」，
  hybrid.rs 合并、gateway/mcp/ipc/CLI 透传与前端 esc 契约不动
  （bm25.rs:136-138 R2 注记延续：sentinel 与正文撞串仅视觉误差，接受）。

### 2.3 性能承诺（T04 实测复核）

- 存储域增量 ≤ **+35%**（评估实测 +31%，留 4pp 余量）；
- reindex 全链耗时增量 < **5%**（评估 <1%）；
- search 单查询延迟不回归（orig 域零 postings 不增评分成本；定位摘要
  为 O(窗口) 字符串操作，≥100ms 级查询面上不可测量）。

## 4. 非目标

- **检索语义/分词器改造**（jieba 等真实分词引入、fan-out 域去留）：
  维持 n-gram fan-out 检索不变，归属检索深化后续 WP / 候选 4 面；
- **语义向量检索实施**：候选 4 维持暂缓（M11-WP05-T03 裁定，T1 语料
  门未满足），线独立；
- **by-hash 流式读**：M11-WP01-T06 已裁不设立；
- **highlight 前端渲染 / IPC / MCP 载荷形状变更**：透传契约冻结（§2.2）；
- **filename/tags 域摘要源改造**：无 fan-out 即无碎片流，不在债面；
- **降级兼容**（新 schema 索引被旧二进制打开）：不承诺、不测试。

## 6. 风险与开放问题

- **R1 tantivy stored-only 形态查证**：`add_text_field(name, STORED)`
  （零 postings）在 pinned tantivy 0.26.2 的可用性与确切 API 形态，须
  registry 源码查证后使用（禁凭记忆）。若该形态不可行，替代序：
  ①`TextOptions::default().set_stored()` 显式构造；②仍不可行 → 回滚
  本 SPEC 修订（评估 STRING|STORED 单 token 形态的膨胀代价）并补 ADR。
  处置：转化为 T03 首步。
- **R2 字面子串定位的词形边界**：Latin 词干还原（en_stem）场景下原文
  高亮框选可能偏窄（如查询 running → 词面 run 框选 running 的前 3 字
  符）、全半角/标点邻接场景偏移——只影响 sentinel 框选精度，不影响
  召回/排序/载荷契约。处置：接受（已知形态单测钉死，长尾登记）。
- **R3 高频单字高亮过密**：unigram 命中在窗口内可能密集（常用字），
  重叠折叠（既有 `collapse_overlapped_ranges`）后仍可能视觉噪声。
  处置：接受；如需窗口内命中数上限属调参非契约，后续 WP。
- **R4 存量索引回落完整性**：旧 schema 打开路径 §2.1 已钉，回落链
  §2.2 ④级兜底；风险残留 = fixture 未覆盖的 schema 形态（如中途版本
  索引）。处置：转化为 T03 测试面（fixture 至少覆盖「旧 6 字段 schema」
  一种；更多形态如实测遇到再登记）。
- **Q1（开放问题）P/L 不新登记的判断**：本 WP 行为由单测 + fixture
  集成测全覆盖，无新增跨操作/跨 crate 不变量（「orig 与扇出域同源」
  由 §2.1 同调用点一次成文保证，单测可达）——判断留评审，否决则先
  registry 后测试（G1）。

# SPEC: M-1-WP01 —— 仓库骨架与 crate 布局

版本: 1.0 · 状态: 批准 · 关联: ADR-0000 · 上游: 调研方案附录 A、执行方案 §6.0
负责人: @lead · 批准日期: 2026-09-18

## 动机

后续一切开发需要在固定的模块边界上进行。骨架定义依赖方向与 crate 职责，是依赖方向 fitness function 的基线。

## 契约

- 单 cargo workspace，成员 = 12 产品 crate + xtask（xtask 随 WP05 加入）。
- 每个 crate：`edition/license/lints` 继承 workspace；`lib.rs` 顶部文档注释声明职责与对应里程碑。
- workspace 级 lint：`unsafe_code = "forbid"`（ADR-0000）。
- 工具链钉版 1.93.1；rustfmt 默认风格；deny.toml 许可证白名单按执行方案 §5.1。

## 验收标准

- [ ] `cargo build --workspace` 与 `cargo test --workspace` 零警告零失败
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` 通过
- [ ] `cargo fmt --all --check` 通过
- [ ] 每个产品 crate 有单句职责描述（lib.rs 文档注释）

## 非目标

任何真实实现（全部为骨架占位）；依赖引入（WP07 首次引入 getrandom，另见 ADR-0001）。

## 涉及文件清单

Cargo.toml、rust-toolchain.toml、rustfmt.toml、deny.toml、.gitignore、crates/**

## 风险与开放问题

- crate 边界可能随实现演进 → 以「依赖方向 + 公共 API 变更需 ADR」约束，接受。

# SPEC: M2-WP04 —— 设备网络：iroh 集成 + 助记词配对

版本: 1.0 · 状态: 批准 · 关联: M2-WP00、ADR-0008、调研方案 §5.8（设备↔设备通道）
负责人: @lead · 批准日期: 2026-09-19

## 动机

WP01–03 在同进程双 Store 上验证了同步核与对账协议。WP04 把对端从「同进程
句柄」抽象为「网络可寻址对端」：iroh（QUIC + 打洞 + 中继回退 + 连接迁移）
+ 助记词配对（Ed25519 挑战 + X25519 ECDH）保证初次相遇的可信建立。

## 契约

### 1. schema v11（只增）

```sql
-- device 表扩 endpoint / 配对会话表
ALTER TABLE device ADD COLUMN endpoint TEXT;             -- iroh NodeAddr 序列化
ALTER TABLE device ADD COLUMN pairing_state INTEGER NOT NULL DEFAULT 0;  -- 0=none, 1=pending, 2=paired
ALTER TABLE device ADD COLUMN last_endpoint_update_ns INTEGER;

CREATE TABLE IF NOT EXISTS pairing_session (
    id              TEXT PRIMARY KEY,   -- ULID
    code            TEXT NOT NULL,      -- 12 词助记词（空格串）
    initiator_dev   TEXT NOT NULL,      -- 发起方 device id
    responder_dev   TEXT,                -- 接收方 device id（首次握手回填）
    state           INTEGER NOT NULL DEFAULT 0,  -- 0=open, 1=accepted, 2=closed
    ephemeral_pk    BLOB NOT NULL,       -- 发起方临时 X25519 公钥
    shared_secret   BLOB,                -- 双方 ECDH 完成后落盘（加密后）
    created_ns      INTEGER NOT NULL,
    expires_ns      INTEGER NOT NULL    -- 5 分钟有效期
);
CREATE INDEX IF NOT EXISTS idx_pairing_state ON pairing_session(state, expires_ns);
```

> **PFS 修订（SEC-AUDIT-2026-M2-001 P1-2，2026-09-19）**：`ephemeral_sk` 不再落盘——
> 临时私钥仅驻留发起方进程内存（会话结束/进程退出即消失），SQLite 页与 WAL 无副本。
> 旧库由 migrate() 重建为上表形态（schema v13）。

### 2. 配对协议（v1，简化为「互信一次，永续复用」）

**发起方**（用户在 A 设备输入 12 词代码）：
1. 生成临时 X25519 密钥对 (`esk_a`, `epk_a`)；
2. 创建 `pairing_session`，state=open，code=助记词；
3. 助记词编码：`BIP-39 wordlist english.txt`（2048 词）—— 12 词 = 128 bit 熵
   ＝**配对码的最低 128 bit** = `esk_a` 截位 → 12 个 11-bit 索引映射到词表；
4. 通过二维码/手输把 12 词交给对端；
5. 监听 iroh 上的发现端口（5 min TTL）。

**接收方**（用户在 B 设备输入 12 词）：
1. 词→索引→位流，验证熵 → 派生对端的 `epk_a` 视图（不验证——后续 ECDH 完成验证）；
2. 生成临时 X25519 密钥对 (`esk_b`, `epk_b`)；
3. 通过 iroh ALPN 握手，发送 `epk_b` + 用共享 secret 签名的 nonce；
4. 发起方验证 `epk_b` 与代码派生期望一致（仅 12 词 → 截位匹配 epk_a 前 N bit）
   ——**不是密码学校验**（助记词本就是凭据），只是检查代码未过期、避免拼写错。

**密钥派生**：
```
shared_secret = X25519(esk_a, epk_b)        # 发起方
shared_secret = X25519(esk_b, epk_a)        # 接收方（结果相同）
device_keypair = Ed25519::derive(shared_secret || "device-key-v1")
endpoint_secret = blake3(shared_secret || "endpoint-secret-v1")
```

**设备身份持久化**：`device_keypair` 写入 `device.pubkey`（已有字段，hex 编码）；
`endpoint_secret` 仅落内存（iroh 会话密钥材料，零持久化——重连重握）。

**会话终结条件**：
- 双方各自把 `pairing_session.state = closed`，`shared_secret` 行清零（zeroize）；
- 设备注册表更新为 `pairing_state = 2`，endpoint 写入。

### 3. iroh transport 抽象

```rust
// crates/partisync-sync/src/transport/mod.rs
#[async_trait]
pub trait Transport: Send + Sync {
    /// 同进程对端（同 Store 双开）：用于 bisync/reconcile 跑模型测试
    async fn connect_inproc(&self, peer: &Store) -> Result<Box<dyn Peer>>;
    /// iroh 网络对端（生产）：通过 NodeAddr 拨号
    async fn connect_iroh(&self, endpoint: &NodeAddr) -> Result<Box<dyn Peer>>;
}

pub trait Peer: Send {
    async fn push_oplog(&mut self) -> Result<SyncStats>;
    async fn pull_oplog(&mut self) -> Result<SyncStats>;
    async fn reconcile(&mut self) -> Result<ReconcileStats>;
}
```

- `InprocTransport`（同进程）保留 WP01–03 测试路径—— **bisync/reconcile 全套模型
  测试零回归**；
- `IrohTransport`（网络）通过 ALPN `partisync/sync/1` 与对端双向；
- `bisync/reconcile` 内部不感知传输——通过 `Peer` trait 抽象面。

### 4. 助记词词表

- 使用 `bip39` crate（RustCrypto 生态，标准 2048 词 english wordlist）；
- 12 词 = 128 bit 熵 = X25519 私钥的最低 128 bit；
- v1 **不**走 BIP-39 checksum（PBKDF2 强化是 WP07 主密钥的事，配对码本身是
  临时凭据，5 min TTL 后失效）——节省 PBKDF2 启动成本。

## 验收标准（可执行）

- [ ] 助记词 round-trip：随机 X25519 私钥 → 12 词 → 还原私钥等值；
- [ ] 配对闭环（inproc + 模拟 iroh 回路）：
      A 发起 → B 输入代码 → 双方独立计算 `shared_secret` → 双方计算
        `device_keypair` 等值 → 双方 device 表 pairing_state=2、endpoint 写入；
- [ ] 配对码过期：5 min TTL 后会话拒绝；
- [ ] 助记词拼写错（替换一词）→ 接收方拒绝（密钥不匹配）；
- [ ] 零回归：P6/P11/P7/WP02/WP03/WP06/WP08 全绿；
- [ ] fmt/clippy/test 全绿。

## 风险与开放问题

- iroh 1.x API 漂移（ADR-0008 已声明）——本 WP 不引入 iroh 行为层接口，
  仅留抽象 trait；iroh 集成若拉延期，bisync/reconcile 不受影响；
- 助记词的"凭据在线"语义（M1-WP07）属密码学教育范畴——文档显式告知用户
  「配对码本就是凭据，5 min 后失效」；
- X25519 私钥的 128 bit 截位降低暴力枚举成本——配对码一次性 + 5 min TTL 抵减
  风险，且 A→B 通道本就是「显式互信」（用户主动输入）。

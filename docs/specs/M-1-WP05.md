# SPEC: M-1-WP05 —— 追溯与治理基建

版本: 1.0 · 状态: 批准 · 关联: ADR-0000、执行方案 §2/§3 · 上游: 执行方案 §6.0
负责人: @lead · 批准日期: 2026-09-18

## 动机

可审计性体系（执行方案 §2）的机械化：追溯链的每一跳都要能被脚本验证，而不是靠记忆。

## 契约

1. **xtask**（`cargo xtask`）：
   - `trace <TASK-ID>`：从 git trailer 提取挂接该任务的全部提交，打印 hash/subject/Spec/AI 披露/人工评审与触及文件；无命中退出非零。
   - `report <MILESTONE>`：汇总该里程碑提交数/任务数/工作包分布/AI 辅助占比/人工终审占比；`docs/reports/<M>-report.md` 不存在时生成报告骨架（含自动统计），已存在则不覆盖。
   - trailer 提取启发式：每个 key 取 body 中最后一次出现（兼容 squash 合并）。
2. **commit-msg 钩子**：非合并提交缺合规 `Task-ID: M?-WPnn-Tnn` trailer 时拒绝（`scripts/install-hooks.sh` 安装）。
3. **治理文档**：根 AGENTS.md（AI 第一上下文）；模板四件套（SPEC/ADR/PR 检查单/里程碑报告，docs/templates/）；属性不变量登记册（docs/tests/properties.md）。

## 验收标准

- [ ] xtask 单元测试覆盖：trailer 解析（含取最后一次出现）、里程碑前缀过滤、工作包提取
- [ ] `cargo xtask trace` 对演练任务 M-1-WP07-T01 输出完整链
- [ ] `cargo xtask report M-1` 生成骨架且统计与实际提交一致
- [ ] 钩子对无 Task-ID 提交拒绝（实测演示）

## 非目标

PR 级校验的 GitHub 集成（WP02 的 task-ids job 承担）；issue 系统对接（无远端，人工任务卡以 SPEC+提交为源）。

## 涉及文件清单

xtask/**、scripts/hooks/commit-msg、scripts/install-hooks.sh、AGENTS.md、README.md、docs/templates/**、docs/tests/properties.md、Cargo.toml（workspace 成员增量）

## 风险与开放问题

- trailer 启发式对 rebase 改写历史的鲁棒性 → 约束：禁止 force-push main，接受。

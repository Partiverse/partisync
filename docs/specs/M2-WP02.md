# SPEC: M2-WP02 —— 双向同步：bisync、冲突血缘与 Tag 共享域（P11）

版本: 1.0 · 状态: 批准 · 关联: M2-WP00、M2-WP01、properties.md P11/P6、调研方案 §5.7（rclone bisync 先例） · 上游: M2-WP01（同步核）
负责人: @lead · 批准日期: 2026-09-19

## 动机

WP01 建立域分离同步核（oplog + push/pull + 保留两者后缀）。WP02 补齐三块：

1. **冲突一等公民化（P11）**：rclone bisync 的 `file.conflict1` 只是文件名约定；
   PartiSync 把冲突挂进资产图谱——同名双改 → 两者皆可寻址，且血缘（基准路径、
   双版本路径、来方设备、触发 oplog 行）可查。宁可多一份副本，不可静默丢数据。
2. **共享域首个真实租户**：Tag（WP01 预留 domain=1）——HLC 全序 LWW 重放，
   创建冲突 union 合并，删除用墓碑防复活。
3. **bisync 定衬封装 + `--max-delete` 类安全阈**（rclone 先例）。

## 契约

### 1. schema v7（只增）

```sql
CREATE TABLE IF NOT EXISTS tag (
    id          TEXT PRIMARY KEY,   -- ULID（随创建 oplog 传播 = 全局共享身份）
    space_id    TEXT NOT NULL DEFAULT 'default',
    name        TEXT NOT NULL,
    color       TEXT,
    deleted     INTEGER NOT NULL DEFAULT 0,  -- 共享域删除 = 墓碑（LWW 防复活）
    updated_hlc TEXT                          -- 本行最后生效写入的 oplog HLC key
);
-- 链接不用 FK、以 entry path 为身份：entry ULID 每节点各自生成（设备自有域），
-- 不可做跨节点身份；path 唯一且随 entry oplog 收敛。悬空行（entry/tag 未到位）合法，
-- 查询 JOIN 自然过滤。
CREATE TABLE IF NOT EXISTS entry_tag (
    tag_id      TEXT NOT NULL,
    entry_path  TEXT NOT NULL,
    deleted     INTEGER NOT NULL DEFAULT 0,  -- unlink 亦为墓碑（防晚到 link 复活）
    updated_hlc TEXT,
    PRIMARY KEY (tag_id, entry_path)
);
CREATE INDEX IF NOT EXISTS idx_entry_tag_path ON entry_tag(entry_path);
CREATE TABLE IF NOT EXISTS sync_conflict (
    id            TEXT PRIMARY KEY,  -- ULID
    space_id      TEXT NOT NULL DEFAULT 'default',
    base_path     TEXT NOT NULL,     -- 双方主张的同一路径
    local_path    TEXT NOT NULL,     -- 本位保留版本路径
    incoming_path TEXT NOT NULL,     -- 改挂冲突后缀版本路径
    origin_device TEXT NOT NULL,     -- 来方设备
    detected_hlc  TEXT NOT NULL,     -- 触发应用的 oplog 行 key（全局同一，可去重）
    at_ns         INTEGER NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_conflict_dedup
    ON sync_conflict(base_path, incoming_path, detected_hlc);
```

### 2. 同步核修正：中继保持原 HLC 键 + 因果更新

WP01 中继行在接收端以本端时钟重新发号（键漂移），LWW 无从比较。WP02 修正：

- `Store::record_oplog_raw(...)`：以**给定 hlc key** 插入（`INSERT OR IGNORE`，
  同写多径到达天然去重），中继改用之——一个写入全网同一个键；
- 插入前对本端时钟做 `Hlc::recv(wall, remote)`（M0-WP01 接收规则）：此后本端
  新写入严格晚于一切已见远端写——LWW 全序成立；
- 设备自有域行为不变（全量行 upsert，与键无关）。

### 3. 冲突「保留两者 + 血缘」（P11）

- `apply_remote_entry` 返回 `ApplyOutcome { path, conflict }`：
  conflict = `Some { base_path, incoming_path }`（发生改挂）；
- **冲突后缀防覆盖**：候选 `{path}.conflict-{owner}`——已存在且同 content_id →
  幂等复用（重复投递安全）；已存在且内容不同 → `-2`、`-3`… 递增找空位
  （防后缀名恰被他人文件占用导致覆盖丢数据）；
- session 检出 conflict → `Store::record_conflict(...)` 落 `sync_conflict`
  （血缘四元组：base/local/incoming/origin + detected_hlc）；
- 查询：`Store::list_conflicts(limit)`（新→旧）。

### 4. Tag 共享域（HLC LWW）

- Store API：`add_tag / update_tag / delete_tag（墓碑）/ tag_entry / untag_entry /
  list_tags / tags_of_entry / entries_for_tag`；
- capture（域=1，entity='tag' / 'entry_tag'）：`record_tag_upsert / record_tag_remove /
  record_tag_link / record_tag_unlink`——本端写图谱后调，oplog 键即本笔写入的 LWW 水位；
- 应用语义（session）：`existing.updated_hlc >= row.hlc`（HLC key 字符串序 == 时间序）
  → 跳过（落选/已见）；否则应用字段 + `updated_hlc = row.hlc`；
  upsert/link 置 `deleted=0`，remove/unlink 置墓碑 `deleted=1`；
- 中继：**应用成功才转发**（落选行是陈旧写，不广播）；origin 保留（回环防护不变）；
- tag/entry_id 链接身份用 entry_path（§1 表注）；悬空软引用合法，JOIN 过滤。

### 5. bisync 与安全阈

```rust
pub struct PushOpts { pub max_delete: Option<u64> }
pub struct BisyncOpts { pub max_delete: Option<u64>, pub max_rounds: u32 } // 默认 max_rounds=8
pub async fn bisync(a: &Store, b: &Store, opts: BisyncOpts) -> Result<BisyncStats>;
// BisyncStats { rounds: u32, pushed: u64, pulled: u64, conflicts: u64 }
```

- `push_opts(src, dst, opts)`：批内待应用 remove 行数 > `max_delete` → **整批拒绝**
  （Fatal，先于任何应用——宁可不动，不可误删；rclone `--max-delete` 同语义）；
- `push / pull` 保留无阈签名（`max_delete: None`）；
- bisync 定衬：反复双向 push，直到整轮 `applied==0`（不动点）或 `max_rounds`；
  `conflicts` 为全程累计。

## 验收标准（可执行）

- [ ] **P11 模型测试（proptest）**：两节点对同一路径随机并发双写（内容各异）→
      bisync 后两版本皆 `entry_by_path` 可寻址且内容与各自所写一致；
      `sync_conflict` 恰有一条血缘记录（base/local/incoming/origin 齐全、指向两版本）；
- [ ] 冲突后缀防覆盖：同路径同属主连续三版冲突 → 三个不同路径共存，首版内容不丢；
- [ ] Tag 共享域收敛（P6 扩展）：三节点随机 tag/link/unlink/update + 随机同步 →
      全部节点 tag 集合与链接集合等价（含墓碑态）；
- [ ] 墓碑防复活：unlink 后晚到的 link（更小 HLC）不生效；delete_tag 后晚到 upsert 不复活；
- [ ] LWW：并发改同名 tag → 全网收敛到 HLC 大者（含 device 决胜）；
- [ ] max-delete：批内删除数 > 阈值 → Err 且对端状态与 oplog 均不变（先拒后用）；
- [ ] bisync 定衬：任意初态 → rounds 有界；稳态后再 bisync applied==0；
- [ ] 回归：P6 既有场景全绿；fmt/clippy/test 全绿。

## 风险与开放问题

- LWW 对同字段高频交替写丢中间态——WP01 已文档化，Tag 同口径（最终态一致）；
- 落选行不转发 vs 陈旧行未及全网：落选判定依 `updated_hlc` 而非到达序——
  先到的新行照样生效、后到的旧行被拒，无复活窗口；全网覆盖由全量对账（WP03）兜底；
- `sync_conflict` / 墓碑无上限增长：查询 LIMIT 兜底，清理归 WP08；
- 中继保键改变 WP01 内部语义：同写多径 `INSERT OR IGNORE` 去重更严，
  P6 回归测试守护（不改任何 P6 断言）。

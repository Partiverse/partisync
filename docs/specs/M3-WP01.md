# SPEC: M3-WP01 —— 分片元数据：fjall 存储层、哈希/Range 双平面与动态分裂

版本: 1.0 · 状态: 批准（G0）· 关联: M3-WP00、调研方案 §4.3 六规律/§5.6 元数据引擎、properties.md P7（分片语义保持）· 上游: M2 关门报告
负责人: @lead · 批准日期: 2026-09-20

## 动机

M2 交付单机同步核（10⁵ 条目 / SQLite）。M3-WP01 把 hub 元数据平面抬到 10⁹ 条目量级：
单库 SQLite 与全路径反规范化在 10⁸ 之上失效（写热点、LIST 前缀扫描退化、无水平扩展）。
按调研方案 §4.3 已验证的工业规律（Tectonic/ADLS HNS/DanceNN），落成**双平面合成**：
entry 平面哈希分片（均匀写入、O(1) 点查）+ 目录树 children 聚簇 range 分区
（有序扫描、动态分裂）。本 WP 只做**存储与路由**，不触复制（WP02）、对账（WP03）、
数据面（WP04）、检索（WP05）。

## 裁定总览（本规格的关键决策）

1. **双平面合成**：entry 平面 = 固定 256 哈希分片，`shard_id = blake3(entry_id)[0..2]
   as u16 % 256`；目录树平面 = children 聚簇，键 `(dir_id, name)` 字典序，range 分区。
2. **O(1) 改名的来源**：children 聚簇键用 `dir_id` 而非全路径（学 ADLS HNS/DanceNN）。
   目录改名只写目录 entry 行 + 该目录的 children 行投影，**不重写任何后代**——
   后代的 parent 指针是 entry id，与名字解耦。
3. **跨平面 = 投影，不做跨分片事务**（调研方案 §4.3 规律 6、Tectonic Name/File 层
   独立一致的先例）：entry 行是权威，children 行是投影；投影暂缺由**读时修复**
   （get/put 命中权威行后补投影）兜底，最终一致由 WP03 Merkle 对账收口。
4. **hub 侧不落 `entry_closure` 表**：闭包行均摊 `深度×36B` 会击穿 ≤300B/条目预算；
   子树遍历 = children 递归迭代器（深度 ≪ 子树宽度，且目录层可内存缓存）。
   与调研方案设备端 closure 表的差异在此显式声明。
5. **分片 = 独立 fjall keyspace**：v0.1 单进程多分片（256 哈希分片 + 动态 range 分区
   各自独立 keyspace/目录），WP02 在每分片上套 openraft 组。
6. **分裂只作用于 range 平面**：单分区行数超 64K → 沿键序中位边界一分为二；
   哈希平面固定 256 分片，永不分裂。

## 契约

### 1. 数据模型与行编码（紧凑二进制，非 JSON——≤300B/条目预算）

| 平面 | 键 | 值 | 预算 |
|---|---|---|---|
| entry（哈希） | entry_id（ULID 16B 二进制） | parent_id 16B + kind 1B + name 变长 + content_id 32B + size varint + mtime_ns 8B + state/flags 2B | ≈110–180B |
| children（range） | dir_id 16B ␟ name 变长 | entry_id 16B + kind 1B + deleted 1B | ≈40–90B |

- 合计 ≈150–270B/条目 < 300B；盘上含 LSM 写放大 ×3 内（KPI 口径，T06 基准实测）。
- 删除 = entry 行墓碑（state 位）+ children 投影行删除；墓碑保留至 WP03 对账窗口。
- 字段语义对齐设备端 schema v14 `entry` 表的 hub 相关子集（不含 scan_journal /
  oplog 等设备侧簿记）。

### 2. 分片路由

```rust
pub fn shard_of(entry_id: &[u8; 16]) -> u8 { /* blake3(entry_id)[0..2] u16 % 256 */ }
```

- 路由表 `shard_id → node_id`：v0.1 单节点静态映射，API 面按「路由表可替换」设计
  （WP02 后物理分片上 Raft 组、WP06 后跨节点迁移的插桩点）。
- ULID 时间有序 → 不允许按 id 直接 mod 分片（写热点）；必须过哈希。

### 3. range 分区与动态分裂

- 分区表：`[start_key, end_key) → partition_id`（持久化于独立 keyspace，路由层内存缓存）。
- 初始单分区 `[∅, ∅)`（全空间）；children 写入路径查分区表路由。
- **分裂协议**（fjall 原子批 + 分区元数据先行，保证崩溃后无半分裂状态）：
  1. 读源分区计数超 64K 行 → 选键序中位边界 `m`；
  2. 原子批写入新分区元数据行（`{m..end}` → 新 partition，状态 `splitting`）；
  3. 批量搬移 `{m..end}` 键到新分区 keyspace（幂等，可重试）；
  4. 原子批更新分区状态为 `active` → 路由生效；源分区惰性清理。
  - 崩溃恢复：`splitting` 状态分区以「双读（源 + 目标合并视图）」继续服务，
    搬移重放至完成（元数据先行 ⇒ 恢复方向确定）。
- 合并非目标（KPI 未要求；10⁹ 规模只增不减）。

### 4. Hub API（`partisync-hub`）

```rust
pub struct Hub { /* 256 哈希 keyspace + range 分区组 + 路由表 */ }
impl Hub {
    pub fn open(root: &Path) -> Result<Hub>;                       // 多分片打开/恢复
    pub fn put_entry(&self, e: &EntryRow) -> Result<()>;           // 权威行 + 投影补写
    pub fn get_entry(&self, id: EntryId) -> Result<Option<EntryRow>>;
    pub fn remove_entry(&self, id: EntryId) -> Result<()>;         // 墓碑 + 投影删
    pub fn rename_entry(&self, id: EntryId, new_parent: Option<EntryId>,
                        new_name: &str) -> Result<()>;             // O(1)：行写 + 投影迁移
    pub fn list_children(&self, dir_id: EntryId, cursor: Option<ChildCursor>,
                         limit: u32) -> Result<ChildrenPage>;      // keyset 分页
    pub fn subtree(&self, dir_id: EntryId) -> impl Iterator<Item = EntryRow>;
                                                                   // children 递归迭代器
}
```

- `list_children`：`(dir_id, name)` 前缀 range 扫描 + keyset 游标
  （`ChildCursor { last_name }`）；单目录百万子项时 p99 由分页保证。
- **读时修复**：`get_entry`/`list_children` 检测权威行与投影不一致（含投影缺失）
  时以权威行为准补齐投影（写回），返回值永远以权威行构造。
- v0.1 单写者串行（进程内 &self 独占）；并发写冲突语义留 WP02 复制层定义。

### 5. 一致性语义（WP02 线性一致文档的底稿）

- 单 entry 行读写在单分片内线性一致（fjall 单 keyspace 原子批）；
- entry↔children 跨平面**无事务**：投影允许短暂陈旧（窗口 = 崩溃间隙），
  读时修复 + WP03 对账收口。此裁定写入本节，WP02 文档展开并双人全审。

## 验收标准（可执行，测试先行）

- [ ] **路由确定性 + 均匀性**（proptest）：shard_of 确定性重放一致；10⁶ 随机 ULID
      样本分片分布最大偏差 < 5%（均值 1/256）；
- [ ] **投影一致性**（proptest，P 风格随机操作序列）：随机 put/remove/rename 后，
      权威行集合 == children 投影重建的目录树（无幽灵子项、无孤儿投影）；
- [ ] **LIST 分页完备**：随机目录树（≥10⁴ 行）keyset 分页全遍历 == 有序全量集合，
      无重复无遗漏；cursor 从中间页续传正确；
- [ ] **rename O(1) 语义**：改目录名后：点查/LIST/子树遍历反映新名；后代 entry 行
      键与投影键**逐一不变**（断言行数不变，即无子树重写）；
- [ ] **动态分裂**：构造 >64K 行分区触发分裂 → 分裂前后全量键集相等、路由表命中
      全部键、无丢键无重键（属性测试，随机键序写入触发多次分裂）；
- [ ] **崩溃一致性**（failpoint 注入分裂协议各步）：kill 后重开 → 服务可用、
      键集完整、无半分裂元数据残留（splitting 态按协议收尾）；
- [ ] **盘上预算基准**：10⁶ entry 导入后测盘上字节/条目 ≤300B（含写放大 ×3 口径）；
- [ ] **基准报告（T06）**：10⁷ entry 顺序导入吞吐、LIST p99（10⁷ 本地实测 +
      10⁹ 外推口径，KPI 终裁归 WP06）；对照 M2 关门 KPI 表登记；
- [ ] 回归：fmt/clippy/test 全绿；既有 workspace 测试不受影响。

## 风险与开放问题

- fjall 3.1 API 与多 keyspace 资源开销（每分片独立目录 ×256 + range 分区）——
  T02 ADR 进场时以该版本文档/源码核实 keyspace 复用模型，必要时收敛 keyspace 数
  （分片键加前缀共享实例），行为契约不变；
- 读时修复的额外写放大——预算基准（T06）覆盖；若击穿 300B 口径，回退为
  后台异步修复（正确性不变，陈旧窗口变长，由 WP03 对账兜底）；
- 投影陈旧窗口内 LIST 可能漏子项——单写者 v0.1 窗口仅崩溃间隙；WP02 复制层
  语义文档须重审此裁定（双人全审钉子）；
- D1 外部审计阻塞 WP01 的密码学面——本 WP 为纯存储/路由，不触 KDF/密钥/加密列
  （blake3 仅作分片路由哈希，非 KDF 用途），不在冻结范围；KDF 层冻结纪律照旧。

# SPEC: M2-WP01 —— 同步核：域分离 oplog 与收敛性（P6）

版本: 1.0 · 状态: 批准 · 关联: M2-WP00、properties.md P6、调研方案 §5.7（Spacedrive V2 域分离先例） · 上游: M0-WP01（HLC）
负责人: @lead · 批准日期: 2026-09-19

## 动机

多设备同步的正确性核心。设计决策（调研方案 §5.7，Spacedrive V2 验证过）：
文件系统数据天然单属主——**设备自有数据（Entry/位置/属主）单写者，属主状态永远权威**，
不需要 CRDT/共识；真正共享的数据（Tag/用户元数据/Content 身份）用 HLC 排序的 oplog + LWW。
域分离把「全量 CRDT」的复杂度砍掉 80%。

## 契约

### 1. 同步域（sync domain，schema v6 只增）

```sql
ALTER TABLE entry ADD COLUMN owner_device TEXT;   -- 域归属：条目属主设备（默认 'device-local'）
ALTER TABLE entry ADD COLUMN synced_seq INTEGER;  -- 已同步水位（对端 ACK 后推进）
-- oplog 表（journal 之上：journal 记「本地 fs 事件」，oplog 记「待广播的图谱变更」）
CREATE TABLE IF NOT EXISTS sync_oplog (
    hlc      TEXT PRIMARY KEY,    -- HLC 序列化（phys:logic:device）
    space_id TEXT NOT NULL DEFAULT 'default',
    domain   INTEGER NOT NULL,    -- 0=设备自有 1=共享
    entity   TEXT NOT NULL,       -- 'entry' / 'tag' / …
    entity_id TEXT NOT NULL,
    op       TEXT NOT NULL,       -- 'upsert' / 'remove'
    payload  TEXT NOT NULL,       -- JSON（变更字段；设备自有域=全量行，共享域=LWW 字段集）
    at_ns    INTEGER NOT NULL
);
```

### 2. 变更捕获 `partisync-sync::capture`

```rust
pub async fn record_entry_change(store, entry_id, op) -> Result<()>;   // 图谱写操作后调
// 域判定：entry.owner_device == 本机 → 设备自有域（全量行 payload）；
//        否则共享域（仅被改字段——v1 简化：Tag/UserMetadata 类共享实体才走此域）
```

捕获点：indexer/journal/watch 的所有 add_entry/remove_entry 变更统一挂接
（`Store::add_entry` 内部调用——保证「图谱无不广播之变更」不变量）。

### 3. 同步对端协议 `partisync-sync::sync_session`

```rust
pub struct SyncSession { /* 对端 Store 句柄（M2-WP04 前用直连 SQLite/内存对端模拟） */ }
impl SyncSession {
    pub async fn push(&self) -> Result<PushStats>;   // 本地 oplog → 对端应用 + ACK 裁剪
    pub async fn pull(&self) -> Result<PullStats>;   // 对端 oplog → 本地应用
}
```

**应用语义（P6 的核心）**：
- 设备自有域：仅属主设备的 oplog 可变更该 entry——非属主收到属主变更 → 幂等应用
  （upsert 全量行，属主字段跟随 oplog）；冲突不可能（单写者）；
- 共享域：HLC 全序重放，同 entity 同字段取 HLC 大者（LWW）；创建冲突 union 合并；
- 应用后进对端 oplog（防回环：oplog 带来源设备，应用时跳过 source==self）；
- ACK 裁剪：对端确认已应用的最小 HLC 水位 → 本地删除 ≤ 水位且被所有对端 ACK 的 oplog 行。

### 4. 回环防护与重放幂等

- 每个 oplog 行带 `origin_device`；应用端 `source == self` 跳过；
- 应用是幂等的（upsert/remove 语义同 M0-WP04）——重放同批 oplog 统计不变（P8 复用）。

## 验收标准（可执行）

- [ ] **P6（收敛性，本项目最重属性测试）**：proptest 构造 2–3 节点、随机操作序列
      （两节点并发 upsert/remove/tag 写）+ 随机 push/pull 顺序（含重复投递）→
      全部节点最终状态等价（entry 集合 + tag 状态）；
- [ ] 单写者纪律：非属主对设备自有 entry 的本地变更被 oplog 拒绝（测试断言）；
- [ ] HLC 全序：共享域 LWW 用 HLC 比较（复用 M0-WP01，含 device 决胜）；
- [ ] 回环防护：A→B→A 的 oplog 不再产生新 oplog（死循环测试）；
- [ ] ACK 裁剪：双向 push/pull 稳态后双方 oplog 行数 ≤1（水位裁剪生效）；
- [ ] 幂等重放：同批 oplog 重放 stats 不变（P8）；
- [ ] fmt/clippy/test 全绿。

## 风险与开放问题

- add_entry 内部挂接捕获 → 与索引器批事务的嵌套（捕获写在批外，事务外发）——
  崩溃窗口：批提交成功但 oplog 未写 → 漏广播。v1 口径：**索引场景不捕获**
  （全量索引即全量状态，对端通过空间首次同步拉全量），仅 watch/journal 路径捕获——
  漏广播面收窄为「journal 已应用但 oplog 未写」，与 P8 同窗口，重放收敛；
- LWW 对「同字段高频交替写」可能丢中间态——设计接受（文档化，最终态一致）；
- oplog 膨胀：ACK 裁剪 + v1 单对端；多对端 ACK 集合归 WP04。

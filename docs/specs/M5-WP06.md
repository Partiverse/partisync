## 动机

M5-WP01..04 各自交付了单点恢复语义测试（UploadAck 超时重试、联邦分区
重连、scan 断点续传、event checkpoint），但散布在各 WP 测试文件内、
**默认 CI 只跑常规口径**，缺三块：① 跨层混沌场景（多层故障叠加：联邦
分区期间 scan 崩溃 + event 重投递）；② 并发竞争矩阵（federation 并发
claim、多 source 并发 drain——目前仅 happy-path 并发隔离）；③ 夜间
调度入口（重套件不打扰常规 CI 时长）。WP06 = 聚合 + 补缺 + nightly 入口。

## 裁定总览

1. **聚合优先，不重写**：既有混沌资产直接纳入 nightly 清单——
   `hub::wp02`（raft crash 演练 19 测）、`hub::m5_wp01`（UploadAck
   FlakySink/超时）、`hub::m5_wp02`（联邦分区重连）、`sync::m5_wp03`
  （scan 崩溃恢复 5 测）、`sync::wp09`（oplog failpoint）。缺失场景
   才新建（T02/T03）。
2. **补缺场景（hub）**：联邦**并发竞争**——两 hub 同时 claim 同一空间
   ×N 轮（竞态窗口真实并发，非顺序复现）→ 断言收敛唯一 winner（tie-break
   语义在并发下成立）；raft leader crash 期间联邦查询照答陈旧视图
   （分区语义 × raft 崩溃叠加）。
3. **补缺场景（sync）**：**多层故障叠加**——scan 分片失败与 event
   checkpoint 中断同时注入（两个 failpoint 并发启用）→ 各自恢复语义
   独立成立；chaos.rs 分区拓扑下 reconcile 收敛（M2-WP09 既有能力 ×
   新编排）。
4. **nightly 入口**：新文件 `.github/workflows/nightly.yml`（schedule
   cron）——**不触碰 ci.yml 门禁阈值**（铁律红线）；夜间跑全量
   `cargo test --workspace` + `--ignored` 混沌/基准冒烟（NK env 同 CI
   Linux 不需要）+ 失败 artifact 留痕。macOS job 跳过（时长），Linux
   单 job。手动 `workflow_dispatch` 可触发。
5. **报告即工件**：收官报告 `docs/reports/M5-WP06-chaos.md` 登记场景
   矩阵（场景 × 既有/新增 × 测试名）与 nightly 入口说明。
6. **模糊测试不立项**：cargo-fuzz 需 nightly 工具链 + 新依赖授权
   （铁律 8）；proptest 已覆盖随机化口径（M3 投影一致性等）。本 WP
   「模糊」由 proptest 既有资产代表，登记于报告。

## 验收标准（可执行）

- [ ] 并发 claim race：N=20 轮双 hub 并发 claim 同空间 → 每轮两侧视图
      收敛同一 winner（hub_id 小者或更高 epoch 者）。
- [ ] 崩溃叠加：leader crash 期间联邦 RouteQuery 正常应答（本地视图）；
      重启后反熵收敛。
- [ ] 多层故障叠加：scan failpoint（`scan.shard_done`）+ event
      failpoint（`event.before_apply`）并发启用 → 两者恢复语义独立
      成立（各自测试断言互不干扰）。
- [ ] chaos.rs 分区编排：3 节点环形分区（A↔B 断、B↔C 通、C↔A 断）→
      逐对恢复 → 全网收敛、无数据丢失。
- [ ] nightly workflow 语法有效（yaml lint / workflow_dispatch 触发）。
- [ ] 回归：fmt/clippy/test 全绿；M0–M5 全部既有套件原样通过。

## 风险与开放问题

- **并发竞态测试的抖动**：20 轮并发 claim 若偶发不收敛 = 发现真缺陷
  （不是测试问题）——处置：失败轮次打印两侧视图快照留痕，不放宽断言。
- **nightly 时长**：全量 workspace + ignored 基准估 40–60min（Linux
  2C runner）；可接受（夜间窗口）。ignored 基准只跑「冒烟级」（WP03
  t06、WP05 t03 元数据仿真），WP05 全量 10⁶ 基准不进 nightly（1h 级）。
- **schedule cron 的时区**：GitHub Actions cron = UTC；低峰窗口选择
  已折算。

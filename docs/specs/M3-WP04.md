# SPEC: M3-WP04 —— 数据面：pack RS(10,4) 纠删、分层存储与增量 GC

版本: 0.1 · 状态: **草案（待 G0 批准）** · 关联: M2-WP03（CAS 块库+引用计数）、
ADR-0004（fastcdc）、ADR-0006（OpenDAL/S3）、ADR-0011（fjall）· 上游:
M3-WP01~WP03（hub 元数据/复制/对账）、M2-report 债务表（D3 iroh）
负责人: @lead

## 动机

hub 元数据面（WP01~03）已具备 raft 复制、线性一致语义与对账服务；数据面
仍是散块 `ChunkStore`（M0/M2 遗产：fastcdc 分块 + blake3 块库 + 引用计数）。
本 WP 把数据面补齐为可运营形态：

1. **pack + RS(10,4) 纠删**：小对象聚合为 pack（目标 128–256MB，索引与
   数据分离），条带化 RS(10,4)——单 pack 损坏 ≤4 分片可重建；修复速度
   限流（≤10% 后台带宽，类 Backblaze f4 口径）；
2. **分层存储**：热 NVMe → 温 HDD → 冷 S3（OpenDAL 既有 ADR-0006 通道），
   按温度策略自动迁移与回取；
3. **增量 GC**：分代 + 宽限期 + 引用计数核销——持续写入下一轮 GC 完成
   且无全局锁、无死锁（M3 DoD 验收项）。

同时按 M2 债务表清偿 **D3**：iroh + iroh-blobs 设备↔hub 数据传输进场
（与 EC 同 ADR 族，一并列 ADR-0014/0015 评估）。

## 现状锚点（诚实标注）

- `partisync-cas` 现有面 = `ChunkStore`（put/get/incr/decr + 分块器）；
  **pack 格式与 EC 均未实现**（M2-WP03 计划内 pack v1 实际未落地——本
  SPEC 直接定义 pack v2 含 EC，不留 v1 兼容包袱）；
- 分层/GC 完全空白。

## 裁定总览（待 G0 批准的关键决策）

1. **pack v2 格式**：`pack = 头部(魔数/版本/索引偏移) + 数据区 + 索引区
   （块 hash → (offset,len,EC 元数据)）`；目标聚合 128–256MB/包（L1 索引
   常驻 fjall：`m-pack-idx`）。写入路径：块先落散块（现 ChunkStore 不动），
   聚合器满/过期刷 pack，刷后散块转「待核销」；
2. **RS(10,4) 条带**：数据区按条带切分（10 数据 + 4 校验分片，分片尺寸
   对齐 pack 目标/条带数）；单分片丢失/损坏可重建（≤4）。**进场依赖
   reed-solomon-erasure（纯 safe 实现）→ ADR-0014 + cargo deny**（铁律 8；
   进场时核实 safe 声明与 API，如需 unsafe 改选型并修订）；
3. **修复限流**：后台修复任务全局令牌桶 ≤10% 估计带宽（类 f4）；修复
   队列持久化于 fjall（`m-pack-repair`），重启续跑；
4. **分层引擎**：三级（NVMe/HDD/S3），温度 = 访问时间衰减 + 空间水位；
   降级（热→冷）整 pack 迁移 + 索引改指针；回取（冷→热）按块按需 +
   异步整包回迁；S3 走 OpenDAL（ADR-0006），凭证配置化；
5. **增量 GC = 分代 + 宽限期**：GC 代际推进（young→old），只扫新代 +
   增量引用核销；块删除须过宽限期（默认 24h 可配）防在途引用悬挂；
   **无全局锁**——GC 与写入并发（per-pack 粒度锁 + 引用计数原子操作）；
6. **D3 iroh 进场**：iroh（QUIC 打洞+中继）+ iroh-blobs（BLAKE3 验证流式）
   同 ADR-0015 评估进场，hub 作为 ALWAYS 可达节点承接设备数据上行与
   下发；本 WP 只做设备↔hub 通道，多 hub 联邦归 M5；
7. **分裂×复制 M4-M6 显式接线评估**：数据面 pack 命令（聚合/迁移/GC）
   进 hub raft 的形态在 T02 设计时评估——若写放大不可接受，改为
   「控制面命令 + 数据面本地执行 + 影子行对账验证」并修订 SPEC 记录。

## 契约

### 1. pack 生命周期

`put_chunks`（散块）→ 聚合器 → `pack v2`（EC 条带化落盘）→ 索引常驻 →
（分层迁移）→ GC 核销。块读取：索引命中 pack → 定位分片 → 命中即读 /
缺失触发修复（限流）→ 组装返回。

### 2. 分层与 GC 并发

- 迁移/GC 均以 pack 为粒度（per-pack 锁）；引用计数incr/decr 原子；
- GC 宽限期内删除块仅标记；宽限期后核销，pack 有效数据比 < 阈值则重打包；
- 崩溃一致性：迁移/重打包 = 写新删旧（新 pack 完整 + 索引原子切换后才
  删旧），任一步崩溃可重入。

### 3. iroh 通道（D3）

- 设备上行：iroh-blobs BLAKE3 验证流式 → hub 散块区 → 聚合器；
- hub 下发：按块清单出 pack 分片流；
- 配对/密钥沿用 M2 ADR-0008/0010（E2EE 不变，中继只见密文）。

## 验收标准（可执行，测试先行）

- [ ] **EC 正确性**（proptest）：任意块集 pack 编码 → 随机破坏 ≤4 分片 →
      解码逐块还原（含索引区损坏重建）；
- [ ] **pack 读写语义**：聚合后散块可删、按 hash 读回逐字节相等
      （proptest，10²–10⁴ 块规模）；索引常驻查询 O(1)；
- [ ] **修复限流**：令牌桶实测修复带宽 ≤ 配额（10%）± 抖动容差；
- [ ] **分层迁移**：温度策略触发整包迁移（NVMe→HDD→S3）+ 回取按需，
      迁移中途 kill → 重启可重入、无丢块；
- [ ] **GC 无锁死**：持续写入 + 并发 GC 完成一轮（M3 DoD）——
      loom/压力测试形态，宽限期语义正确（期内块不真删）；
- [ ] **iroh 通道**：设备经 iroh-blobs 上行 1GB 级数据集 → hub 逐块
      验证入库；断线重连续传；
- [ ] 回归：fmt/clippy/test 全绿；deny 通过（reed-solomon-erasure +
      iroh + iroh-blobs 进场复核，ADR-0014/0015 登记）。

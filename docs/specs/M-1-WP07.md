## 契约

`crates/partisync-core::ulid`，零实现依赖（仅 dev-dep proptest；OS 熵经 getrandom，ADR-0001）。

```rust
pub struct Ulid(/* 16 字节大端：48 bit 毫秒时间戳 + 80 bit 随机 */);

impl Ulid {
    pub const fn from_parts(timestamp_ms: u64, random: u128) -> Ulid;
    //    timestamp_ms 取低 48 bit（掩码），random 取低 80 bit（掩码）
    pub fn now() -> Ulid;                       // 系统毫秒 + OS 熵；熵不可用 → panic（文档化）
    pub fn timestamp_ms(&self) -> u64;          // 低 48 bit 时间戳
    pub fn random_part(&self) -> u128;          // 低 80 bit 随机段
}

impl fmt::Display for Ulid;                     // 26 字符大写 Crockford Base32
impl FromStr for Ulid;                          // 恰 26 字符，大小写不敏感

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)] // 字节序比较
pub enum UlidError { InvalidLength { len: usize }, InvalidChar(char), Overflow }
```

**编码**：Crockford 字母表 `0123456789ABCDEFGHJKMNPQRSTVWXYZ`（排除 I/L/O/U）。
**解析规则（严格）**：恰 26 字符；大小写不敏感；`I/L/O/U` 及一切非字母表字符 → `InvalidChar`；
首字符译值 > 7（即整数值 ≥ 2^128）→ `Overflow`；长度 ≠26 → `InvalidLength`。
**已知向量**：`from_parts(0,0)` ⇔ `"00000000000000000000000000"`；
`from_parts(0xFFFF_FFFF_FFFF, u128::MAX)` ⇔ `"7ZZZZZZZZZZZZZZZZZZZZZZZZZ"`（全值上限）；
`"8ZZZZZZZZZZZZZZZZZZZZZZZZZ"` → `Overflow`（8 译值 8 > 7）。
**排序**：`Ord` = 字节序 = (timestamp, random) 数值序；ts 严格更小 ⇒ Ulid 更小（L2）。
**非单调保证**：`now()` 不保证同毫秒单调——排序需求由 oplog/HLC 承担（调研方案 §5.7），此为显式非目标。

单调 ULID、UUID 互转、加密强度随机源抽象（直接 OS 熵即够）、字符串排序与字节排序差异处理（本实现两者一致）。

## 风险与开放问题

- Crockford 进位/掩码边界易错 → 已知向量 + 属性测试双向覆盖；
- 严格解析（拒绝 I/L/O/U 不做别名映射）可能与外部 ULID 字符串互操作摩擦 → 内部主键场景可接受，如未来需要导入外部 ID 另行 ADR；
- `now()` panic 策略 → 熵失败属环境级不可恢复，接受并文档化。

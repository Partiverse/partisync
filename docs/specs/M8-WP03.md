## 1. 动机

Hub 是 E2EE 体系里唯一的中立元数据方，也是企业化的真正战场（M7-WP03
趋势调研判例：竞争全在治理平面）。当前 Hub 无审计留痕、无配额护栏、
无租户概念——企业部署三问（「谁在何时动了什么」「空间会不会被写爆」
「多部门如何隔离」）均无法回答。M7-WP03-T03 已把三项登记为 P2 候选，
本 WP 把它们从议题变成可交付面。

不做则 M9 的 SSO/合规叙事没有地基，企业客户诉求触发时仍需从零起草
（候选清单登记已两年期空转）。

## 2. 契约（草稿级，批准即冻结）

### 2.1 审计日志（audit trail）

- **事件源**：Hub 业务写（`HubCmd` apply 面——Put/Remove/Rename，经
  M8-WP04 接线后的 raft 提交点）+ 管理面操作（registry/路由/配额
  变更）；事件字段 `actor / action / object / ts / result`；
- **存储**：append-only JSONL（fjall 独立 keyspace + 按窗滚动文件
  导出）；**异步 sink**——审计写入不阻塞写路径热路径（有界队列，
  队满降级策略实施期定稿并登记）；
- **完整性锚**：逐行链式哈希（前一行 hash 入当前行），导出文件附
  链头链尾 digest——**防篡改检测**（诚实边界：Hub 管理员仍可重写
  全量，密码学级防管理员归 M9 外部审计议题，登记不扩）；
- **导出**：`partisync-hub audit export --from --to` → audit-ready
  JSONL（合规消费方口径）。

### 2.2 空间配额

- 计量口径冻结为**逻辑字节**（CAS 逻辑内容字节，非 EC/pack 物理放大
  ——口径差异写入文档）；计量面复用 graph/cas 统计；
- **硬限**：空间超限 → 写路径拒绝 `QuotaExceeded`（结构化错误，可
  被 CLI/FUSE 映射为 ENOSPC）；**软告警**：阈值（默认 80%）触发
  事件（沿 UploadAck 事件面通知，UI 呈现归 WP05）；
- **挂载面护栏联动**：FUSE 写回路径（M8-WP07）消费同一配额判定——
  本 WP 只暴露判定 API，挂载侧接线归 WP07 任务卡。

### 2.3 多租户最小面

- 空间↔租户映射：`tenant → [space_ids]`（registry 面 CRUD）；一个
  空间至多属一个租户；
- 隔离保证沿既有密码学面（空间级 KDF 派生隔离，M2 判例）——本 WP
  只做**策略面**：跨租户列举/路由不可见探针 + 映射一致性；
- SSO/OIDC/AD-LDAP 一律留 M9（M8-WP00 非目标表）。

## 3. 验收标准（可执行）

- [ ] **审计探针**：写/删/改名/配额变更 → JSONL 行字段完备 + 顺序
      一致；链式哈希篡改检测探针（改任一行 → 链验失败必报）；
- [ ] **导出探针**：`audit export` 时间窗内容与 keyspace 内存对照
      一致；链头链尾 digest 可独立复算；
- [ ] **配额探针**：硬限拒绝 + 错误映射（QuotaExceeded→ENOSPC 路径）；
      软告警阈值触发一次且仅一次；计量值与实际逻辑字节对照 ≤ 容差
      （容差实施期定）；
- [ ] **多租户探针**：跨租户列举不可见；空间换绑租户的拒绝路径；
- [ ] **热路径无回归**：apply/事件流吞吐对 M5-WP04 口径（508k evt/s）
      无回归（阈值任务卡定）；审计异步 sink 背压可观测；
- [ ] **新不变量候选 P18**（审计链完整性：任意行篡改 → 链验必报）
      实施**前**走 partisync-property-registry 转正（P16=WP07 写回、
      P17=WP04 读单调已订）；
- [ ] 三件套零新增豁免 + CI 全绿；覆盖率只升不降。

## 动机

当前远端索引（`graph::remote_index::index_provider`）是**单线程递归
collect 后字典序处理**：LIST 吞吐受单连接限制，10⁶ key 量级即可观测瓶颈
（调研方案 §4.1：单机 stat 10⁴/s，10¹² = 3.2 年——并行化是必需品不是优化）。
本地索引已有作业化断点（M0-WP05，checkpoint 每 200 文件），但远端扫描没有
并行与分片粒度恢复。WP03 交付扫描调度器：目录前缀即分片、worker 池自取
队列（闲者多劳）、分片账本持久化（断点恢复），为 WP04（事件流增量）前的
全量扫描路径补齐规模化能力。

## 裁定总览

1. **位置与形状**：`partisync-sync/src/scan.rs`（能力层向下依赖 provider/
   graph，方向合规）。核心三件套——`ListSource`（清单源 trait：列单层）+
   `ScanScheduler`（worker 池 + 分片队列）+ `EntrySink`（批次消费 trait）。
   `impl ListSource for Provider` 落 sync 侧（trait 本地，孤儿规则合规；
   sync 新增 provider 依赖 = 能力层→领域层，无需 ADR）。
2. **分片 = 目录前缀，BFS 隐式分裂**：分片单元 = provider 内部目录前缀。
   worker 取分片 → 列单层（`ListSource::list_dir`）→ 文件项分批（512）交
   sink → 每个子目录作为新分片入队。深/宽目录自然产生更多分片——**自适应
   分裂即 BFS 展开本身**，无需独立热分片机制。负载均衡 = 队列自取（闲者
   多劳），无中心分配器。
3. **并行模型**：固定 worker 池（`concurrency` 默认 min(8, cpu)，可配），
   每任务循环：原子取分片 → 列 → 分批 apply → 记 done。统计
   （`ScanStats`：分片 done/failed、条目数、elapsed）原子累积 + 进度回调
   （每 done 分片一次）。
4. **断点恢复 = 分片粒度账本**（诚实口径：分片内列一半不设断点——单层
   list 为原子操作，分片即最小恢复单元）：`ScanJournal` trait（save/load
   账本：done/failed 分片集 + 累计统计）+ 默认 JSON 文件实现（
   `serde_json`，既有依赖，零新增）。每 done 分片落盘一次（crash 至多重扫
   当前在途分片）。恢复语义：重载账本 → 跳过 done → **failed 重入队** →
   在途分片按 pending 重扫。
5. **失败语义**：分片源失败 → 重试 1 次后记 `failed` 并继续（末尾汇总
   报告，不静默吞错）；sink 失败 → **fail-fast** 立即停池（写入面脏数据
   风险 > 吞吐）。failpoint 命名点（`scan.before_sink` /
   `scan.shard_done`）复用 `sync::failpoint` 供崩溃矩阵注入。
6. **有序性放宽（与 remote_index 的差异）**：并行分片无全局字典序——
   sink 需接受乱序批次；断点语义由分片账本承接（取代现行「字典序路径
   划界」）。graph 写入面为幂等 upsert（remote_index §契约），乱序安全。
7. **CLI 接线（T05）**：新子命令 `partisync scan-plan`——对 provider 目标
   执行调度扫描（dry-run 统计口径：分片数/条目数/吞吐/失败清单），支持
   `--concurrency N` 与 `--journal <path>`（断点续扫）。**不入库**：graph
   写入面的 sink 化改造（index_provider 并行化）归后续卡——本 WP 交付
   调度与恢复内核 + 可观测 CLI，入库集成独立成卡符合原子交付。
8. **单层扁平巨目录不分裂**（OpenDAL `list` 单层语义限制）：10⁷ keys 平铺
   单目录仍为单分片；字典序 range 分片（start-after 语义）归后续卡。
   账本/统计对巨型分片给出显式告警（单分片条目 > 10⁵ 记 warning 回调）。

## 契约

### 1. 数据模型（scan.rs）

| 项 | 形态 |
|---|---|
| `ListedNode` | `{ path: String, is_dir: bool, size: u64, mtime_ns: u64 }`（单层项） |
| `ListSource` | `async fn list_dir(&self, dir: &str) -> Result<Vec<ListedNode>, PartisyError>`（空 dir = 根；`""` 为根） |
| `EntrySink` | `async fn apply(&self, dir: &str, entries: &[ListedNode]) -> Result<(), PartisyError>`（按分片批次；`Send + Sync`） |
| `ShardStatus` | `Pending / Done / Failed { error }` |
| `ScanStats` | `shards_done / shards_failed / entries / dirs / elapsed`（原子累积快照） |

### 2. 调度器

- `ScanScheduler::new(source, sink, opts)` → `run(seed: &str, journal:
  Option<&ScanJournal>) -> Result<ScanStats, PartisyError>`；
- `ScanOpts { concurrency, batch_size(512), progress: Option<回调>,
  warning_threshold(10⁵) }`；
- worker 循环（裁定 2/3/5）：取分片 → `list_dir`（失败重试 1 次）→
  子目录入队 + 文件批交 sink → `journal.record_done` → 计数；
- 池停机条件：队列空 **且** 全 worker 空闲（无在途分裂）。

### 3. 账本（断点恢复，裁定 4）

- `ScanJournal`：`async fn save(&self, state: &JournalState) ->
  Result<(), PartisyError>` / `async fn load(&self) ->
  Result<Option<JournalState>, PartisyError>`；
- `JournalState { seed, done: Vec<String>, failed: Vec<(String, String)>,
  entries: u64, dirs: u64 }`（JSON 文件实现 `FileJournal`：临时文件 + 原子
  rename，防半写）。

## 验收标准（可执行，测试先行）

- [ ] **并行加速**：fake source（确定性树 + 每分片注入延迟）下，
      concurrency=4 对串行加速比 ≥ 2.5×；条目集一致（与串行基线对账）。
- [ ] **负载均衡（BFS 分裂）**：宽/深混合树全部分片完成、无饥饿；单层
      超 10⁵ 项触发 warning 回调（巨型分片告警）。
- [ ] **失败隔离与 fail-fast**：某分片源持续失败 → 重试 1 次 → failed
      计入且不阻塞其余；sink 失败 → 池立即停 + Err 返回。
- [ ] **断点恢复**：failpoint 注入中断（部分分片 done 已落账本）→ 新
      调度器 resume → done 分片不重扫（source 访问计数断言）→ 最终条目
      集与全集一致；failed 重入队重扫。
- [ ] **账本原子性**：FileJournal 半写（截断文件）load 容错（报错不
      panic，恢复语义可继续）。
- [ ] **Provider 接线**：fs 后端 tmpdir 真实树（文件/子目录混合）走通
      全链（source=Provider）。
- [ ] **CLI**：`scan-plan` 对 fs 目标完成 dry-run 统计 + `--journal` 续扫
      幂等（第二轮 0 新条目）。
- [ ] 回归：fmt/clippy/test 全绿；M0–M4 与 M5-WP01/02 既有套件原样通过。
- [ ] **基准（T06）**：加速比曲线（1/2/4/8 worker）、恢复正确性、吞吐
      实测登记 `docs/reports/bench/M5-WP03-scan-scheduler.md`。

## 风险与开放问题

- **OpenDAL 单层 list 语义**：`list` 各后端层级语义差异（fs/s3/webdav）由
  Provider::list_children 既有口径吸收（M1 验收）；调度器不直触 OpenDAL。
- **巨型扁平目录**（裁定 8）：v0.1 单分片不分裂——s3 站点若存在 10⁷ 扁平
  前缀，扫描退化为单 worker；告警回调兜底观测，range 分片归后续卡。
- **乱序 sink 与 remote_index 字典序 checkpoint 的兼容**：两者并存（现行
  路径不动）；graph 写入面 sink 化时以账本取代路径划界（后续卡设计题）。
- **跨 hub 扫描委派**：M5-WP02 路由视图已就绪，但分片委派协议（hub 间
  工单分发）超出本 WP；「分布式」v0.1 = 单进程内并行调度内核 + 恢复
  语义，委派归 WP04 后评估（避免本 WP 拖入联邦写路径）。

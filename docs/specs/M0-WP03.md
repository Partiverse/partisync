## 动机

块级去重与泛化 delta 是 PartiSync 对 rclone 的头号差异化（调研方案 §2.2 缺口 1/§5.8）。
本工作包落地分块器与内容寻址块库，并让演示面呈现**块级节省**——同源大文件
（模型 checkpoint 场景）的真正杀手锏。

## 契约

### 1. 分块器 `partisync-cas::chunker`

```rust
pub struct CdcConfig { min: usize, avg: usize, max: usize }
impl CdcConfig {
    pub const PRODUCTION: Self;                    // 256KiB / 1MiB / 4MiB
    pub const fn new(min, avg, max) -> Result<Self, CdcConfigError>;
        // 归一化：向下取 8 的倍数（fastcdc v2020 约束，ADR-0004）；min<avg<max 校验
}
pub fn chunk_boundaries(data: &[u8], cfg: CdcConfig) -> Vec<(usize, usize)>; // (offset,len)
pub fn chunk_root(chunk_hashes: &[&str]) -> String; // blake3(concat(hex))——块清单 Merkle 根（P4 的 root(chunks)）
```

### 2. 块库 `partisync-cas::store::ChunkStore`

```rust
pub struct ChunkStore { /* objects/ 两级扇出 + index.db（chunks: hash PK, size, refcount）*/ }
impl ChunkStore {
    pub async fn open(root: &Path) -> Result<Self>;        // 幂等迁移
    pub async fn put(&self, data: &[u8]) -> Result<String>;    // 已存在 ⇒ refcount+1 不重写（P4）
    pub async fn get(&self, hash: &str) -> Result<Vec<u8>>;
    pub async fn incr(&self, hash: &str) -> Result<i64>;
    pub async fn decr(&self, hash: &str) -> Result<i64>;       // 归零 ⇒ 删行删文件（GC 微操作）
    pub async fn stats(&self) -> Result<CasStats>;             // chunks, chunk_bytes, saved_bytes, refs
}
pub struct CasStats { chunks: i64, chunk_bytes: i64, refs: i64, saved_bytes: i64 }
// saved = Σ(size×refcount) − Σsize（块级去重口径）
```

### 3. 索引器集成（schema 迁移 v2：只增）

- `ALTER TABLE entry ADD COLUMN chunk_root TEXT`（大文件的块清单根）；
- 文件 ≥ `CdcConfig::PRODUCTION.min` ⇒ 分块入库 ChunkStore，entry 记 chunk_root；
  小文件维持整文件 content 去重（两段式采样哈希归后续批次，v1 采样省略并在此声明）。

### 4. 演示与夹具

- `gen-fixture --blobs N --blob-size <bytes> --blob-versions k`：N 组 × k 个版本的
  checkpoint 场景（版本间共享 ~95% 内容，仅尾部变异）；
- CLI `index`/`ui` 增加 `--cas <dir>`（默认 `./partisync.cas`）；
- UI 统计卡新增「块级节省」（`/api/cas-stats`）。

## 验收标准（可执行）

- [ ] **P1**：同输入两轮分块 → 边界序列逐位相等；
- [ ] **P2**：在位置 p 插入/删除字节后，p + avg 之外的全部边界不变（内容定义性）；
- [ ] **P3**：任意输入所有块长 ∈ [min,max]；1 MiB 随机流均值落在 avg±30%；
- [ ] **P4**：`chunk_root == content_hash(concat(chunk_hex))`；同块二次 put → refcount+1、
      objects 文件数不变、get 返回原字节；
- [ ] decr 归零：行与对象文件删除；再 put 可重建；
- [ ] checkpoint 场景端到端：6 版本 × 2MB 基底（5% 尾部变异）→ 块级 saved_bytes ≥ 总量 70%；
- [ ] 索引器幂等（含分块路径）：重复索引 stats 与 cas stats 均不变；
- [ ] fmt/clippy/test 全绿；core+cas 变异分数维持 ≥60%。

## 非目标

pack 打包与 EC（M3）；两段式采样哈希（后续批次）；流式/异步分块（StreamCDC 留接口，v1 全内存）；
块级 delta 传输协议（M2-WP05）。

## 风险与开放问题

- 全内存分块对超大文件（>1GB）的内存压力 → v1 演示规模接受；WP07 引入 StreamCDC 流式路径；
- refcount 崩溃一致性（put 文件成功但索引写失败）：对象写入先于索引提交，孤儿对象由
  M3 分代 GC 回收（文档化，不阻塞 v1）；
- `chunk_root` 仅为块清单摘要，非 Merkle 树（无分支验证能力）——M2 delta 协议升级为
  分级 Merkle 时迁移，SPEC 先声明口径。

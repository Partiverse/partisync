# SPEC: M0-WP04 —— 文件事件管线（watcher → scan_journal → 增量应用）

版本: 1.0 · 状态: 批准 · 关联: ADR-0005、properties.md P8（journal 部分）、调研方案 §5.7 · 上游: 执行方案 §6.1-WP04
负责人: @lead · 批准日期: 2026-09-18

## 动机

全量扫描在万亿级推算下不成立（单机 3.2 年，调研方案 §4.1）——增量事件驱动是必需品。
本工作包让「文件系统里发生的事」可靠地流入 PartiGraph：watcher 事件 → journal 落盘 →
幂等应用到图谱，崩溃后重放收敛。演示面上表现为：改文件 → 网页统计自动更新。

## 契约

### 1. schema v3（只增）

```sql
CREATE TABLE IF NOT EXISTS scan_journal (
    seq  INTEGER PRIMARY KEY AUTOINCREMENT,
    path TEXT NOT NULL,          -- 虚拟路径（/ 相对于索引根）
    kind INTEGER NOT NULL,       -- 0=created, 1=modified, 2=removed
    at_ns INTEGER NOT NULL
);
```

### 2. journal 队列 `partisync-graph::journal`

```rust
pub async fn record(store, path, kind) -> Result<()>;          // 事件落盘（应用前）
pub async fn pending(store) -> Result<Vec<JournalEvent>>;      // seq 序
pub async fn apply_pending(store, cas, fs_root) -> Result<Applied>;
    // 逐条幂等应用；成功后删行。Applied { created, modified, removed, skipped }
```

**应用语义**：
- created/modified：fs 现存文件 → 哈希（≥256KiB 分块入库）；`add_entry` 升级为
  **upsert**（path 冲突时更新 size/mtime/content_id/chunk_root，保留 id 与位置——
  这是 M0-WP02 契约的修订：幂等语义不变，新增「新鲜度」语义，见 Changelog）；
  中途新目录链自动补建（ensure_dir_chain）；
- removed：`remove_entry(path)` 级联——删除 entry + 闭包双向行 + 子树整体；
  content 无引用后删除行；**块库孤儿块留待 M3 分代 GC**（M0-WP03 SPEC 风险节既定，此处如实继承）；
- fs 路径已消失的 created/modified → 按 removed 处理（自愈）。

### 3. watcher `partisync-graph::watch::watch_loop`

`notify::RecommendedWatcher`（std mpsc）→ tokio 桥接 → 去抖窗口（默认 1s）内按 path
合并取末态 → record → apply_pending → 输出摘要。Ctrl-C 优雅退出。

### 4. CLI 与演示面

- `partisync watch <root> [--db --cas --debounce-ms 1000]`：先幂等全量索引，再进入事件循环；
- UI：5s 轮询统计与当前视图（前端自动刷新，无需手写刷新逻辑变更 API）。

## 验收标准（可执行）

- [ ] journal 集成测试（内存库 + 真实临时目录）：注入 created/modified/removed 事件行 →
      apply 后图谱统计精确变化；**重复 apply 同一批事件（重放）→ 统计不变（P8 幂等收敛）**；
- [ ] upsert：modified 事件更新 size/mtime/content 且 id 不变（L 语义：id 稳定性）；
- [ ] removed 级联：删目录 → 子树 entry/闭包/content 全清；最后一个引用删除后 content 行消失；
- [ ] 崩溃口径测试：apply 中途「崩溃」（注入 panic 后重开库重放）→ 最终统计一致；
- [ ] 端到端演示：watch 运行中，fs 增/改/删文件 → UI 统计 5s 内自动反映（curl 断言）；
- [ ] fmt/clippy/test 全绿。

## 非目标

作业系统持久化（M0-WP05，下一批）；周期性对账扫描兜底（WP07）；块库孤儿 GC（M3）；
rename 事件区分（v1 = removed+created 对）；网络 fs 事件可靠性（明确不可靠，兜底扫描管）。

## 风险与开放问题

- notify 在 macOS FSEvents 的事件延迟（~1s 级）：演示可接受，去抖窗口覆盖；
- 大批量事件（rsync 灌库）风暴：v1 顺序应用，WP07 加批量窗口自适应；
- **本 SPEC 修订 M0-WP02 的 add_entry 契约**（幂等 → 幂等+新鲜度），已在此留痕，
  人工终审注意点：upsert 不改变 entry.id 与 parent 位置。

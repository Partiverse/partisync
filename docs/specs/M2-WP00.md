# SPEC: M2-WP00 —— M2 总纲：同步引擎、多端与 E2EE

版本: 1.0 · 状态: 批准 · 关联: 执行方案 §6.3、调研方案 §5.7/§5.11、properties.md P5–P8/P11 · 上游: M1（关门报告见 docs/reports/M1-kpi.md）
负责人: @lead · 批准日期: 2026-09-19

## 动机

M1 建立了「单机资产图谱 + 协议双面」。M2 兑现产品核心主张：**多设备融合**——
同一空间的资产跨设备一致（P6 收敛性）、离线可用（P8 已有 journal 基础）、端到端加密可选。

## 工作包图（依赖序；对应执行方案 §6.3）

- WP01 同步核：域分离（设备自有单写者 / 共享域 HLC oplog）+ P6 收敛性测试（M2 最重属性测试）
- WP02 双向同步：bisync + 冲突策略「保留两者 + 血缘」（P11）
- WP03 Merkle 对账：分级树 + 水位线快路径（P7 无假阴性）
- WP04 设备网络：iroh 集成 + 助记词配对（Ed25519 挑战 + ECDH）
- WP05 块级传输：iroh-blobs 验证流 + 泛化 delta（块清单交换）
- WP06 占位符：placeholder 骨架同步 + 按需 hydrate
- WP07 E2EE：空间级密钥层次（**钉子 + 外部审计为 G3 硬门禁**）
- WP08 版本回收：trash-can / staggered 版本化
- WP09 混沌测试床：三节点容器化（分区/离线/时钟混乱/崩溃恢复全套）

## M2 关门 KPI（执行方案 §6.3）

- 三端空间同步 + **断网 24h 重连收敛**（混沌床自动验证）；
- P6/P7/P8 全绿；外部密码学审计通过；
- 端到端基准：10⁵ 文件差异同步收敛 <5min（LAN）。

## 非目标

hub 集群（M3）；EC/分层（M3）；移动端壳（M6）；冲突的自动 merge 函数（v1 保留两者）。

## 风险

- iroh 0.x→1.x API 漂移（ADR-0005 同类风险；锁版本 + 隔离层）；
- E2EE 与检索的张力（加密空间端侧检索，性能取舍明码标价——调研方案 §5.11）；
- 同步核是全项目正确性风险最高点（P6 不变量的实现复杂度）——WP01 单独成批、
  测试先行、混沌床前置。

## 裁定总览

### 1. 索引写入：管线完成后异步索引

WP01 五阶段完成后，通过**事件通知**触发索引写入（非轮询）：

```
SidecarStore::mark_done(embed stage)
  → 发布 ContentIndexed 事件（in-process channel 或 graph jobs 扩展）
  → IndexWriter::upsert(content_id) 异步消费
  → 读取 sidecar_items OCR/transcribe/embed 产物
  → 写入 tantivy 索引（BM25 多字段） + usearch（向量）
```

索引写入与管线执行**完全解耦**：管线不依赖索引，索引可独立重建（re-index from sidecar_items）。

### 2. tantivy BM25 索引设计

**索引字段**（多字段 BM25，SPEC M4-WP01 裁定 2 沿用）：

| 字段 | 来源 | 分词 |
|------|------|------|
| `filename` | `entries.name` | text（文件名标准分词） |
| `tags` | `tags.name` JOIN | keyword_array |
| `ocr_text` | `sidecar_items.stage=ocr, detail` | text_stemmed（降噪 OCR） |
| `transcript_text` | `sidecar_items.stage=transcribe, detail` | text_stemmed（语音转写） |

**schema**：`content_id`（主键）+ 四字段 + `updated_ns`（增量更新用）。

### 3. usearch 向量索引设计

**向量来源**：
- 文本稠密向量：`stage=embed, artifact=fs:<id>/embed_text_dense.bin`（BGE-M3 768d）
- 图像稠密向量：`stage=embed, artifact=fs:<id>/embed_image_dense.bin`（CLIP 512d）
- 稀疏向量（可选）：`fs:<id>/embed_text_sparse.bin`（BGE-M3 SPLADE）

**索引策略**：
- 本地：每设备一个 usearch 索引文件（`~/.partisync/vectors.usearch`）
- Hub 级：按内容哈希空间分片（hub 上按 `content_id` 前缀路由到不同分片节点，检索时扇出合并）
- 向量维度在写入时从文件头读取（动态兼容模型版本升级）

### 4. 混合检索融合：BM25 + RRF + bge-reranker 精排

**融合流程**：

```
用户查询
  ├─ BM25 检索 → Top-100 (`filename + tags + ocr_text + transcript_text`)
  ├─ usearch 向量检索 → Top-100（稠密向量，余弦相似度）
  └─ [可选] 稀疏向量检索 → Top-100（SPLADE）

RRF 融合（k=60）：
  score_rrf = Σ 1/(k + rank_bm25) + Σ 1/(k + rank_vector)

Top-20 → bge-reranker 精排（cross-encoder，重排返回 Top-K）
```

**bge-reranker 用途**：对 RRF 融合的粗排结果做语义重排序，显著提升 top results 质量。
bge-reranker 模型走本地推理（fastembed 家族），不调用外部 API。

### 5. 检索 API 设计（MCP asset_search 上游）

```
trait SearchEngine {
    /// 混合检索
    async fn hybrid_search(&self, req: SearchRequest) -> Result<SearchResponse, SearchError>;

    /// 纯全文检索（轻量，供过滤场景）
    async fn bm25_only(&self, req: Bm25Request) -> Result<Bm25Response, SearchError>;

    /// 纯向量检索（图像→图像、文本→文本）
    async fn vector_only(&self, req: VectorRequest) -> Result<VectorResponse, SearchError>;

    /// 增量索引（管线回调）
    async fn upsert(&self, content_id: &str) -> Result<(), IndexError>;

    /// 索引重建（从 sidecar_items 全量重读）
    async fn rebuild_index(&self) -> Result<RebuildReport, IndexError>;
}
```

**SearchRequest**：
```rust
struct SearchRequest {
    query: String,               // 自然语言查询
    filters: SearchFilters,       // content_id / tags / mime_kind / date_range
    limit: u32,                  // default 20, max 100
    vector_kind: VectorKind,     // TextDense | ImageDense | Auto
    include_transcript: bool,    // 是否包含转写文本（关闭可提升速度）
}
```

**SearchResponse**：
```rust
struct SearchResponse {
    hits: Vec<SearchHit>,
    total: u64,                   // 粗排总数（RRF 候选池大小）
    timing_ms: u32,              // 端到端耗时
    cache_ttl_ms: Option<u32>,   // 下次可缓存时间提示
}
```

## 契约

### 1. 索引写入契约

- `upsert(content_id)` 幂等：同 content 重跑，产物更新后重新写入，版本标记 `updated_ns`
- `upsert` 读取 `SidecarStore::items(content_id)` 中的 OCR/transcribe/embed 产物
- embed 向量文件不存在（stage skipped）→ 该字段留空，不阻塞其他字段写入
- 索引写入失败（IO/解析错误）→ 记录错误日志，返回 `IndexError`，管线不感知

### 2. 检索契约

- `hybrid_search` 端到端 p95 <300ms（10⁹ 条目，RRF k=60，Top-20 rerank）
- `bm25_only` 端到端 p99 <100ms（10⁶ 条目，pure BM25）
- 查询结果含 `content_id` + `score` + `highlights`（BM25 snippet）
- 零结果返回空 `hits`，不返回错误

### 3. 索引更新语义

- 管线 stage 完成 → 事件触发 `upsert`（最终一致，不要求立即可查）
- 重建索引 `rebuild_index` → 从 `sidecar_items` 全量读，对 `updated_ns` 无感

- **bge-reranker 模型体积**：cross-encoder 模型体积大（~1GB），feature 门控
  默认关（ADR-0018 须定义 CI fake 行为）；本地推理需 CPU/GPU 资源评估

  执行同一 content 的 upsert——须保证最终一致（原子 upsert + 幂等）
- **迁移**：已有 10⁶ 条目的老用户如何迁移到新索引格式——留作 M4+ 开放项

# SPEC: M0-WP05 —— 作业系统 v1（持久作业 + checkpoint + 恢复）

版本: 1.0 · 状态: 批准 · 关联: properties.md P8/L5、执行方案 §6.1-WP05、SPEC M0-WP04 · 上游: 调研方案 §5.3
负责人: @lead · 批准日期: 2026-09-18

## 动机

10⁶+ 文件的索引是长任务：中断（Ctrl-C/关机/崩溃）后从头重扫在万亿级推算下不可接受
（§4.1）。执行方案 P8：任意时点崩溃 → 重放后一致且不丢已确认进度。作业系统让
「index」成为可恢复的持久作业——本批交付最小闭环：**断点续扫**。

## 契约

### 1. schema v4（只增）

```sql
CREATE TABLE IF NOT EXISTS jobs (
    id         TEXT PRIMARY KEY,   -- ULID
    kind       TEXT NOT NULL,      -- 'index'（v1 唯一 kind）
    status     INTEGER NOT NULL,   -- 0=queued,1=running,2=interrupted,3=completed,4=failed
    root       TEXT NOT NULL,      -- 规范化 fs 根
    checkpoint TEXT,               -- 最后提交的虚拟路径（含 = 划界，续跑跳过 ≤）
    done_files INTEGER NOT NULL DEFAULT 0,
    error      TEXT,
    created_ns INTEGER NOT NULL,
    updated_ns INTEGER NOT NULL
);
```

### 2. 作业 API `partisync-graph::jobs`

```rust
pub struct JobCtx { pub id: String, pub skip_up_to: Option<String>,
                    pub stop_after: Option<u64>, pub done: u64 }
pub async fn create(store, kind, root) -> Result<String>;
pub async fn start/complete/fail/mark_interrupted(store, id, ...) -> Result<()>;
pub async fn get/list(store) -> Result<…>;
impl JobCtx { async fn flush_checkpoint(&self, store, vpath) -> Result<()> }  // 每 200 文件
```

`index_path` 增加可选 `job: Option<&JobCtx>`（第 5 参）：文件级跳过（`vpath ≤ checkpoint`
直接跳过——目录不跳，保证结构完整）、每 200 文件 flush checkpoint、达到 `stop_after`
→ 返回 `Err(severity = Interrupted)`（测试与演练注入点；生产中断由 Ctrl-C 处理器标定）。

### 3. CLI

- `partisync index <root> …`：创建作业 → 运行；**Ctrl-C = 优雅中断**（status=interrupted，
  checkpoint 已持久，打印恢复指引）；完成 → completed；Fatal → failed（带 error）。
- `partisync resume [--job <id>]`：恢复指定（缺省取最新 interrupted）作业，从 checkpoint 续跑。
- `partisync jobs`：列出作业（id/kind/status/进度/checkpoint）。

### 4. 状态序列化偏离声明

执行方案 §6.1 写「状态 MessagePack」；v1 的作业状态就是关系列（无需嵌套序列化），
引入 rmp-serde 属纯开销——**偏离记录于此**；未来 Sidecar/复杂状态需要时另立 ADR。

## 验收标准（可执行）

- [ ] **L5（恢复等价性）**：同一树，「全量直index」与「跑到 N 中断 → resume」
      最终 stats 完全相等（files/bytes/unique/saved 四元组）；
- [ ] 中断返回 `Severity::Interrupted`；作业状态链 queued→running→interrupted→running→completed 落表；
- [ ] checkpoint 语义：resume 后 `done_files` 从续点累计（不是从 0）；跳过段不重复哈希
      （以日志计数断言）；
- [ ] CLI 实测：index 中途 `kill -INT` → jobs 显示 interrupted → resume → completed，
      最终 stats 与全量一致（演示留档）；
- [ ] fmt/clippy/test 全绿。

## 风险与开放问题

- checkpoint 粒度 = 文件级（每 200 文件提交）：最坏重复 ≤200 文件的哈希工作量——可接受；
- SIGKILL 无法优雅中断 → status 停留 running（陈旧）：v1 以 resume 按最新 checkpoint 恢复
  并覆盖状态（陈旧 running 视同 interrupted），WP07 加启动时陈旧作业清扫；
- 与 watch 并发写：SQLite WAL 允许，checkpoint 行级更新冲突面小，v1 接受。

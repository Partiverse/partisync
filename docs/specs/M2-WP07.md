# SPEC: M2-WP07 —— E2EE 端到端加密（空间级密钥层次 + XChaCha20-Poly1305）

版本: 1.0 · 状态: 批准 · 关联: M2-WP00、ADR-0010、调研方案 §5.11、执行方案 §6.3（外部密码学审计 G3 硬门禁） · 上游: M2-WP04（设备身份）
负责人: @lead · 批准日期: 2026-09-19

## 动机

共享域 + 跨设备传输 = 用户资产经互联网暴露。WP07 让用户可选「加密空间」：
助记词派生主密钥 → 派生空间密钥 → 内容加密（XChaCha20-Poly1305）+ 元数据
密钥（独立派生以平衡检索张力）→ 不可信设备预加密接收（sealed envelope）。

**外部密码学审计为 M2 G3 硬门禁**：RustCrypto 栈选型已 ADR-0010 锁定，本 WP
仅交付自测试与文档面；外部审计报告是 M2 关门的最后一道门槛（不属本 WP）。

## 契约

### 1. 密码学栈（ADR-0010 既定；SEC-AUDIT-2026-M2-001 整改后）

- 密钥协商/身份：x25519-dalek 3 / ed25519-dalek 3（已 ADR-0008 引入）
- 内容/MAC：chacha20poly1305（XChaCha20-Poly1305）
- KDF/哈希：blake3 **官方 Key Derivation 模式**（`blake3::derive_key`）——
  整改前自实现两阶段 keyed-hash 已废弃（P1-1）；context 用协议级常量，
  变长输入走 key_material，域分离由引擎层保证
- 助记词→主密钥：argon2（ADR-0010 选型）
- 内存擦除：zeroize（派生密钥输出一律 `Zeroizing` 包裹——P2-4）
- 盐策略：生产空间 master_key 派生必须持 16 字节 CSPRNG 随机盐
  （`space_crypto.kdf_salt` 持久化，P2-3）；space_id 绑定盐仅限测试

### 2. 空间密钥层次

```
master_key  = argon2id(mnemonic, salt=kdf_salt, m=64MiB, t=3, p=1)   // kdf_salt = CSPRNG 16B 持久盐
space_key   = blake3-derive("partisync space-key-v1",   master_key || space_id)
content_key = blake3-derive("partisync content-key-v1", space_key || content_id)  // per-content
meta_key    = blake3-derive("partisync meta-key-v1",    space_key)                // tag/link
```

- 内容密钥：per-content 派生（同一文件重写不重用）→ 不可逆；
- 元数据密钥：per-space 单实例（tag 名/链接路径明文哈希索引——v1 简化）。

### 3. Store API（graph 层）

```rust
/// 登记空间的加密元数据（seed_kek_hash + alg）
pub async fn register_space_crypto(&self, space_id: &str, kek_hash: &str) -> Result<(), PartisyError>;

/// 空间加密状态查询
pub async fn space_crypto(&self, space_id: &str) -> Result<Option<SpaceCryptoRow>, PartisyError>;

/// 加密写入（content 已 hydrate）：content_id 用 content_key 加密 ⇒ ciphertext_hash
/// 入 content 表；v1 简化：content_id 字段存「密文哈希」，content 表外另存
/// ciphertext 表。读路径用 meta_key 解密 content_id 名再回到 content 表。
/// （v1 简化版：encrypt=True 模式下 content_id 字段本身即密文）
```

### 4. 内容加密接口 `partisync-sync::crypto`

```rust
pub fn encrypt_content(key: &[u8; 32], plaintext: &[u8]) -> (Vec<u8>, [u8; 24]); // (ct, nonce)
pub fn decrypt_content(key: &[u8; 32], nonce: &[u8; 24], ciphertext: &[u8]) -> Result<Vec<u8>, PartisyError>;
pub fn derive_space_key(master: &[u8; 32], space_id: &str) -> [u8; 32];
pub fn derive_content_key(space_key: &[u8; 32], content_id: &str) -> [u8; 32];
pub fn derive_meta_key(space_key: &[u8; 32]) -> [u8; 32];
pub fn argon2_master_key(mnemonic: &str, space_id: &str) -> [u8; 32]; // Argon2id(m=64MiB, t=3, p=1)
```

### 5. 不可信设备预加密接收

- 内容加密包 = `nonce(24) || ciphertext || tag(16)`（XChaCha20-Poly1305 自带 tag）；
- 接收方在密钥不可达时返回 sealed envelope 头（nonce + content_id 哈希） →
  接收方上线凭 master_key 解封 → hydrate_entry；
- 共享域 tag/link 元数据密钥独立派生——加密空间端侧检索性能取舍由 §5.11
  既定（v1：tag 名/链接路径明文哈希索引）。

### 6. v1 简化

- argon2 启动开销（M=64MiB）纳入冷启动 KPI（执行方案 §6.3）；
- 暂不实现「撤销单设备」——通过重发全量密钥轮换空间密钥即可；
- 文件树不在加密面（path 明文可见，content_id 加密）——这与 §5.11「tag 名
  明文哈希索引」对齐（性能优先）。

## 验收标准（可执行）

- [ ] 助记词→master→space→content/meta 全链派生确定性（同一输入 ⇒ 同一输出）；
- [ ] encrypt_content + decrypt_content round-trip 等值；
- [ ] nonce 修改触发 decrypt 失败（AEAD 自检）；
- [ ] ciphertext 修改触发 decrypt 失败（Poly1305 自检）；
- [ ] meta_key 与 content_key 互不等（域分离）；
- [ ] argon2_master_key 不再依赖外部 master 输入——给定 mnemonic+space_id ⇒ 同一 key；
- [ ] fmt/clippy/test 全绿；既有 119 测试零回归。

## 非目标

- 内容寻址 CAS 端的加密封装（CAS 存 blake3 密文哈希 vs 明文哈希差异属于
  更大改造，归 M3+ 加密 CAS 工作）；
- 移动端 keychain 集成（M6 范围）；
- 撤销/重配流程——属 WP04 信任设备列表扩展；
- **外部密码学审计**——独立任务，M2 关门依赖项。

## 风险与开放问题

- argon2 m=64MiB 在低端设备可能阻塞冷启动——规格 §风险节明列，KPI 验证后调参；
- XChaCha20-Poly1305 nonce 24 字节随机生成（getrandom）——碰撞概率可忽略；
- 助记词的「凭据」语义——文档告知用户妥善保管（不在设备同步）；
- 审计报告若发现算法不合规——回退到 aws-lc-rs KDF（ADR-0010 已留备选路径）。

## 契约

### 1. HLC（混合逻辑时钟，P5 不变量：严格单调 + 跨设备全序）

```rust
pub struct Hlc { phys_ms: u64, logic: u32, device: u64 }   // Ord 按 (phys, logic, device)
#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub enum HlcError { CounterOverflow }
impl Hlc {
    pub const fn new(device: u64) -> Self;                     // 零点（phys=0, logic=0）
    pub const fn from_wall(device: u64, wall_ms: u64) -> Self; // 以当前墙钟起步
    pub fn tick(&mut self, wall_ms: u64) -> Result<(), HlcError>;   // 本地事件
    pub fn recv(&mut self, wall_ms: u64, remote: Hlc) -> Result<(), HlcError>; // 收到远端事件
    pub const fn phys_ms/logic/device(&self) -> …;             // 提取器
}
```

**语义**（Spacedrive HLC 先例 + Lamport/Mattern 教科书式定义）：
- `tick(w)`：`w > phys` ⇒ `phys=w, logic=0`；否则 `logic+=1`（墙钟回拨时靠逻辑位保序）。
- `recv(w, r)`：`c = max(w, phys, r.phys)`；若 `c` 同时等于两者 phys ⇒ `logic=max(logic,r.logic)+1`；
  仅等于自身 ⇒ `logic+=1`；仅等于远端 ⇒ `logic=r.logic+1`；否则 `c>w 且均不等于`不可能（c 恒为三者最大，至少等于其一）。
- **严格单调**：每次 tick/recv 后 `self` 严格大于操作前的 `self`，且 recv 后严格大于 `remote`。
- **跨设备全序**：`device` 参与排序键 ⇒ 任意两个 Hlc 可比较且相等当且仅当三元组相等（对端必须使用不同 device id——由 oplog 层注册表保证，文档化）。
- **溢出**：同一 phys 毫秒内第 2³² 个事件返回 `CounterOverflow`（不可恢复分类为 Fatal，调用方决定策略）。
- 模块零运行时依赖（纯值类型）。

### 2. 错误分类学

```rust
pub enum Severity { Retryable, Fatal, Interrupted }        // 作业恢复三分类（执行方案 P8/SOP）
pub struct PartisyError { pub severity: Severity, pub source: Option<Box<dyn Error + Send + Sync>> }
pub fn classify_io(kind: std::io::ErrorKind) -> Severity;  // 表驱动
```

`classify_io` 映射表（M0 初版，随实现扩充须改 SPEC）：`TimedOut|ConnectionRefused|ConnectionReset|
ConnectionAborted|NetworkUnreachable|Interrupted|WouldBlock|NotFound ⇒ Retryable`
（NotFound：扫描期对移动/删除目标的良性竞争，重扫即可）；`PermissionDenied|InvalidData|InvalidInput|
Unsupported|StorageFull|WriteZero|OutOfMemory ⇒ Fatal`；其余 `⇒ Fatal`（保守默认）。
`Interrupted` 为**应用层显式中断**（用户暂停/关机信号），不由 io kind 推断。

### 3. ProviderCaps（骨架，P9 的载体）

```rust
#[non_exhaustive] pub struct ProviderCaps {
    pub hash: HashCaps,             // which 支持的校验/哈希
    pub mtime: MtimePrecision,      // None|Seconds|Millis|Micros|Nanos
    pub atomic_rename: bool, pub server_side_copy: bool,
    pub presign_put: bool, pub event_stream: bool, pub multipart: bool,
}
pub struct HashCaps { pub md5: bool, pub sha256: bool, pub crc64nvme: bool, pub blake3: bool }
pub enum MtimePrecision { None, Seconds, Millis, Micros, Nanos }
impl Default for ProviderCaps  // 保守：全 false/None（无能力假设）
pub fn change_detection_needs(caps: &ProviderCaps) -> ChangeDetection // 策略降级纯函数
pub enum ChangeDetection { Checksum, SizeMtime, SizeOnly }
```

`change_detection_needs` 降级序：任何共同哈希 ⇒ `Checksum`；mtime ≥ Seconds ⇒ `SizeMtime`；否则 `SizeOnly`。

## 风险与开放问题

- `recv` 后「严格大于 remote」在某些 HLC 变体中不成立（相等也可接受）；本规格采用严格大于以简化 oplog 去重——若 M2 实现中造成冗余，规格修订需留痕。
- classify_io 的 NotFound→Retryable 映射对「删除不存在的重放」场景恰好正确、对「用户误删路径」会空转重试一次——量级无害，接受。

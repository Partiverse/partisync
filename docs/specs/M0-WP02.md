# SPEC: M0-WP02 —— 元数据存储 v1 与可体验演示面

版本: 1.0 · 状态: 批准 · 关联: ADR-0002、调研方案 §5.3（PartiGraph schema 草案）· 上游: 执行方案 §6.1
负责人: @lead · 批准日期: 2026-09-18

## 动机

PartiGraph 是产品的核心资产（调研方案 §5.3）。本工作包落地 schema v1 与仓储层，
并交付一个网页演示面——让资产图谱、内容去重在本阶段就**可看见、可操作**，
而非等到 M4 的 AI 层才有第一张脸（Spacedrive「架构先于产品」教训的反制）。

## 契约

### 1. Schema v1（SQLite，5 表；迁移 SQL 随 crate 内嵌）

```sql
device(id TEXT PK, name, slug UNIQUE, pubkey NULL, capabilities JSON NULL, last_seen NULL)
volume(id TEXT PK, device_id, fingerprint, is_removable INT, is_cloud INT)
entry(id TEXT PK /*ULID*/, space_id TEXT NOT NULL DEFAULT 'default',
      parent_id NULL REFERENCES entry(id), kind INT /*0=file,1=dir*/,
      name TEXT NOT NULL, path TEXT NOT NULL,      -- v1 反规范化：全路径（演示导航；M0-WP07 评估 CTE 化）
      content_id NULL REFERENCES content(id), size INT NOT NULL DEFAULT 0,
      mtime_ns INT NOT NULL DEFAULT 0, state INT NOT NULL DEFAULT 0 /*0=materialized*/)
entry_closure(ancestor TEXT, descendant TEXT, depth INT, PK(ancestor,descendant))
content(id TEXT PK /*blake3 hex*/, size INT NOT NULL, mime NULL, kind NULL)
索引: entry(parent_id), entry(path) UNIQUE, entry(content_id), entry_closure(descendant)
```

**v1 裁剪**（对调研方案 §5.3 全量草案的显式缩减，各自归属后续工作包）：
无 space 表（单默认空间）；无 provider/chunk（M1/M0-WP03）；无 tag/sidecar（M4）；
无 oplog/scan_journal（M2 同步引擎）。state 暂只 materialized。

### 2. 仓储层 `partisync-graph::store::Store`

```rust
pub struct Store(/* sqlx SqlitePool */);
impl Store {
    pub async fn open(path: &Path) -> Result<Self>;         // 建库 + 迁移（幂等）
    pub async fn seed_device_volume(&self, …);              // 设备/卷一次登记
    pub async fn add_entry(&self, parent: Option<EntryId>, …) -> Result<EntryId>;
        // 维护 entry_closure：SELECT 祖先链 UNION 自身
    pub async fn entry_by_path(&self, path: &str) -> Result<Option<EntryRow>>;
    pub async fn children(&self, parent_path: &str) -> Result<Vec<EntryRow>>;
    pub async fn ancestors_of(&self, path: &str) -> Result<Vec<EntryRow>>; // 面包屑
    pub async fn search(&self, q: &str, limit: u32) -> Result<Vec<EntryRow>>; // name LIKE，默认 LIMIT 200
    pub async fn stats(&self) -> Result<Stats>;
    pub async fn duplicates(&self, limit: u32) -> Result<Vec<DupGroup>>;
}
pub struct Stats { files, dirs, total_bytes, unique_contents, unique_bytes, duplicate_groups, saved_bytes }
// saved_bytes = Σentry.size − Σcontent.size（引用计数式去重口径）
```

### 3. 索引器（最小实现，完整扫描器归 WP04）

`partisync-graph::indexer::index_path(store, root)`：walkdir 递归 → 目录/文件建 entry；
文件计算 blake3（ADR-0001 邻接：内容寻址主哈希）→ `INSERT OR IGNORE content`；
确定顺序（walkdir 默认序 + sort_by_file_name）保证幂等重跑。

### 4. 演示面（提前交付的 WP06 预览）

`partisync-cli` 子命令：
- `partisync index <root> [--db <path>]`：索引目录入库（默认 `./partisync.db`）；
- `partisync ui [--db <path>] [--addr 127.0.0.1:8080]`：axum 服务：
  - `GET /`（单页 HTML，中文界面：统计卡/浏览/搜索/重复内容四视图）
  - `GET /api/stats` · `GET /api/list?path=` · `GET /api/search?q=` ·
    `GET /api/duplicates` · `GET /api/breadcrumb?path=`

### 5. 夹具生成器

`cargo xtask gen-fixture --root <dir> --files N [--dup-rate 0.3]`：
随机树（深度≤5、目录度≤8），文件内容从内容池取样；dup-rate 比例的文件**复用池中已有字节**
（不经哈希，写盘即同字节），供去重演示。

## 验收标准（可执行）

- [ ] Store 集成测试（内存 SQLite）：迁移幂等；add_entry 闭包维护正确；
      **L4 模型对照**：随机树（proptest）上，闭包子树查询 ≡ 朴素递归遍历（properties.md L4）；
- [ ] stats 数学：构造 3 文件其中 2 份同内容 ⇒ saved_bytes == 一份副本字节；
- [ ] duplicates 分组：同内容 N 文件成组、组内路径正确；
- [ ] 索引器幂等：同一目录连跑两次，stats 不变；
- [ ] `gen-fixture --files 300` 可用；索引 300 文件 < 5s；UI 五端点 curl 断言 JSON 结构；
- [ ] fmt/clippy/test 全绿；cargo deny 通过（新依赖批次，ADR-0002）。

## 风险与开放问题

- **钉子清单项**：schema v1 即数据资产起点，迁移纪律自本 SPEC 起（只增不改，
  改列需新迁移版本 + 数据回填脚本）——人工终审重点；
- path 反规范化在大目录的膨胀（每 entry 存全路径）：v1 接受（查询简单、演示优先），
  WP07 用 recursive CTE 对比后决策；
- LIKE 搜索中文/大小写：SQLite LIKE 默认 ASCII 不敏感——中文按精确子串（OK），
  英文大小写不敏感（可接受），FTS5 归 M0-WP07/M4。

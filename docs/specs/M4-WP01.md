## 动机

M4 进入 AI 层。检索（WP02）与 MCP 工具面（WP03）都消费同一批衍生数据：
缩略图、EXIF、OCR 文本、音视频转写、语义嵌入。这些产物统一由 Sidecar
管线在内容摄取后异步计算——**挂 content 不挂 entry**（N 个 Entry 指向
1 个 ContentIdentity，一份内容只算一次 AI，调研方案 §5.7）。

M4 DoD 明确要求「Sidecar 崩溃恢复」：管线必须建立在持久、可重入、
可审计的作业系统上，而非进程内后台任务。

## 现状锚点（诚实标注）

- `partisync-ai` 为**空骨架 crate**（lib.rs 仅模块注释，M-1 bootstrap）；
- **持久作业系统 v1 已存在**（M0-WP05，`partisync-graph/src/jobs.rs`，
  SQLite `jobs` 表）：status/checkpoint/done_files + Interrupted 状态 +
  「resume 与全量直 index 等价」L5 钉子；但为 index 作业**专用**
  （kind 单一、checkpoint 粒度 = 批、状态即关系列——v1 状态偏离声明）；
- `content` 表已有（content_id 去重锚点，entry.content_id 外键）；
- sidecar 存储、管线阶段、模型管理、调度接线**全部空白**；
- `partisync-index` 为空骨架（注释预留 sidecar 调度），检索引擎归 WP02。

## 裁定总览（待 G0 批准的关键决策）

1. **作业系统 v2 = 扩展而非重写**：沿 jobs v1 的关系列口径（不引入
   MessagePack——与 v1 状态偏离声明一致），新增 sidecar 作业 kind 与
   **per-content per-stage 状态行**（`sidecar_items`：content_id × stage
   → pending/running/done/skipped/failed + 产物引用）；作业级 checkpoint
   语义 = 「stage 粒度可重入」，每个 stage 幂等；
2. **Sidecar 挂 content**：以 content_id 为粒度存产物（缩略图 blob 落
   CAS/文件区、EXIF/OCR/转写为文本列、嵌入为向量文件引用 + 维度/模型
   版本元数据）；同 content 重复入队 = no-op；
3. **阶段管线（固定次序，阶段间解耦）**：
   stage1 缩略图+EXIF（纯 Rust）→ stage2 OCR（ort，图像）→
   stage3 转写（whisper-rs，音视频）→ stage4 嵌入（fastembed：BGE-M3
   文本 + CLIP 图像）。C2PA 归 WP05，本 WP 不含；
4. **依赖进场走 ADR**：ort / fastembed / whisper-rs / tokenizers 及
   缩略图/EXIF 纯 Rust 库（image、kamadak-exif 候选）→ **ADR-0017**
   （推理栈与图像栈依赖批次，一次 ADR 覆盖一批无聊依赖）+ cargo deny
   全绿（铁律 8）；workspace `forbid(unsafe)` 不受依赖内部 unsafe 影响，
   进场时核查我方代码无 unsafe 渗出；
5. **模型管理 = 清单钉版 + 本地缓存 + 缺失降级**：模型文件以
   （名称，版本，blake3，来源）清单钉住，落本地缓存目录；**缺失时该
   stage 标 skipped、管线继续**（不阻塞其他阶段，状态可查询）；
   真实模型下载/推理只在手动冒烟与夜间跑，**CI 一律离线**（fake 模型
   钉行为契约）；
6. **隐私与 E2EE 张力**：一切推理本地执行，无网络调用；E2EE 空间的
   sidecar 是否落密文/明文标注（调研方案 §5.11）在 T02 设计裁定并在
   本 SPEC 修订记录；
7. **调度接线**：watch/scan_journal 发现新 content → sidecar 作业入队
   （content 粒度去重）；并发上限可配；CLI `job` 子命令扩展
   （status/retry/cancel，含 sidecar kind）；
8. **崩溃恢复沿 L5 钉法**：kill -9 任意点 → 重启 resume → 最终 stats
   与全量直算**完全等价**（M0-WP05 恢复等价性先例）。

## 契约

### 1. 作业生命周期

`scan_journal(content_new)` → `enqueue(sidecar, content_id)` →
调度器 claim → 逐 stage：`sidecar_items` 行置 running → stage 执行 →
产物落 SidecarStore + 行置 done → 下一 stage；任一 stage failed/skipped
→ 记录原因，作业终态 = 部分完成（可 retry 单 stage）。

### 2. Stage trait（依赖隔离）

```
trait SidecarStage {
    fn stage(&self) -> StageId;
    fn applicable(&self, mime: MimeKind) -> bool;
    async fn run(&self, input: StageInput) -> Result<StageOutput, StageError>;
}
```

ort/whisper/fastembed 类型**只在 stages 内部可见，不穿透 trait 边界**
（学 ADR-0015 裁定 1）；`partisync-ai` 对外只暴露 trait、SidecarStore
与 JobSystem v2 门面。stage 幂等：同 content 重跑产物确定、不重复入队。

### 3. SidecarStore

content 粒度读/写产物 + 状态行；供 WP02 检索（嵌入/OCR/转写文本）与
MCP 面（WP03）消费，本 WP 只定存储契约与查询接口。

## 验收标准（可执行，测试先行）

- [ ] **崩溃恢复**：管线执行中随机点 kill（进程级模拟）× N 轮 → 重启
      resume 完成，最终 stats 与全量直算等价；无孤儿 Running、无重复产物；
- [ ] **content 去重**：N entry → 同 content → sidecar 每阶段恰执行一次
      （执行计数器钉住）；
- [ ] **阶段幂等**：同 content 重跑同 stage 产物字节级稳定，不产生
      第二份入队；
- [ ] **各阶段行为契约**（fake 模型，CI 离线）：缩略图（JPEG/PNG →
      目标尺寸约束）、EXIF 抽取字段集、OCR/转写/嵌入的输入输出契约与
      skipped/failed 语义；
- [ ] **模型缺失降级**：无模型文件 → 该 stage skipped + 原因可查，后续
      stage 照常完成；
- [ ] **调度接线**：scan_journal 事件 → 自动入队 → 管线跑完 → CLI
      job status 可见全链状态；
- [ ] **回归**：fmt/clippy/test 全绿；cargo deny 通过（ADR-0017 批次
      进场复核）；覆盖率只升不降。

## 风险与开放问题

- **编译与体积**：ort/whisper-rs 引入 C++/cmake 构建链与数百 MB 级
  模型/二进制——T02 ADR 须给出 feature 门控方案（默认关，显式开启），
  避免 workspace 全员背负；
- **CI 离线**：模型下载走 HuggingFace，CI 一律 fake 模型（裁定 5）；
  真实模型冒烟登记为手动验收步骤；
- **E2EE 张力**（裁定 6）：加密空间 sidecar 落盘形态归 T02 裁定，
  必要时修订本 SPEC；
- **API 幻觉风险**：ort/fastembed/whisper-rs 均为新进场 API，按铁律 8
  查证对应版本文档/源码后使用（进场时锁定精确版本）；
- **whisper 依赖 cmake/clang**：构建环境要求登记 ADR-0017；
- 与 WP02 的接口（嵌入格式/维度）在本 WP 定契约，WP02 起草时对账。

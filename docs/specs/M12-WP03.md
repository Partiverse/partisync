## 1. 动机

[P21] 强制验签（M9-WP04）后 `install-demo-ext.sh` 装载必拒：desktop
e2e 环境红灯根因、「扩展装载」体验面不可用（EXT-SIGNING.md:48 示例扩
展签名窗口，M10 债）。CI 子钥已是锚定钥（signature.rs:17-24 任一通过
即有效）——签名补齐不需要任何密钥面/验签语义变更。

## 2. 契约

### 2.1 签名工作流（T02-a）

`.github/workflows/sign-demo-ext.yml`（新，`workflow_dispatch` 手动触
发）：checkout → 安装 minisign（沿 release.yml:178-185 判例）→
`minisign -Sm examples/extensions/demo_ext.wasm -s $RELEASE_SIGNING_CI_KEY`
（trusted comment 格式沿 release.yml:197-199）→ upload-artifact
`demo_ext.wasm.minisig`。**产物经人工下载后以正常 PR 入仓**（带
Task-ID trailer；不用 GITHUB_TOKEN 自动提交——追溯唯一铁律 2）。
私钥仅 GitHub secret 注入，人不经手（ADR-0027 判例不变）。

### 2.2 安装脚本（T02-b）

`scripts/install-demo-ext.sh`：增拷贝 `demo_ext.wasm.minisig`；minisig
缺失时 stderr 显式告警（不静默）并指向 EXT-SIGNING「示例扩展签名窗
口」节。

### 2.3 e2e 三态守卫（T02-c）

`crates/partisync-desktop/tests/commands.rs` `mcp_call_real_sidecar_ext_list`
守卫：无安装 → skip（现状）；有装无签 → **skip-with-reason**（stderr
说明「demo 扩展缺 .minisig，验签拒载属预期」，消除装了必红的环境耦
合）；有装有签 → 真实断言 `ext_demo_echo` 可列（e2e 从「跳过假绿」
升格为「真装载链验证」）。

### 2.4 防漂移校验（T02-d）

sign-demo-ext.yml 增校验步：对已入仓 `.minisig` 用 CI 子钥公钥
（signature.rs:22 base64 行原样）执行 `minisign -V`——wasm 变更后签
名漂移在该工作流下次运行时显式失败。

## 3. 验收标准（可执行）

- [ ] `.minisig` 入仓且 `minisign -V`（CI 子钥公钥）对仓内 wasm 验证通过（命令输出归档 docs/reviews/）；
- [ ] `install-demo-ext.sh` 执行后 `~/.partisync/extensions/` 四件齐（wasm/json/minisig），真 sidecar 面 `ext_list` 列出 `ext_demo_echo`（CLI/partisd 面实录归档，沿桌面端验收规则 2026-10-09 修订：验证走 CLI/守护进程/MCP）；
- [ ] e2e 三态行为正确：无安装 skip / 有装无签 skip-with-reason（stderr 文案在案）/ 有装有签断言通过（`cargo test -p partisync-desktop --test commands` 绿）；
- [ ] 零 `ANCHOR_PUBKEYS` 变更、零 `partisync-ext-host` 代码变更、零新依赖（git diff 实证）；
- [ ] EXT-SIGNING「示例扩展签名窗口」节回填闭合注记（M10 债清账）；
- [ ] 三门禁绿（fmt/clippy/test）。

M10-roadmap-proposal §6-NB2 / M9-WP03 §2.2（面板契约底座）

## 1. 动机

记忆浏览面板（M9-WP03-T02 交付，PR #138/#139）打通了
memory_search/write/verify 三工具透传与承诺验证徽章，但列表交互停留
在最小可用：**内容列一律 90 字截断**（`app-core-v3.js:625`），metadata
字段返回了却完全不展示，memory_id 不在任何可见位置（只在 DOM
data-* 属性里）；**列表顺序完全由服务端固定**（FTS 路径 score DESC →
created_ns DESC，LIKE 路径 created_ns DESC，`store.rs:2286-2320`——
无任何排序参数），前端也没有次级整理手段；**tags 只能精确输入过滤**
（`mem-tag` 输入框），看不到当前数据里有什么 tag 可选；**时间列只有
绝对本地时间**（`timeFmt`，`app-core-v3.js:43-48`），扫一眼分不清
「刚写入」和「上周」。更有一笔登记债：**记忆检索 form 的整页重载
bug**——`index.html:88` inline `onsubmit="return false"` 被 CSP
`script-src 'self'`（`tauri.conf.json:25`）拦成死代码，[检索] 按钮
`type=submit`（`index.html:91`）+ `mem-q` Enter 无 preventDefault
（`app-core-v3.js:742`）都会触发 form 默认提交 = 整页刷回 browse tab；
这与 M10-WP01-T04 在检索 tab 实测确认的 bug 同型（回归锁
`t04_search_form_never_reloads_page`，`ui_hardening.rs:405-406` 明文
登记「记忆面板同名 form 模式为既有遗留，不在本卡范围」——本 WP T01
清偿）。

不做本 WP：记忆面板是 α 主线核心资产（可验证记忆层）的唯一用户面，
M10-WP04 编辑/删除（tombstone）落地前面板交互就是全部体验；列表
不可整理、内容不可见全貌、id 不可复制（MCP 工具联调只能开 DevTools
抄 data 属性）直接抵消 M10「GUI 功能加速」主线。

## 2. 契约

**横切（全程生效）**：本 WP **零新增/零修改 IPC command、零引擎与
gateway 改动**——全部在桌面壳前端层（JS/HTML/CSS）+ Rust 静态契约
探针；`memory_search` 服务端契约（`store.rs:2286` 签名与 ORDER BY）
一字不动。footer「IPC 12 commands」计数不变。

### 2.1 T01：记忆 form 防重载 + 表头客户端排序

- **防重载（清偿登记债）**：摘除 `index.html:88` 死 inline
  `onsubmit`；`btn-mem-search` `type=submit` → `type=button`；JS 侧
  `mem-q` Enter keydown preventDefault + form submit 兜底
  preventDefault（沿检索 tab T04 判例，`app-core-v3.js:731-732`）。
  **回归锁**：`t04_search_form_never_reloads_page` 同款断言扩到记忆
  form（零 inline onsubmit / 零 type=submit / Enter preventDefault /
  submit 兜底）。
- **表头排序（客户端）**：结果表可排序列 = 创建时间 / score / tags /
  来源设备（内容列除外——截断展示排序意义弱）；点击表头按当前已渲染
  行集排序，再点反序，第三点回默认（服务端序）；表头箭头指示当前
  排序键与方向；新检索 / 换 query / 换 tag 后排序态重置为默认（沿
  T04 chips「换查询重置选中态」判例）。tags 列排序键 = `memTags()`
  解析后的逗号列表字典序（非 canonical JSON 原串）。
- **诚实边界**：只排序当前渲染窗口（≤50 条，`limit:50, offset:0`
  契约不变）；meta 行「N / total」既有透出已明示窗口语义。服务端
  排序参数 = gateway MCP 公共工具面变更，非目标（§4）。

### 2.2 T02：详情联动展开 + 复制

- **行展开详情**：点击记忆行（既有「验证」按钮除外，stopPropagation）
  展开 `tr.mem-detail` 行（沿 `.mem-proof` 展开行判例，
  `app-core-v3.js:654-662` / `styles-v3.css:367-369`）：完整 content
  （不截断）、tags 完整列表、metadata pretty-print JSON（esc 后）、
  **完整 memory_id**、created_ns 完整本地时间、score 及**口径注记**
  （FTS 路径 = 匹配秩 / LIKE·精确路径恒 1.0，`store.rs:2279-2282`
  docstring 语义诚实透出）。再点行收起；**展开/收起不得关闭既有
  证明行、不得清空列表**（硬约束，沿 M10-WP01 §2.3「不清空结果」
  判例）；多行详情并存允许，证明行单开语义维持不变。
- **复制**：详情行内「复制内容」「复制 ID」按钮 →
  `navigator.clipboard.writeText`（webview 内建 API，零新增依赖）；
  成功反馈 = 按钮文案瞬时变化（「已复制」→ 1.5s 回落）。剪贴板
  API 不可用时回落方案实现期定（§6-R1），GUI 实操必测复制成功。
- **转义不变量**：详情行模板（content/metadata/tags 全部动态段）
  esc() 全覆盖——模板中不得出现未转义插值（沿 M9-WP03 §2.1 esc
  契约与 M10-WP01 §2.2 不变量句式）。

### 2.3 T03：时间展示深化 + tag 过滤 chips

- **相对时间**：创建时间列改相对显示（「刚刚 / n 分钟前 / n 小时前 /
  n 天前」），**>30 天回落绝对日期**；title 悬浮 = 完整本地时间
  （`timeFmt` 既有输出不回退）；`created_ns` 缺失/0 → 既有「—」回落。
- **tag 过滤 chips**：结果渲染后从当前已渲染行集派生 tag 集合
  （`memTags()` 解析），渲染 chips 行（复用 `.chips/.chip` 既有样式，
  `styles-v3.css:150-159`）；点击 chip 客户端过滤已渲染行（不重发
  查询、不触后端），meta 行同步「显示 n / 共 m」；全不选 = 不过滤；
  新检索后 chips 重置并重派生（T04 判例）。与 T01 排序正交可叠加
  （先过滤后排序，或等价组合——实现期定，验收只锁组合结果正确）。
- **诚实边界**：tags 是记忆数据真实存在的维度（与资产索引 tags 恒空
  不同，`M10-WP01 §2.4` 对比登记），但 chips 只反映当前 50 条窗口内
  的 tag——不做服务端 tag 聚合查询（`memory_search` 无聚合面）。

### 2.4 验收方式（沿 M8-WP05/M9-WP03/M10-WP01 判例，硬性）

- Rust 静态契约探针（`ui_hardening.rs` include_str 断言判例）锁每项
  接线与不变量；payload 形状零变更，`commands.rs` 既有 e2e
  （`t02_memory_panel_dataflow_via_stub_sidecar`）不回归即可，不新增
  e2e（纯客户端面无 payload 可对账；如实现期需要，增补登记修订版）；
- **真实 GUI 实操截图**（AGENTS.md 桌面端硬性规则）：每任务随 PR 归档
  `docs/screenshots/M10-WP02-T0n-*.png`（T01 排序前后 + Enter 检索
  不重载 / T02 详情展开 + 复制粘贴验证 / T03 chips 过滤前后 + 相对
  时间 tooltip）；环境不可得时 PR 保持 OPEN 打 label「待 GUI 验证」，
  不得合入；
- property registry 无 UI/面板条目（P1–P20 均引擎/同步/承诺域，
  P20 为记忆承诺引擎面）——**不新设 P 编号，以测试自身为契约**（沿
  M9-WP03 §3 判例）。

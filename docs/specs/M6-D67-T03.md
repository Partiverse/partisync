## 动机

M6-D67 SPEC §D7 要求 BM25-only / hybrid_no_rerank / hybrid_with_rerank
**三档对比**， T02 已落档 bm25_only 档（LCSTS 真档 Recall@10=0.95）； 本
SPEC 落地 hybrid_no_rerank 档， 提供「BM25 + 向量 RRF 融合」档位的真档
数字。 hybrid_with_rerank 档（T04）涉及 fastembed `Rerank` 模型 ~700MB
权重下载 + 推理时延 +100ms/query， 不在 M6 优先级； 待 T03 真档数字证明
hybrid 提升量级后再决策 T04 必要性。

前置资产（均已就绪）：
- `HybridSearch`（RRF k=60 融合）+ `IndexEngine` + `VectorStore` 全栈
- fastembed TextEmbedding `BGESmallZHV15`（512d）模型权重 hf-mirror 可达
- M6-D67-T02 LCSTS 真档 200doc/40query subset + `prepare-lcsts.py` 抽出器

## 契约

### 1. 新增 `EvalRunner::run_hybrid_no_rerank` 方法

签名：
```rust
pub async fn run_hybrid_no_rerank(
    &self,
    bm25_index_path: impl AsRef<Path>,
    vector_index_path: impl AsRef<Path>,
    embed_cache_dir: impl AsRef<Path>,
) -> Result<MetricReport, PartisyError>
```

三阶段：

```
1) load_corpus + Bm25Index::upsert_batch + bm25.commit + bm25.reload
2) EmbedStage-init (BGESmallZHV15) + corpus_texts → Vec<Vec<f32>> + VectorStore::upsert_batch
3) for each query: embed(query_text) → HybridSearch::search_with_vector → PerQueryMetrics
```

返回 `MetricReport.mode = "hybrid_no_rerank"`， 其余字段同 bm25_only。

### 2. `examples/eval_real.rs` 模式分发扩展

```
"bm25_only"          → EvalRunner::run_bm25_only        (T02)
"hybrid_no_rerank"   → EvalRunner::run_hybrid_no_rerank  (T03, 新增)
"hybrid_with_rerank" → 仍报错「T04 待实装」
```

CLI：`scripts/eval-real.sh` 已支持 `EVAL_MODE=hybrid_no_rerank`（env 已在
line 25 默认值 bm25_only， 加 `--features index-embed` 由 line 79-83 触发）。

### 3. 行为契约

- `run_hybrid_no_rerank` 走 fastembed， 需要 feature `index-embed` ；
  feature 关闭时编译期不存在该方法
- 评估时间预期： 200 doc embed ≈ 5s + 40 query embed ≈ 1s + 40 hybrid search
  ≈ <1s = 总 < 10s（实测与 SPEC 预期一致）
- `MetricReport.mode` 字段值严格 `bm25_only` / `hybrid_no_rerank` /
  `hybrid_with_rerank`， 大小写敏感

### 4. feature gate

- `partisync-index/Cargo.toml`：`index-embed` feature 改为默认**开**
  （SPEC M4-WP02 ADR-0018 已确认 fastembed 编译时间可接受）； 若 CI
  编译时间超阈值再回退默认关
- `examples/eval_real.rs` 在 hybrid_no_rerank 模式下加 `--features
  index-embed`

### 5. `VectorKind` 维度约束

- 现有 `VectorKind::TextDense` = 768d (legacy 占位值， 与 `m5_wp05/07` 测试集
  768d synthetic 向量对齐， 无生产模型对应)
- 新增 `VectorKind::TextDenseZh512` = 512d Cos (匹配 `BGESmallZHV15`)
- `VectorStore` 新增 `text_dense_zh512` 子索引字段， 与现有 `text_dense`/
  `image_dense` 并列； open_or_create / clear / approx_count / lock_for_*
  / search / upsert 全方法扩 match 分支
- 落档时**不动** 768d 路径， 避免 m5 回归测试改 fixture

### 6. CLI 入口契约

`examples/eval_real.rs` 当前 `--mode` 仅识别 `bm25_only`； 本 SPEC
扩展为：

```
--mode bm25_only          → EvalRunner::run_bm25_only        (T02 已实装)
--mode hybrid_no_rerank   → EvalRunner::run_hybrid_no_rerank  (本 SPEC 新增)
--mode hybrid_with_rerank → 仍报错「T04 待实装」
```

## 非目标

- 不实装 `hybrid_with_rerank` 档（属 M6-D67-T04）
- 不引入新 embedding 模型（BGE-M3 / multilingual-e5 等保留后续）
- 不改 `HybridSearch::search_with_vector` 现有签名（已有签名足够）
- 不动 `VectorKind` 矩阵或 usearch metric（BGE-small-zh 用余弦/内积已有）
- 不为 EvalRunner 单独抽 `Embedder` trait（fastembed 单一后端足够）

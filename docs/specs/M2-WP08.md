# SPEC: M2-WP08 —— 版本回收（trash-can / staggered 版本化）

版本: 1.0 · 状态: 批准 · 关联: M2-WP00、M2-WP06、调研方案 §5.7、properties.md P12
负责人: @lead · 批准日期: 2026-09-19

## 动机

P12「数据可恢复」：用户的「删除」操作应是 trash（可恢复期），而不是物理删除。
WP08 提供两类回收：
1. **trash-can**：用户显式删除的 entry 在 N 天保留期内可恢复（resurrect）；
2. **staggered 版本化**：对覆盖写（同一 path 不同 content_id）保留最近 K 版，
   满足「我改了又改，能回到中间态」需求。

## 契约

### 1. schema v10（只增）

```sql
CREATE TABLE IF NOT EXISTS entry_version (
    id          TEXT PRIMARY KEY,  -- 版本 ULID
    path        TEXT NOT NULL,
    content_id  TEXT,              -- 被取代的 content_id
    size        INTEGER NOT NULL,
    mtime_ns    INTEGER NOT NULL,
    owner_device TEXT,
    state       INTEGER NOT NULL DEFAULT 0,  -- 0=staggered-versioned, 1=trashed
    retired_at_ns INTEGER NOT NULL,
    expires_at_ns INTEGER NOT NULL  -- 超过此时间物理清理
);
CREATE INDEX IF NOT EXISTS idx_version_path ON entry_version(path);
CREATE INDEX IF NOT EXISTS idx_version_expires ON entry_version(expires_at_ns);
```

### 2. Store API

```rust
/// 退役条目（写新行覆盖前自动调用：保留旧版 staggered-versioned）
pub async fn retire_for_overwrite(&self, path: &str) -> Result<(), PartisyError>;

/// trash 条目（用户显式删除）：置 state=1 + 填 expires_at_ns
pub async fn trash_entry(&self, path: &str, ttl_ns: i64) -> Result<(), PartisyError>;

/// resurrect：trashed 行重新挂回 entry 表（path 须当前空缺）
pub async fn resurrect(&self, path: &str) -> Result<String, PartisyError>;

/// 列版本（含 staggered + trashed）——按 retired_at_ns DESC
pub async fn list_versions(&self, path: &str) -> Result<Vec<EntryRow>>;

/// 物理清理：删除 expires_at_ns < now 的行
pub async fn gc_expired(&self) -> Result<u64, PartisyError>;
```

### 3. 同步语义

- staggered 版本行不进入 sync_oplog（属本地历史，多端各自保留）；
- trash/resurrect 通过 oplog 广播：`device="trash"` 实体 / `device="log"` entity_id=path。
- WP06 的 pin 优先级：trashed 不直接物理删（用户可恢复）；gc_expired 由定时器或
  CLI 调用触发，pin_count > 0 的条目延迟清理（GC 跳过）。

### 4. 默认参数

- staggered 默认 K=5（每 path 最多保留 5 版，超出按 retired_at_ns 删旧）；
- trashed 默认 TTL 30 天（30×24×3600×10⁹ ns）；
- GC 触发：CLI `partisync gc` + 启动时一次性扫描；
- stagger 阈值与 TTL 写入 `sync_config(key TEXT PK, value TEXT)` 表——CLI 可覆盖。

## 验收标准（可执行）

- [ ] 覆盖写：同一 path 写 7 次 → `list_versions` 仅返回最近 5 版；
- [ ] trash + resurrect：trashed 行 resurrect 后 entry 表可见、版本表保留；
- [ ] GC：`gc_expired(now + ttl)` 删除 expires_at_ns < now 的版本行；
- [ ] pin 防回收：pin_count > 0 的 trashed 行 GC 跳过；
- [ ] 跨节点 trash 同步：a trash `/x` → push → b 同样 trash（oplog 路径已含 entity=entry op=remove——兼容）；
- [ ] 回归：P6/P11/P7/P9 全绿；fmt/clippy/test 全绿。

## 非目标

- 分级存储（cold archive）——属 M3 EC/分层；
- 增量 diff 历史（rsync --backup 风格 byte-level diff）——调研方案 §5.7
  「目录级策略」提及，v1 不做；
- GUI 回收站 UI——M6 范围。

## 风险与开放问题

- 物理清理的不可逆性：trash TTL 必须明示（CLI 显示），用户可见默认 30 天；
- staggered K=5 + 历史大文件 = 5×容量峰值——调度 GC 频次与触发点（启动扫描
  + 每周一次后台）由后续 M3 决定，v1 仅暴露 CLI 入口。

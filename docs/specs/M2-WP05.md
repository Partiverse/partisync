# SPEC: M2-WP05 —— 块级传输：iroh-blobs 验证流 + 泛化 delta 协议

版本: 1.0 · 状态: 批准 · 关联: M2-WP00、ADR-0009、调研方案 §5.8（泛化 delta + BEP+casync 合体） · 上游: M2-WP04（设备网络）
负责人: @lead · 批准日期: 2026-09-19

## 动机

WP01–03 是元数据级同步（oplog + Merkle 状态对账），不搬运内容字节本身。
WP05 把内容块的"对端差异→搬运"协议落地：iroh-blobs（BLAKE3 验证流）+
泛化 delta（接收方先送"我有的块哈希清单"，发送方按缺失块清单流式推送）。
v1 不引入网络传输层（iroh transport 由 WP04 IrohTransport trait 占位），
重点是 ChunkPlan 计算与已有 transfer executor 的接入面。

## 契约

### 1. 内容块定义（沿用 ADR-0004 fastcdc）

- 块哈希 = blake3 hex（partisync-cas::content_hash 复用）
- ChunkPlan：源端 (`from`) 与目标端 (`to`) 各持一份 chunk 哈希清单，差分得：
  - `have_to_have`（两侧都有 ⇒ 跳过）
  - `need_to_have`（目标缺 ⇒ 推送）
  - `extra_to_have`（目标多余 ⇒ 视策略：保留或回收——v1 保留）

### 2. Store API（graph 层）

```rust
/// 条目的内容块清单根（chunk_root）。
/// v1：chunk_root 已有字段存储的是 hex 字符串；本 WP 增加按 content_id
/// 反查所有引用该内容的所有 entry 行持有的块清单——若均一致则跳过搬运
pub async fn entry_chunk_root(&self, path: &str) -> Result<Option<String>, PartisyError>;

/// 条目的本地块集合：来自 CAS 已存内容 + fastcdc 切分（lazy：在 sync 路径上
/// 仅取 chunk_root，避免本地重切）。v1 简化：chunk_root 即「源端块清单的根哈希」，
/// 对账协议 P7 的"状态叶"已在 WP03 包含 chunk_root——本 WP 不重算。
```

### 3. 协议层 `partisync-transfer::chunk_plan`

新增 `crates/partisync-transfer/src/chunk_plan.rs`：

```rust
/// 一条块在 ChunkPlan 中的角色。
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ChunkRole { Need, Have, Extra }

/// 块清单根 + 块哈希列表 → ChunkPlan（差分两个清单）。
pub fn plan_chunks(
    from: (&str, &[String]),  // (chunk_root, block_hashes)
    to:   (&str, &[String]),
) -> ChunkPlan;

/// 路由到具体执行器：
/// - need 块 → IrohBlobsExecutor（v1 落地为「列出待传输块」+「回调式推送」骨架，
///   网络传输留给 IrohTransport 实现）
/// - 缺 chunk_root 的 entry → 退化为整文件传送（小文件占 99%）
pub async fn execute_plan<F>(&plan: &ChunkPlan, mut sender: F) -> Result<PlanStats>
where F: FnMut(&[u8]) -> Result<(), PartisyError>;
```

### 4. 集成点

- WP03 reconcile 慢路径发现 entry 状态不等 → 计算两侧 chunk_root → 若不同
  调 ChunkPlan → 把 need 块入队 → IrohBlobsExecutor 推送 → 调用方
  `Store::hydrate_entry(path, content_id, size)` 完成 hydrate（WP06 接口）；
- WP06 placeholder 行 hydrate 由本 WP 触发——而非由 sync.rs push 路径触发，
  避免 push 路径复杂化。

### 5. v1 简化

- 不引入 iroh 网络（依赖 `iroh-blobs 1.x` 同 minor 但 transport 由 WP04 占位）——
  本 WP 仅交付 ChunkPlan 计算与 executor 骨架；
- chunk_root 不重算——直接复用 entry.chunk_root 字段（已有或 NULL）；
- 块清单本身需要由 transfer / provider 层计算（fastcdc 切块 + blake3 哈希）——
  v1 仅在 `content_hash` 函数层面已有；块清单落地作为后续工作（CAS 抽象）。

## 验收标准（可执行）

## 非目标

- iroh-blobs 实际网络传输（WP04 IrohTransport trait 占位；本 WP 通过
  executor 抽象面与回调式 sender 解耦）；
- CAS 块清单的 fastcdc 切分（属 transfer crate 现有 executor 范畴，非 WP05）；
- 大文件断点续传协议层（v1 同会话内一次性传输）；
- 自适应 BDP/令牌桶（scheduler 范畴，M3+ 工作）。

## 风险与开放问题

- CAS 块清单与 entry.chunk_root 在 v1 尚未一一对应（chunk_root 多为 NULL）——
  ChunkPlan 退化路径覆盖；
- 后续 iroh-blobs 接入时 `execute_plan` 的 `sender` 回调就是 iroh blob stream
  的包装；本 WP 抽象面足够（已基于 `FnMut(&[u8]) -> Result`）。

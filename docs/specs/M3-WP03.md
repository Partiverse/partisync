# SPEC: M3-WP03 —— hub 对账服务：空间注册表、角色与设备↔hub Merkle 对账

版本: 1.0 · 状态: **批准（G0）** · 关联: M3-WP02（复制面，已关门）、
M2-WP03（Merkle 对账协议）、M2-WP07（KDF/盐，D2）、ADR-0008/0009/0010 ·
上游: M3-WP02 RFC §8 移交项、M2-report 债务表 D2/D3
负责人: @lead · 批准日期: 2026-09-21（用户指令「批准」视同 G0 通过）

## 动机

M3-WP02 交付了复制与一致（raft 组、线性一致读、failover <10s 实测），
但 Hub 公共门面仍为 WP01 直连单机语义（RFC §8 移交项），复制语义未在
Hub API 上可达。本 WP 三件事：

1. **Hub 门面接线 raft**（SPEC M3-WP02 契约 2 兑现）：读写走线性一致
   复制面，entry/children 成为 raft 状态机 section（裁定 7 兑现）；
2. **hub 对账服务**（M3 主计划 WP03 正主）：设备↔hub Merkle 对账复用
   M2-WP03 协议（分级桶下钻 + 水位快路径 + P11 冲突血缘），承载于
   hub 的 raft 状态机上；
3. **空间注册表与角色**：space → {成员/角色(owner/editor/viewer),
   kdf_salt, 根} 持久化于 raft；空间创建即 D2 盐接线闭环；写路径角色
   强制。

同时清偿 M2 债务 D2（本 WP 内），并裁定 D3（iroh）去向（见裁定 6）。

## 裁定总览（待 G0 批准的关键决策）

1. **Hub 复制语义接线先行**（前置任务）：`Hub::open` 增加
   `NodeConfig`（节点身份/组拓扑，v0.1 单节点组默认）；写 =
   `client_write`（leader），读 = 线性一致（`ensure_linearizable` +
   本机 SM）；entry/children 业务行成为 raft apply 的业务 section
   （M3-WP02 裁定 7 兑现）。**回归线**：WP01 19 测 + WP02 21 测在
   「单节点组拓扑」下原样通过（RFC 验收 1 偏移项兑现）；WP01 直连
   形态测试保留为存档回归。
2. **对账协议复用 + 源抽象**：`sync::reconcile` 泛化——把
   `partisync_graph::Store` 硬依赖抽为 `LeafSource`（叶扫描 + 修复
   sink 两个 trait 面）；设备端继续用 graph Store 实现，hub 端新增
   raft 面适配器（线性一致读扫叶 + 经 raft 的修复写）。协议语义
   （快路径/桶下钻/属主权威/P11 冲突血缘）一字不变；**回归线 =
   M2-WP03 测试原样通过**。
3. **空间归属 = 行级标签（最小侵入）**：v0.1 数据面保持单一全局命名
   空间；space 归属 = 空间根 entry（注册表行持根 id）+ 后代由 parent
   链天然归属（子项不冗余 space 字段，对账/检索按根下钻范围界定）。
   物理隔离/多租户强隔离（L2 联邦形态）归 M5/M6——诚实标注：v0.1
   为逻辑隔离。
4. **空间注册表 = 独立全局 raft 组**（group_id 语义：注册表组与分区
   数据组并存，`pid=0` 保留为注册表组）：注册表行 = `space_id →
   {根 entry_id, 成员表{device_id→role}, kdf_salt, created}`。注册表
   与数据分跨两组 = 跨组无事务（公理 6 口径）：注册表变更（建空间）
   与首个数据写不原子，由「空间根存在性」单调不变量收口。
5. **角色与鉴权**：owner（管成员/删空间）/editor（写）/viewer（只读）
   三级；设备身份 = M2 pairing 的 ed25519 设备密钥；设备↔hub 每请求
   携带签名信封（T04 帧协议扩展，版本字节内升级），hub 验签后按
   注册表角色检查——viewer 写一律拒绝。**鉴权面属 R2 密码学相邻**
   （对抗审查强制）。
6. **D3（iroh 真实网络层）不进本 WP**：设备↔hub 通道复用 T04 TCP 帧
   （版本字节已留位）；iroh 与 WP04 数据面的 iroh-blobs 同依赖族，
   归 WP04 一起进场（单一 ADR 覆盖 iroh + iroh-blobs，cargo deny 一并
   复核）。本 WP 仅保证通道层可替换（帧协议不动，传输可换）。
   M2-report 的 D3 偿还窗口「M3 hub 集群」修订为「M3-WP04」（随本
   SPEC 批准记录）。
7. **分裂×复制 M3-M6 与 10⁶ 复测列入本 WP**：对账修复写是真实的
   「业务写在组拓扑下」场景，M3-M6 failpoint 矩阵随 T07 落测（RFC
   §6 规格态 → 测试态）；10⁶ 修正后复测进 T08 报告。

## 契约

### 1. Hub 门面（SPEC M3-WP02 契约 2 兑现）

- `Hub::open_with(Config)`：Config 含 NodeConfig + 组拓扑（v0.1 单组）；
- 全部读写签名不变；写 = 线性一致（leader commit+apply 后应答），
  读 = 线性一致（leader）；
- 崩溃/切换语义继承 M3-WP02 RFC §5（ACK 不丢；ACK 前崩溃 = 客户端
  超时语义 + 同键 upsert 收敛）。

### 2. 空间注册表（新 raft 组，pid=0）

- 行：`space_id → SpaceRow{ root_entry_id, members: {device_id → role},
  kdf_salt: [u8;16], created_at }`；
- 创建空间 = 原子写注册表行（含 CSPRNG `random_kdf_salt()`，D2）+
  建根 entry（跨组两步，§裁定 4 不变量）；
- 角色检查点：数据写（editor+）、成员管理（owner）、读（全员含
  viewer）；hub 强制，客户端不信任。

### 3. 对账服务

- `sync::reconcile` 泛化后签名形态：
  `reconcile(a: &impl LeafSource, b: &impl LeafSource, opts)`；
- hub 端 `RaftLeafSource`：叶扫描走线性一致读（分页水位快照），修复
  sink 走 `submit`（raft 写）；冲突语义沿用 P11（`.conflict-{owner}` +
  `sync_conflict` 血缘）；
- 设备端会话沿用 M2 pairing 身份；每空间独立对账（space_id 定界）。

### 4. 一致性语义

- 全部继承 M3-WP02 RFC（线性一致写/leader 线性一致读/follower 顺序
  读裁定 F1）；对账收敛判据 = Merkle 根相等（协议内建）。

## 验收标准（可执行，测试先行）

      reconcile → 根相等、修复计数正确、冲突落 `.conflict-{owner}`；

- [ ] **对账吞吐口径**：10⁷ 条目两库差异对账 <5min 初测（M3 DoD 预演，

- **对账泛化动 M2 已审计面**（sync crate）：协议语义不变为回归线
  （M2-WP03 测试原样过）；`Store` trait 抽面上移涉及 graph crate 的

  显式覆盖；

  follower 扫叶的正确性窗口随 M3-M6 矩阵一并用例化；

## 动机

M4 五个能力 WP（WP01–WP05）已全部关账（最近 `569c37f` WP05 验收闭合）。
M4-WP06 是 M4 里程碑的**关门之作**，交付两类制品：

1. **MCP/网关安全评估**——M4 暴露 5 个 MCP 工具（`asset_search` / `asset_read` /
   `asset_organize` / `dataset_export` / `job_status`）和 CLI 入口；
   执行方案 §6.5 / §7.2 明确「M4 前须完成 MCP/网关外部渗透测试」。
   本 WP 完成**内部可执行项**（威胁模型、注入/鉴权/DoS 探针、内部渗透报告）
   + **外部邀请准备**（RFC、范围清单、对接窗口），外部真实执行由用户在 M4
   关账前择期委托。
2. **语义检索质量评估集**——M4-WP02 检索引擎（BM25 + 向量 RRF + reranker）已实现，
   但**质量未在真实语料上量化**；执行方案 §6.5 DoD 明确「10⁶ 条目语义问答 p95
   <200ms」+ 评估报告。本 WP 从既有 INBOX e2e 真实库采样，人工标注 30–50 个
   查询 → ground truth，**离线可复现**地度量 BM25-only / hybrid-no-rerank / hybrid+reranker
   三档的 nDCG@10 / MRR / Recall@10，作为后续优化基线。

## 契约（裁定）

### 裁定 1 · 评估集来源：真实 INBOX e2e 库 + 人工标注

**库来源**：`~/.partisync-inbox-e2e/`（已存在，不重新生成）。
由 WP03 L2 验收时建库，sidecar 五阶段 + C2PA 第六阶段全跑完；唯一真实图片
`20240910-140620.jpeg` 可作 sanity check。

**库采样**：
- 从 2797 unique content 中按 `mime_kind` 分层采样 N=200 作评估语料
  （image/video/audio/document 各层 + 长尾）。
- **种子文件登记**：评估用 200 个 content_id + 相对路径入
  `crates/partisync-index/tests/fixtures/wp06_corpus.tsv`
  （TSV：content_id, mime, source path），git 入库。
- INBOX 私有目录路径入 `.gitignore`（与既有 WP03 L2 e2e 一致）。

**查询集**（`crates/partisync-index/tests/fixtures/wp06_queries.jsonl`）：
- 人工设计 **40 个自然语言查询**（中英混合，覆盖）：
  - 短查询（1–2 词） / 长查询（≥6 词）
  - filename-only 命中 / tag-only 命中 / OCR 文本命中 / 跨字段命中
  - 同义词扩展（命中向量召回优势） / 精确词命中（BM25 优势）
  - 时间/大小过滤型
- 每个查询附 `vector_kind=auto` 默认 + `include_transcript` 默认 + `limit=20`

**Ground truth**（`crates/partisync-index/tests/fixtures/wp06_qrels.jsonl`）：
- 每条 `{ query_id, content_id, relevance }`，relevance ∈ {0, 1, 2, 3}
  （0=不相关、1=弱相关、2=相关、3=高度相关）。
- **标注规则**：双人盲标 + 仲裁（执行方案 §1.2 RACI：AI 起草+人终审）。
  标注口径：能直接回答 query 的=3，部分回答=2，主题相关但非直接=1，无关=0。
- **绝不**把 BM25/hybrid 检索结果反向当 ground truth（防「自评自」假阳性）。

### 裁定 2 · 度量口径

- **指标**：Recall@10 / MRR / nDCG@10
- **三档对比**（每指标各报）：
  - `bm25_only`（纯 BM25，已实装）
  - `hybrid_no_rerank`（BM25 + 向量 RRF，无 reranker——向量用 fake 768d 0..1
    占位，因为无 embedding 模型时向量路径不可用；本档作为**架构基线**，待
    embedding 模型接入后**重新跑**为生产档）
  - `hybrid_with_rerank`（feature `index-rerank` 开启，本机如有模型则跑；
    无模型时本档跳过并登记 P0 开放项）
- **覆盖率**：N=200 语料 / 40 查询；CI 跑全量；KPI 报告固化基线数值。
- **离线可复现**：种子文件 + 脚本入仓；`cargo test --test wp06_eval`
  跑通即出 JSON 报告。

### 裁定 3 · 渗透测试边界

按执行方案 §7.2「M4 前（MCP/网关渗透）」要求，分两阶段：

**A. 内部渗透（本 WP 交付）**

| 探针类 | 目标 | 用例 |
|---|---|---|
| **注入** | MCP 工具输入 | SQL 注入试探（`query`/`content_id`/`operations.value` 字段）；JSON 畸形输入；超长字符串（1 MiB）；Unicode 控制字符；空字符串；null；嵌套过深（>32 层） |
| **鉴权** | 跨空间/跨租户 | content_id 不属于本库时 `asset_read` 必须 tool_err（**不是 200 空对象**）；`asset_organize` 跨租户写必须拒绝；`dataset_export` 仅导出可见 content_ids |
| **DoS** | 资源耗尽 | `asset_search` 100 万次/秒无界迭代；`dataset_export` shard_size=0 + 1M records 内存爆炸防护；并发 100 客户端 MCP 请求 |
| **C2PA 边界** | WP05 校验路径 | 篡改 manifest 后 `asset_read` 返回 state=Invalid 不抛出；超长 manifest（>10 MB）解析不爆栈；缺 `c2pa.actions` 的 manifest 不抛 panic |
| **Sidecar 边界** | WP01 管线 | missing file 不应让整批 fatal（**已知 bug**——LocalContentLoader 幽灵 content 整批 fatal；登记为 P0 开放项另立，不在本 WP 修） |

**B. 外部渗透准备（本 WP 准备，不委托）**

- **威胁模型**：`docs/security/threat-model-mcp-gateway.md`
  （STRIDE：Spoofing / Tampering / Repudiation / Information Disclosure /
  DoS / Elevation of Privilege；按 MCP 工具逐个列攻击面）
- **攻击面清单**：`docs/security/attack-surface.md`
  （stdin/stdout JSON-RPC / DB / index root / sidecar dir / 模型目录）
- **外部渗透 RFC**：`docs/security/pentest-rfc.md`
  （范围、目标资产、排除项、时长、报价模板、合规边界）
- **范围清单**：`docs/security/pentest-scope-checklist.md`
  （可勾选的攻击路径，与内部探针用例一一对应）

**注**：外部真实执行（M4 关账前由用户委托独立 vendor）不在本 WP；本 WP 仅
准备 RFC + 内部可执行探针，作为 M4 关账 G3 检查单 §7.1.10
「外部渗透测试无高危」的**前置准备**。

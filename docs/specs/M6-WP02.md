# SPEC: M6-WP02 —— Task-ID trailer 正则扩展（评估档 D 前缀）

版本: 0.1 · **状态: 草稿（2026-09-26 起草）** · 关联:
ADR-0022（正则扩展决策）、M-1-WP05（追溯基建·commit-msg 钩子）、
M6-D67（首个使用新前缀的评估档任务）
负责人: @lead · 批准人: @lead · 批准日期: YYYY-MM-DD

## 动机

执行方案 §6.5/§7.1 在 M6 阶段引入「评估档」任务概念（D1–D7：审计/
渗透/性能基准/数据集评测等），其 Task-ID 命名约定为
`M{m}-D{nn}-T{nn}`，与既有 WP 任务并存。现有本地钩子
（`scripts/hooks/commit-msg`）与 CI 校验脚本
（`scripts/check-task-ids.sh`）的正则仅覆盖 WP 分支，导致首个 D 档
任务 `M6-D67-T01` 必须以 `git commit --no-verify` 绕过钩子，破坏
铁律 2「追溯唯一」的机械一致性。本 WP 把正则扩展为 WP/D 双分支，让
评估档任务走与 WP 任务同等的合规路径。

## 契约

### 1. 正则字面（落地字面量）

```
^Task-ID: M-?[0-9]+-(WP[0-9]{2}|D[0-9]+)-T[0-9]{2}$
```

`$` 端锚：要求 Task-ID 行末尾严格落在 `T{nn}` 后——一并修复既有正则
子串误接受（如 `M0-WP01-T123` 旧正则会匹配 `T12` 前缀放行）。

接受的两类格式（示例）：

| 类别 | 格式示例 | 说明 |
|------|----------|------|
| WP 任务（既有） | `Task-ID: M0-WP01-T07` | 工作包任务，沿用既有约定 |
| M-1 阶段（既有） | `Task-ID: M-1-WP07-T01` | 引导阶段，允许 `M-` 前缀 |
| D 任务（新） | `Task-ID: M6-D67-T01` | 评估档任务；`D` 后允许多位 |

### 2. 文件改动范围

| 文件 | 改动 |
|------|------|
| `scripts/hooks/commit-msg` | 第 6 行 `pattern` 变量；错误提示文案（行 14）增加 D 示例 |
| `scripts/check-task-ids.sh` | 第 9 行 `pattern` 变量；保持脚本其它部分不变 |
| `scripts/check-task-id-format.sh`（新建） | 单元测试：旧/新格式接受 + 非法格式拒绝（独立可跑，无需 git） |

### 3. 行为契约

- 合并提交豁免不变（`scripts/hooks/commit-msg` 第 8–10 行）
- 正则仍锚定行首（`^`），body 中靠后的 `Task-ID:` 行（如 squash
  merge trailer）按既有启发式最后一次出现为准（`xtask trace` 不变）
- 拒绝的失败消息（commit-msg 钩子）增加示例：
  `（如 Task-ID: M0-WP01-T01 或 M6-D67-T01）`

## 验收标准（可执行）

- [ ] `bash scripts/check-task-id-format.sh` 退出 0，覆盖：
  - [ ] 接受：`M0-WP01-T07`、`M-1-WP07-T01`、`M6-D67-T01`、`M6-D6-T01`、
    `M6-D123-T01`
  - [ ] 拒绝：无 `Task-ID` 行、空 `Task-ID:`、错误前缀（`X0-WP01-T01`）、
    WP 后非两位数字（`M0-WP1-T01`）、D 后非数字（`M6-DAB-T01`）、
    尾段非两位数字（`M6-D67-T1` 与 `M0-WP01-T123`）
- [ ] `bash scripts/check-task-ids.sh origin/main HEAD` 对当前 main
  上最新 5 个 commit 全绿（回归既有 WP 提交）
- [ ] 干跑（dry-run，git 实际以文件路径调用钩子，非 `/dev/stdin`）：
  ```bash
  printf 'feat: dummy\n\nTask-ID: M6-WP01-T02\n' > /tmp/msg.txt \
    && bash scripts/hooks/commit-msg /tmp/msg.txt  # 期望 exit 0
  printf 'feat: dummy\n\nTask-ID: M6-D67-T01\n' > /tmp/msg.txt \
    && bash scripts/hooks/commit-msg /tmp/msg.txt  # 期望 exit 0（新前缀）
  printf 'feat: dummy\n\nTask-ID: M0-WP01-T123\n' > /tmp/msg.txt \
    && bash scripts/hooks/commit-msg /tmp/msg.txt ; echo $?  # 期望 exit 1（$ 锚拒绝）
  ```
- [ ] 回归：`cargo fmt/clippy/test` 不变（无 Rust 改动，但任务纪律要求
  跑一遍兜底）

## 非目标

- 不引入第三类任务命名（`EXPLORE`/`INCIDENT` 等）——如需另开 ADR
- 不修改 `xtask trace` 的 Task-ID 解析逻辑——其解析在 §非目标 1 中已
  按正则抽出 `M{m}-{WPnn|Dnn}-T{nn}` 三元组，等宽接受
- 不调整 CI `task-ids` job 的触发条件（`if: pull_request`）——本 WP 仅
  改脚本内部正则
- 不回溯已合并的 `M6-D67-T01` commit（`c883656`）——其历史 `--no-verify`
  痕迹留作已知一次性事件，不重写历史

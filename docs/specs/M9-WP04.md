## 1. 动机

扩展装载现状零信任面：ext-host 按目录同名配对装载（`<name>.wasm` +
`<name>.json`），`ExtRegistry::scan` 扫到即装
（crates/partisync-ext-host/src/registry.rs:276）——无签名校验、无来源
认证，用户无法区分官方/第三方扩展，下载源不可验证（威胁模型草案
T-S1 恶意投放 / T-S2 供应链篡改，M7-WP03-enterprise-topics §2.2/§2.3，
缓解优先级 P1「扩展生态开放前必做」）。该空白自 M7-WP01 §4-1 登记，
经 M7-WP03 T03 威胁模型草案、M9-WP00 §4 债表承接（「WP04，不自建
registry」），至本 WP 清偿最小闭环：**选型 ADR 落锤 + component 装载期
强制验签**——扩展生态对外开放前先立信任锚，是「小步」而非分发体系
（registry/更新通道均不在本 WP，见 §5 非目标）。

不做本 WP：G6 债持续挂账；任何第三方扩展分发（哪怕手工下载）都无验伪
手段；M9-WP00 §2 拍板项③（签名选型）悬而不决阻塞 WP06 beta 发布产物
叙事的信任面口径。

## 2. 契约

### 2.1 选型与依赖引入（ADR-0030 落锤）

- **复用 ADR-0027 minisign 线位**；验签 crate `minisign-verify`
  （0.3.x，MIT、零依赖，docs.rs 实证 2026-10-04）入
  `[workspace.dependencies]` + ext-host `[dependencies]`——新顶层依赖
  由 ADR-0030 承载（ADR-0027:31-33 预留路径兑现）；deny 核对随 T02
  门禁实证，异常沿 ADR-0011 先例回 ADR-0030 修订登记；
- 签名产出 = minisign CLI（CI/开发者本机），**不进 workspace 依赖图**
  （ADR-0027 决策 1 口径原样延伸）；
- 锚定公钥 = 既有发布双钥（主钥 `EBC32789A716D70A` + CI 子钥
  `E056CBB62BF3EF34`，docs/release/RELEASE-PUB-KEY.md:28-40）内嵌
  ext-host 常量，**任一通过即有效**（沿 RELEASE-PUB-KEY.md:22-26 验签
  语义）；专钥分域挂 ADR-0030 修订触发条件。

### 2.2 装载期强制验签（新不变量 P21）

- **磁盘三文件**：`<name>.wasm` + `<name>.json`（既有冻结规则）+
  `<name>.minisig`（新：minisign 对 `<name>.wasm` 字节的签名）；
- **装载序**（`ExtTool::load`，registry.rs:148 现序 manifest 校验 →
  preflight → 编译 → 实例化）：manifest 三阶段校验 →
  **验签（新插点）** → preflight → component 编译 → …——缺签/坏签在
  component 字节进入 wasmtime 编译器**之前**拒绝（编译面攻击零暴露；
  [P14] fail-closed 同构，拒绝先于任何 host function 暴露）；
  `ExtRegistry::scan` 逐扩展经同一 load 路径，语义自动一致；
- **错误面**：`LoadError` 新变体 `Unsigned`（`.minisig` 缺失）与
  `BadSignature(String)`（存在但格式非法/验签失败）——均为装载期
  拒绝，Display 携带扩展名定位；
- **验证口径**：内嵌双公钥 `PublicKey::from_base64` 构造，签名
  `Signature::from_file` 读取，逐钥 `pk.verify(wasm_bytes, &sig,
  false)`（第三参 `allow_legacy=false`，0.3.0 API，docs.rs 实证），
  任一钥通过即放行；
- **无豁免**：不提供 unsigned 跳过开关（env/config 均不设）——威胁
  模型缓解方向「装载期强制验签」字面执行；
- **孤儿 `.minisig`**（有签名无 wasm）：沿 scan 孤儿 `.wasm` 判例
  （P2-1）显式拒，坏文件静默消失会让工具面呈半态。

### 2.3 签名产出与文档面

- 分发者签名流程文档 `docs/release/EXT-SIGNING.md`：minisign CLI 签
  `.wasm` 的命令链、trusted comment 约定、轮换/撤销引用
  key-custody.md；`RELEASE-PUB-KEY.md` 增补「扩展签名」节（复用同
  双钥声明 + 装载期强制验签说明）；
- 测试面自足：test-only keypair（fixtures 入仓，显式标注非生产钥）+
  预签名 fixture（对既有 `demo_tool.wasm` 签一次，T02 开发期一次性
  生成）——生产钥材料零接触（key-custody 纪律）。

## 5. 非目标

| 项 | 归属 | 理由 |
|---|---|---|
| registry / 目录服务 / 扩展更新通道 | 不做（登记议题，独立 WP 待拍板） | 「不自建 registry」硬约束（M9-WP00 §1-WP04）；enterprise-topics 建议表 P2 独立议题 |
| keyless / Sigstore / Rekor 在线验证 | 不做 | 本地优先冲突（ADR-0030 四轴对比·验证面） |
| OCI artifact 分发通道 | 修订触发条件 | artifact 不住 OCI（分发 = 本地目录放置），对齐无兑现点 |
| manifest 入签名面（联合摘要） | 开放问题（§7-R3） | 篡改面评估为缩权/拒绝向，真实闭合需求出现再修订 |
| 专钥分域（extension-dedicated 钥） | ADR-0030 修订触发 | 首个第三方分发者出现时 |
| 第三方分发者多钥 / trust store / 吊销分发 | 议题登记不设计 | enterprise-topics §2「只登记不设计」纪律延伸 |
| 桌面 UI 签名状态展示 | 未排期 | ext 错误透传面已有 error-region，无新 UI 面 |
| macOS 公证 / Authenticode 链式签名 | ADR-0027 既有非目标 | 独立外部依赖，口径不变 |

## 7. 风险与开放问题

- **R1 crate 事实漂移**：minisign-verify API/版本以起草期 docs.rs
  实证为准（0.3.0：`verify(&self, bin, &Signature, allow_legacy)`，
  MIT、零依赖）；T02 以本地 cargo doc/deny 复核，不符回本 SPEC 修订
  （禁凭记忆写第三方 API 红线的双向执行）。
- **R2 双钥复用组织面**：CI 子钥泄漏 = 发布 + 扩展双面失守——与现状
  发布面等量（同一把钥本就签发布），不新增单点；专钥分域挂修订触发。
  接受为一期口径。
- **R3 manifest 完整性缺口（开放问题）**：manifest 不入签名面，篡改
  面评估为缩权/拒绝向（[P14] 声明面 ∩ 白名单无提权路径；改名撞内建
  `ToolNameCollision` / 扩展间 `Duplicate` 显式拒，
  registry.rs:263-267）；若出现真实验证需求（如扩展身份与工具名绑定
  的企业诉求），修订为 wasm+manifest 联合摘要签名。
- **R4 测试 fixtures 签名生成**：需 minisign CLI 本地一次性生成
  test-only 钥与 `.minisig`（fixtures 为入仓实物 `.wasm`，预签名
  可行——integration_p13_p14.rs:46 copy 判例）；测试钥无口令、显式
  标注 test-only，key-custody 双人流程仅约束生产钥。
- **R5 示例扩展断签窗口**：生产路径示例扩展需生产钥签名（持有人
  动作）——持有人签名前，示例扩展在强制验签下不可装载；挂 T03
  人工项（沿 ADR-0027 待批准项②「密钥生成仪式留实跑期」判例），
  不阻塞 T02。
- **R6 修订触发条件汇总**（任一触发 → ADR-0030 修订或新 ADR）：
  OCI 分发通道落地 / 首个第三方分发者 / 企业强制 Sigstore·X.509 /
  manifest 联合摘要闭合需求。

## 动机与裁定

WP03 报告后续卡原提议「semaphore 许可队列取代 tick」。实现评估推翻：
semaphore 的 `close()`（终止信号）与 fail-fast 路径的 `enqueue` 存在
`add_permits on closed` panic 竞态；区分工作票/唤醒票复杂度高——收益
（尾延迟 50ms→0）不值。**改走空闲动态退避**：worker 空转时 sleep 从
1ms 指数升至 50ms 上限（取到分片即重置）——有工作时尾延迟 ≤1ms
（50×），空闲时 CPU 开销可忽略，正确性仍不依赖时序（每 wake 重查
pending/abort），与既有协议同构、零新竞态。

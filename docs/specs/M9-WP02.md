## 1. 动机

M9 三价值台阶之一（N2）：CAS + Merkle + MCP 组合的记忆层外部零竞品，
窗口 6–12 个月（MCP 2.0 / WASI 0.3 双定稿前）。2026-10-03 摸底证实：
mem0（托管 MCP，11 工具）与 Letta（MemFS git 记忆）均无 Merkle proof /
hash chain / 内容寻址，最接近者仅 mem0 history 审计端点（中心化信任）
与 Letta git 历史（无哈希承诺）——「可验证记忆」差异化成立
（docs/reviews/M9-WP02-memory-competitor-scan.md §3）。

工程现状：graph store 已是同步权威库（entry/tag 两实体域经 oplog/bisync
多端收敛），但无记忆实体、无 inclusion proof 能力（merkle.rs 为对账分桶
树，P7 语义）；MCP 工具面六工具不含记忆。不补此层，AI agent 对本产品
的写入口停留在「资产整理」（asset_organize），无事实沉淀能力；而一旦
agent 写入不可验证，记忆沦为可静默篡改的普通表——差异化窗口同步流失。

## 2. 契约

### 2.1 一期范围拍板（批准生效）

本地 stdio 侧车先行：工具面随 `partisync-mcp`（CLI）与桌面 McpSidecar
（`mcp_call` 透传，桌面端零代码改动）交付；Hub 远程 MCP 端点 = 非目标
（WP05）。

### 2.2 memory schema（ADR-0029 决策落地）

graph store 新实体域，additive-only 幂等迁移（沿现行 `schema.sql` 机制，
零破坏性变更）：

```
memory(memory_id TEXT PRIMARY KEY,      -- blake3("M\x1f"+content+tags+metadata canonical) hex
       content TEXT NOT NULL,           -- 事实文本（≤64KiB）
       content_hash TEXT NOT NULL,      -- blake3(content) hex（列级校验面）
       tags TEXT NOT NULL,              -- canonical JSON array（≤32 项）
       metadata TEXT NOT NULL,          -- canonical JSON object（≤16KiB，默认 {}）
       created_ns INTEGER NOT NULL,
       origin_device TEXT NOT NULL,
       hlc TEXT NOT NULL,               -- oplog 排序键；行簿记 LWW 裁决依据
       deleted INTEGER NOT NULL DEFAULT 0)  -- 预留位，一期恒 0（§4）
memory_root(id INTEGER PRIMARY KEY CHECK (id=1),
       root TEXT NOT NULL, memory_count INTEGER NOT NULL, updated_ns INTEGER NOT NULL)
```

- 写语义：`memory_write` 同事务写行 + 更新 `memory_root` 快照 + capture
  oplog（`entity="memory", op="upsert"`）。同 (content, tags, metadata)
  二次写幂等（deduplicated，不新增行、根不变）。
- `memory_root` 为派生值：可从 memory 表全量重算；重算 ≠ 快照 = 检出
  篡改/损坏（§2.3 verify 语义）。
- 簿记字段（created_ns/origin_device）进叶哈希（沿 entry_leaf「含全部
  可比字段」判例）；同 id 双端独立写由 HLC LWW 收敛一行（内容字段相同，
  语义无损；P6 覆盖）。

### 2.3 证明树与只读 proof API（`partisync-graph::memory`）

独立二叉 Merkle（RFC 6962 式，blake3；叶前缀 `0x00`、节点前缀 `0x01`
域分离；叶按键 `memory_id` 升序，奇数叶复制末叶补齐）：

```
memory_leaf(&MemoryRow) -> Leaf                       // 叶编码（canonical，入 §2.2 身份哈希同源字段）
memory_root(rows) -> String                           // 全量重算根
inclusion_proof(rows, memory_id) -> Option<AuditPath> // O(log n) 审计路径
verify_inclusion(root, &AuditPath) -> bool            // 自包含验证：不需数据库
verify_store(&Store) -> VerifyReport                  // 全量：重算根 vs 快照根 + 逐行 content_hash 列级校验
```

与对账分桶树（merkle.rs，P7）并存互不复用。只读：proof API 不产生任何
写路径。

### 2.4 MCP 工具面（mcp.rs 三工具；桌面零改动）

- `memory_write(content: string, tags?: string[], metadata?: object)
  → {memory_id, deduplicated: bool, root}`。content 非空 ≤64KiB；tags
  ≤32 项字符串；metadata 为 JSON object ≤16KiB。超限 → 工具级错误
  （不截断、不静默）。
- `memory_search(query?: string, tag?: string, memory_id?: string,
  limit?: number=20, offset?: number=0) → {results:
  [{memory_id, content, tags, metadata, created_ns, origin_device, score}],
  total}`。一期引擎：SQLite 全文/前缀匹配（FTS5 可用则 FTS，否则 LIKE
  兜底，T02 落锤并记录），tag 精确过滤，`memory_id` 精确查；score 为
  匹配秩（非语义分）；结果按 score 降序、次键 created_ns 降序。
- `memory_verify(memory_id?: string) →` 无 id：`{root, memory_count,
  recomputed_root, ok}`（快照根 vs 重算根 + 全量列级校验）；有 id：
  `{memory_id, leaf_hash, audit_path: [hex], root, ok}`。只读。
- 三工具入 `all_tools()`/`call_tool`/instructions（mcp.rs 四改动点判例）；
  `tools/list` schema 为对外唯一权威契约。语义向量检索不在本期（§4）。

### 2.5 同步语义

oplog `entity="memory"` 新增 upsert 应用臂（session.rs match 判例）：
远端应用走既有 GraphApplier 同层 capture 机制；行冲突按 HLC LWW（一行
胜，双端终态一致）；无 remove 臂（一期无删除）。bisync tick 沿 WP01
装配层，记忆行随既有推送管线多端收敛，零新增同步代码路径为设计目标。

### 2.6 CAS exists() 精化（M8 微债随公开面顺带清偿）

`FsBackend::exists`（tier.rs:156）IO 错误不再伪装 `Ok(false)`：NotFound
→ `Ok(false)`，其他 stat 错误 → `Err(TierError::Io)`；调用方
`tier.rs:549` 的 `.unwrap_or(false)` 一并移除（错误显式上浮）。

### 2.7 新不变量（P20，随 T02 走 partisync-property-registry，登记先于测试代码）

- **P20 记忆层可验证承诺**：(a) 确定性——root 是 memory 可见集的确定性
  函数（同集同根，与插入顺序无关）；(b) 可靠性——`verify_inclusion`
  对属于承诺集的叶成立，篡改 leaf/audit_path/root 任一字节必败，审计
  路径长 ≤ ⌈log2 n⌉+1；(c) 可重算——快照根可由持久层全量重算重建，
  篡改/损坏后 verify 报不一致而非静默通过。

## 3. 验收标准（可执行）

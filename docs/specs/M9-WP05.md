## 1. 动机

G8「MCP 仅本地 stdio」自 M8 前瞻登记、经 M9-roadmap §6 承接为 WP05
（M9-WP00:73「评估 + 骨架」）。MCP 2.0 已于 2026-07-28 定稿——本仓库
rmcp 恰已精确锁定该版 spec（Cargo.toml:64 `rmcp = "=3.4.0"`，ADR-0019），
工具语义面达标，但传输与授权两面整体缺席：gateway 唯一运行入口是 stdio
（crates/partisync-gateway/src/mcp.rs:1579 `serve_server(state,
stdio())`），无 HTTP 面、无 OAuth 2.1 resource server 面。窗口敏感
（roadmap §1「双定稿窗口 6–12 个月」）：不在窗口内完成对齐评估，窗口
关闭后评估成本与竞品差距同步升高。

不做本 WP：G8 持续挂账；2026-07-28 的远程化形态（stateless Streamable
HTTP + OAuth 2.1 PRM）是否与既有 handler 直调模型同构——这一决定未来
所有远程化投入规模的判断——悬而未决；后续任何「把记忆/资产工具面暴露
给远程客户端」的产品动议都没有威胁模型与骨架地基可依托。

## 2. 契约

### 2.1 评估文档（docs/reviews/M9-WP05-mcp2-remote-eval.md）

内容三要素（缺一即不合格）：**差距面**（G-1..G-6 传输 + A-1..A-5 授权
逐条对 2026-07-28 规范性要求）、**威胁模型要点**（T-R1..T-R7，沿
M7-WP03-enterprise-topics §2.3 表格式，只登记不设计）、**结论**（§5：
一期骨架不承诺生产可用——本 SPEC 明示）。全部规范性引文以起草期在线
实证为准（2026-10-04 modelcontextprotocol.io 2026-07-28 版 + docs.rs
rmcp 3.4.0），禁凭记忆引用 spec 条款。

### 2.2 Hub 远程 MCP 端点骨架（partisync-hub::mcp_remote，新模块）

**mock/骨架边界（硬性，沿 M5-WP04 v0.1 外部依赖策略判例：stub 落既有
依赖，正式接线另立）**：不接真实 OAuth（无 AS、无 token 验证——Bearer
存在即放行）、无 TLS 终结、无工具执行、不承载真实数据、无 SSE 流。
模块 doc 注释与响应 serverInfo 均明示骨架身份，防误当生产面。

- **端点面**（axum Router，hub 既有依赖，零新增顶层 crate）：
  - `GET /.well-known/oauth-protected-resource` → PRM 文档
    （RFC 9728 形状）：`resource`（配置入参，缺省 mock 值）+
    `authorization_servers`（配置入参，缺省含一个 mock AS——评估文档
    A-1「MUST 至少一个」的形状兑现）+ `scopes_supported` +
    `bearer_methods_supported: ["header"]`；
  - `POST /mcp` → 握手骨架：
    - 无/非 Bearer `Authorization` → **401** +
      `WWW-Authenticate: Bearer resource_metadata="<PRM 路径>"`
      （评估文档 A-2 挑战形状）；
    - 有 Bearer（mock：不校验）→ 按 body `method` 分派：
      `initialize` → 单 JSON JSON-RPC 响应（`protocolVersion:
      "2026-07-28"` + capabilities + serverInfo，name 标注 skeleton）；
      notification（无 id）→ **202 Accepted** 无体；其余方法 →
      **404** + JSON-RPC error `-32601`（评估文档 G-6，与遗留裸 404
      区分）。
- **纯函数核心**：PRM 构造与 POST 分派为不依赖 axum 提取器的纯函数
  （handler 薄包装）——单测零新增 dev-dependency（不加 tower）。
- **接线**：hub-demo（既有演示面，hub-demo.rs:42 Router）merge 该
  router；默认 bind 仍 127.0.0.1:8090（hub-demo.rs:29，评估文档 G-4
  本地绑定口径）。

### 2.3 明示的不承诺

一期骨架**不承诺生产可用**：不可达公网、不可承载真实数据、不可替代
gateway stdio 面、不验证任何 token。§4 验收只判定上述 mock 形状本身。

## 5. 非目标

| 项 | 归属 | 理由 |
|---|---|---|
| 真实 OAuth 2.1（AS 选型/接入、token 受众校验、scope 模型） | 正式远程化立项（条件触发：真实多端远程需求验证后；评估文档 §6-O2/O3） | T-R1/T-R6：授权先行是数据上线前置，一期骨架不承载真实数据 |
| rmcp `transport-streamable-http-server`/`auth` feature 启用 | 同上（须 ADR + cargo deny + 覆盖度复核，评估文档 §4/O1） | 传递依赖面未实证，铁律 8 流程随正式任务走 |
| TLS 终结 / 公网部署 / 反向代理面 | 同上 | 部署边界变更独立决策 |
| 工具执行透传（远程调 asset_*/memory_*） | 同上 | 数据出本机边界 = 产品动议，先授权后工具 |
| SSE 流 / `subscriptions/listen` / MRTR | 同上 | 握手面无流式需求（评估文档 G-5） |
| Origin 校验 / quota 接线 | 同上（评估文档 T-R3/T-R7 缓解方向） | 骨架仅 127.0.0.1 demo 面 |
| gateway stdio 面任何改动 | 不做 | 本 WP Hub 侧新增，不动 gateway |
| 桌面 UI / CLI 面 | 不做 | 无承接面（远程面未承诺可用） |

## 7. 风险与开放问题

- **R1 spec/库事实漂移**：评估文档规范性引文以 2026-10-04 在线实证为
  准；2026-07-28 之后新 revision（含 issuer SHOULD→MUST 升级预告，
  评估文档 §6-O4）触发重评，不追溯改已合入结论（修订登记）。
- **R2 骨架被误当生产面**：三层缓解——SPEC §2.3 明示 + serverInfo
  skeleton 标注 + 模块 doc mock 边界声明；验收探针把「token 不验证」
  钉死为明示行为（§4），后续接真实 OAuth 时该探针必红 = 强制修订
  入口。
- **R3 mock Bearer 全放行的暴露面**：仅当操作者显式把 hub-demo 挂上
  非回环地址才成风险；demo 面默认 127.0.0.1（hub-demo.rs:29）且非
  发行产物；SPEC §5 明示公网部署为非目标。接受。
- **R4 hub 依赖面**：骨架只用 axum/tokio/serde/serde_json（hub
  Cargo.toml 既有），零新增——PR2 以 `git diff Cargo.toml` 为空实证。
- **R5 一 Task-ID 三堆叠 PR 的追溯链**：xtask trace 按 Task-ID 聚合提交，
  PR1/PR2/PR3 均挂 M9-WP05-T01 沿 M9-WP04-T02 判例（#143–#145）；PR
  正文互相引用堆叠顺序；实装/探针拆分由铁律 3 触发（0.2 修订）。
- **R6 正式远程化的范围蔓延压力**：评估文档 §5-4 已把正式立项的 ADR
  必答题（AS 选型/feature/TLS/scope）列清——本 SPEC 批准不构成任何
  正式远程化的批准；新需求出现走新 SPEC（铁律 1）。
